# 子代理验收清单

> 子代理自报「已完成」不等于完成。**没有回读验证的产出，一律按未完成处理。**
> 用法：每收一次子代理产出，复制本清单逐条勾选；任一条打不上勾就退回或降级重做。

## 零、验收前提

- [ ] 已拿到子代理的回传，含**产出路径清单**与**关键证据片段**（不是"已完成"三个字）
- [ ] 已对照派活工单第六节的验收标准，逐条准备验证动作
- [ ] 已确认哪些产出是子代理做的、哪些是主代理自己做的（汇总时必须标注）
- [ ] 主代理未被本任务占住：用户在验收期间仍能随时发起对话

---

## 一、产出存在性与内容

- [ ] 声称产出的每个路径**都真实存在**，用 `terminal` / `read_file` 亲自打开过，不是只有文件名
- [ ] 文件非空、编码正确、能正常解析（JSON 能 `json.load`、表格能读出应有行数）
- [ ] 数量对账：声称 N 条/N 页/N 个文件，实际数出来就是 N（逐条列出，不用"大概"）
- [ ] 内容与工单口径一致（单位、取整、命名规则、字段名），无自行改口径
- [ ] 无占位符残留：`TODO`、`示例`、`lorem`、空章节、`待补充` 均已清除或如实标注

## 二、外部副作用必须回读（最硬一条）

> 凡是产生了外部状态变更的动作（写文件、发消息、调 API、改数据库、推代码），
> **必须索取可验证 handle（路径 / ID / URL / commit hash / message id），由主代理回读确认**。

- [ ] 每个副作用都有 handle，且 handle 是可定位的（不是"已发送"这类描述）
- [ ] 主代理已**独立回读**该 handle 处的真实状态（重读文件、查列表、查回执、`git log`），确认与声明一致
- [ ] 回读结果与子代理声明一致；不一致的项已标记为未完成并排查
- [ ] 不可逆动作（删除、覆盖、对外发送、支付）**未经主代理确认不得执行**；已执行的逐个复核影响范围
- [ ] 涉及密钥、账号、隐私的信息未出现在产出、日志或回传中

## 三、过程必须实测（不能只有描述）

- [ ] 脚本/命令**真实运行过**，回传里贴的是真实终端输出（含 exit code 或报错原文），非"应可运行"
- [ ] 关键结论有可复现路径：给出所用命令与输入，主代理能照着重跑一遍并得到相同结果
- [ ] 涉及检索/取数的任务，**推不出结论的地方如实标注"未取到"**，未用推测或语言生成填充
- [ ] 未编造事实：文献、作者、年份、数据、链接抽查过至少 2 处，均可打开且内容相符
- [ ] 反例或边界情况被覆盖过（空输入、缺字段、单条数据），或明确说明未覆盖

## 四、失败与降级路径

- [ ] 未完成项已**明确列出**（数量、原因、卡在哪一步），未混在成功项里含糊带过
- [ ] 已尝试的替代路径被记录（换工具、换数据源、换解析方式），并说明为何仍失败
- [ ] 降级方案已给出：主代理自己做 / 换路径重派 / 缩小范围 / 转后台长期任务，四选一并说明理由
- [ ] 降级后**不得编造结果**：缺失部分在交付物中显式标注为缺失，不留空白假装完整
- [ ] 若失败涉及外部服务（限流、403、超时），已记录现象与重试次数，供下次改道

## 五、汇总与标注

- [ ] 交付汇总中**已标明哪部分由子代理完成**、哪部分主代理自己做（逐段/逐文件标注）
- [ ] 涉及多个子代理时，已检查并行组的产出**互不冲突**（无两个子代理写同一文件/同一记录）
- [ ] 串行依赖的产出已确认前置完成后再启动后续
- [ ] 主代理对最终交付物**负全责**：已通读一遍，不是把子代理产出原样转手给用户
- [ ] 残留风险与已知局限已用一句话说清（哪些没验证、哪些可能有偏）

---

## 快速判定表

| 情况 | 处置 |
| --- | --- |
| 路径不存在 / 文件为空 | 退回重做，附具体缺失项 |
| 副作用无 handle 或回读不一致 | 按未完成处理，先核实真实影响再决定下一步 |
| 只有描述、无可复现命令与输出 | 退回，明确要求补真实输出 |
| 核心目标达成、边缘项缺失 | 已有部分可交付，缺失项显式标注后由主代理补或降级 |
| 触发限流/权限等外部阻塞 | 记录现象，改道或降级自己做，不硬等 |
| 任务本身跨会话需长期存活 | 从子代理方案改为 cron / 后台进程 |
