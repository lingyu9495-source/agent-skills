# 扫描件 / 图片型 PDF 转文本

## When to Use
- 收到 PDF，但 `read_file` 报 `NeedsOcrError` 或提不出文字
- 政府文件、合同、申报书、发票等**扫描件**要转成可检索、可分析的文本
- 要派子代理去读一批扫页图片

## 第一步：判定是不是图片型（先验再干）
```python
import pymupdf
d = pymupdf.open(path)
print(d.page_count, sum(len(p.get_text().strip()) for p in d))
```
- 全文字符数为 **0** → **图片型扫描件**，必须走 OCR 或视觉
- 有文字但少/乱 → 混合型，逐页试提，只对空页补 OCR
- 别把图片型 PDF 当一个普通 PDF 读——绕不过去，早点转型

## 第二步：渲页（两种下游共用）
```python
for i, pg in enumerate(d):
    pg.get_pixmap(dpi=130).save(f"{OUT}/p{i+1:02d}.png")   # 130dpi 够 OCR；小字用 200+
```
页面大、字密的（表格/小字）先分区放大再识别，别硬拿整页降质图去识。

## 第三步：选通道（关键决策）

| 通道 | 适用 | 注意 |
|---|---|---|
| **多模态模型视觉**（自己能看图时） | 页数少、要理解版式/图表 | 逐页高质图，**逐字转录**指令 + 「看不清写『字迹不清』，不许编造」 |
| **本地 OCR**（tesseract / RapidOCR） | 页数多、只要文字 | 中文用 `chi_sim`；**报数字/编号/金额必须放大复核** |

**两条通道都要的事**：
- **强制不编造**：指令里写清楚「只输出页面上真实存在的内容，看不清就标『字迹不清』」
- **关键数字二次复核**：日期/金额/编号/得分/比率 → 放大重识一遍
- **同形误识校正**：中文 OCR 常错（孪→李、南宁→南京、3↔8）→ 按上下文校正并标注
- **印章/水印/眉批单列**，别混进正文

## 第四步：校验（交付前必过）
- **抽查回读**：随机验证几页的关键信息，与原文图对得上
- **完整性**：页数对得上（16 页就要 16 页），空白页也要确认（"本页无正文、无印章"也是结论）
- **口径冲突照实报**：同一名字在不同页写法不一致、编号跳号 → 原样列出待确认，**不自行"修正"**

## 派子代理读扫件：先做能力预检
子代理沿用父级模型，**模型能力就是子代理能力**。
- 非多模态模型收到图只会拿到 `[Unsupported Image]`——若你要派子代理读图，**在 context 里直接给好本地 OCR 命令与渲染步骤**，并明说"视觉不可用就改走本地 OCR"，别让它自己摸
- 分页并行：按页码切给多个子代理（如 p1-6 / p7-11 / p12-16），各自读各自范围，主脑汇总——**比单线读全文快且不炸上下文**
- 子代理汇报里必含：每页转录 + 不确定点单列 + 未覆盖页码说明

## 落盘
- 渲染图、OCR 中间产物全部放 `cache/scratch/<主题>/`，**不动源文件**；转录稿另存 `.md`，与原件并存
