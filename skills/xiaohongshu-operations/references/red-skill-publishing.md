# Red Skill 上传与发布规则

> 适用：往小红书 SkillHub 上传技能包、把 Skill 挂到笔记或评论区。
> 以平台页面与《Red Skill服务协议》原文为准，平台改版后重新打开核对再用。

## 上传流程
1. **前置门槛：实名认证**——未认证时点「上传Skill」只弹认证窗（小红书 App 扫码），认证成功后才能进表单
2. **两步**：① 上传源码 → ② 填写信息
3. **上传方式**：上传文件（拖拽/点击）或通过对话上传
4. **格式要求**：含 `SKILL.md` 的**文件夹或 zip**；支持 `.md/.txt/.html/.css/.js/.py/.json/.xml` 等；**单文件 ≤10MB、总包 ≤30MB**
5. **内容来源**单选：「原创」/「转载」——自制技能选原创；含开源或搬运组件的**必须选转载**并按 4.6 条保留版权声明
6. 必须勾选同意《Skill发布安全规范》才能点「下一步」

## 第 2 步「填写信息」字段规范（实测）
| 字段 | 限制 | 填法 |
|---|---|---|
| Skill 名称 | **≤15 字** | 显示在笔记正文下方。从 `displayName` 自动带入的**通常超限**，压成短中文名（如「可研报告撰写引擎」），别用英文 slug |
| Skill ID | ≤128，英文/数字/连字符 | 直接用 slug |
| 简介 | ≤1000 | 从 frontmatter `description` 带入，**先删掉 `**` 等 markdown 记号**再看字数（详情页不渲染它们，只会露出来难看） |
| Skill 介绍 | **≤10000** | 通常直接灌 SKILL.md 全文，**必超 3~4 千字**，见下面的删减顺序 |
| 场景标签 | 多选 | `button.skill-form__tag`；选中态类名带 `--active` |
| 版本号 | 形如 `1.8.0` | 与 SKILL.md frontmatter 的 `version` 保持一致（frontmatter 与 README 打架会被看出来） |

**介绍超限的删减顺序**（按性价比从高到低）：
1. 删与平台无关的章——兄弟技能对照、包内文件说明（README 里已有一份）
2. 删含敏感词的章——报价话术、接单话术（**一举两得**：省字数 + 去审核风险）
3. 最长的工作流章按 `### ` 子标题精简：保留每步的"做什么 + 完成判据"，砍掉工具输出示例与长命令块，末尾留一句「完整流程见包内 SKILL.md」
4. **「关于作者」钩子段永远最后动、默认保留**——它是变现入口，删之前先问老板

**「发布Skill」按钮的解锁条件**（缺一即 `disabled:true`）：文件已上传 + 内容来源单选 + 协议已勾 + 全部必填字段非空 + **至少一个场景标签**。按钮灰了就按这个清单逐项回读，最常见的是改字段后标签被重渲染清空。

**提交后回读**：页面出现技能卡「**审核中 · V.N.N.N**」+「发布成功」才算数。
**审核通过后的挂载路径**（平台公告原文）：发布页 → 添加组件 → **Red Skill**。

## 详情页钩子的取舍（老板拍板口径）
钩子段（微信/公众号/二维码/商店货架页）写在 Skill 详情页里，**是否算站外引流由平台认定**，协议 5.4(1) 禁「为规避平台风控而设置站外引流路径」。当前执行口径：

- **必删**：微信号、公众号名、微信二维码图片链接——小红书对微信零容忍（私信发微信禁言 7 天起步），写在详情页等于自报引流
- **可留**：技能商店货架页链接（SkillPay 等）——性质是技能分发而非私域，且正是免费版→付费的主链路。**此口径的过审结果待验证**，被拒就降级为全删重提
- 删完**用正则统计敏感词计数归零**（微信/公众号/二维码/账号名/接单/代写），别凭肉眼扫


## 协议硬约束（每条对应一种被拒/被罚的可能）
| 条 | 要求 | 操作含义 |
|---|---|---|
| 4.3 | 不侵权；对接口/模型/workflow 拥有合法授权；符合数据安全与 AI 法规 | 依赖第三方 API 的包要自己确认授权链 |
| 4.4 | 详情页必须清晰披露**主要功能、适用范围、限制、使用风险** | 这四项写全是过审加分，缺了出事自担 |
| 4.7 | 必须能按描述正常运行，功能缺陷致损自担 | **没测过的包不传** |
| 5.1 | 平台会做**安全扫描**，高风险可暂缓/拒发 | 首发选零外部依赖的包（不调 API、不要密钥），过扫描概率最高 |
| 5.4 | 禁止规避风控、**恶意刷量/批量模拟调用**、违法违规 | 不刷安装量 |
| 7.1 | 违规：下架 Skill **及挂载笔记** → 限传 → **冻结/注销账号** → 报监管部门 | 一次冒险可能把整个号搭进去 |
| 3.4 | 每账号可发数量上限由平台定 | 一次别贪多，先发一个打样 |

## 分发形态（平台提供的能力）
- **安装口令**：平台生成的文本指令（含 Skill 获取地址 + 安装说明），用户复制到本地 AI 助手安装
- **挂载入口**：审核通过后 ① 发布笔记时添加 ② 评论区用 `+` 号发给提问者
- 平台提供**安装次数**等基础统计（仅供参考）

## 变现实话（协议层结论）
《Red Skill服务协议》通篇只讲**安装口令、安装次数统计、挂载展示**，**没有定价、支付、分成、收益的任何条款**。
→ 当前它是**免费分发与引流通道，不是收款通道**：Skill 负责攒安装量与建立专业人设，钱靠笔记把人引到自有服务（诊断/定制/可研）再收。
→ 不拿安装量当营收指标，把它当**获客漏斗的顶层**。

## 从笔记带到技能市场的三条路径（风险排序）
判断依据：小红书《交易导流违规管理细则》——“引导至**私域或站外三方平台**”，“暗示间接”也算。

| 路径 | 做法 | 风险 | 结论 |
|---|---|---|---|
| **Red Skill 官方挂载** | 笔记挂 Skill → 用户装到本地 → **Skill 文件内部**写商店指引 | 引导发生在用户本地文件，不在小红书的笔记/评论/资料里，平台审不到、也不归它管 | ✅ **主力**，唯一同时满足“能带人走”和“不违规”的通道 |
| 品牌词搜索 | 笔记只提技能名，让用户自己去搜，不放链接不提平台名 | 写露骨（平台名/去哪搜）仍算“暗示引导” | 🟡 只当辅助 |
| 评论区/私信引导 | 回复里给链接或联系方式 | 私信是重点监控，含微信/二维码/外链关键词直接触发风控 | 🔴 禁 |

**实操含义**：合规结构天然分三层——笔记只讲免费 → Red Skill 详情页只写功能/适用/限制/风险（4.4 本来就要求）→ 付费指引只在 Skill 文件里。三层各归各的审查方，互不穿透。

## 打包与选品
1. **选品顺序**：零外部依赖的原创方法论包 → 需联网/需密钥的包（后置，先确认不触扫描红线）
2. **必补披露段**（4.4 要求）：在 SKILL.md 里显式写「功能 / 适用范围 / 限制 / 使用风险」四段
3. **去掉一切密钥与个人路径**：配置里的 token、内网地址、绝对路径一律换成占位说明；渠道归因钩子写成来源标记（如“加时备注小红书”），别照搬别的渠道名
4. **先证明能用，再压包**（老板的硬门槛，顺序不可倒）
   - 用法先读脚本 docstring 与 README——**位置参数脚本不认 `--help`**，直接跑 `--help` 会被当文件名，产物落进当前目录
   - 测试一律在**技能目录外**的临时目录里跑（脚本默认输出到 cwd，跑错就污染技能包）
   - 逐个脚本跑 `--help`，验**退出码 0**；再回数技能目录文件数、`find <目录> -newermt '-5 minutes'` 查测试污染
   - 脚本没有 argparse 的，先补一行门卫再发：`if len(sys.argv) > 1 and sys.argv[1] in ("-h","--help"):` 打印 docstring 后 `raise SystemExit(0)`；缺参数保护的同理补 `if len(sys.argv) < N: sys.exit(__doc__)`——否则新用户一上来就 `IndexError`
   - 端到端链路要含**每条交付路径**（生成 → 处理 → 自检 → 导出），不只验主脚本
5. **跟付费版分层再打包**（团队成员口径）：免费/付费必须一眼分得开——免费给本机直连与纯标准库部分，付费给联网取数与交付级成品；市场版另起 `-lite` 后缀 slug 并降版本号，同名同号两套包会互相打架
6. **压包**：用 Python `zipfile`（`arcname = os.path.relpath(path, 父目录)`，保留技能文件夹前缀；跳过 `__pycache__`/`.pyc`）。压完三件验收：`testzip()` 通过、`SKILL.md` 在包内、体积与文件数符合预期
7. 提交前把包与文案一起交老板过目——提交即对外发布
