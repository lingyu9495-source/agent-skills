# 小红书账号运营（浏览器接管）

## When to Use
- 接管/运营小红书账号：读账号数据、发笔记、上传 Red Skill、看创作者后台
- 任何指向 `creator.xiaohongshu.com` 的操作

## 边界（每次动手前先过一遍）
1. **登录、短信验证码、实名认证只由老板本人完成**——我只负责把二维码调出来截图发过去（`browser_vision` → 回复里带 `MEDIA:<截图路径>`），绝不输入密码、验证码、身份信息
2. **凡“提交/发布”都是对外发布**：备好内容与文件 → 老板过目 → 再点提交；账号是老板的资产，违规连坐到他
3. 内容定位未经老板拍板不擅自改

## 节奏（老板明确要求过效率）
- 互不依赖的步骤**并行发**（浏览器操作与本地打包同时开），别一步一汇报——他要的是"提高效率的同时保证准确度和质量"，串行汇报两者都得不到
- **只在不可逆动作前停一次**（提交 / 发布 / 任何对外可见的改动），其余直接干到交付，不问"开始吗/可以吗"
- 汇报合并成一次：进度 + 产物 + 待拍板项一起给

## 操作流程
1. **开工先看当前 URL**：浏览器与老板共用，他可能正在上面操作；不在目标页再 navigate（登录态靠 cookie，切回去还在）
2. **登录页** `creator.xiaohongshu.com/login`：默认短信登录，点登录卡右上角图标切扫码登录
3. **摸底先行**：读首页的粉丝/笔记/近 7 日曝光与互动，先搞清楚这是个什么号再动手
4. **入口 URL（实测有效）**：
   - 主工作台：`/publish/publish`（登录态直达，侧边栏与发布页都在这）
   - `/home` 返回“页面不见了”，**别用**
   - Red Skill：`/new/skill-hub`
5. **点击**
   - 优先 `browser_click(ref)`
   - 弹窗开关、路由跳转后 ref 立即失效（报 `Unknown ref`）→ 重新 `browser_snapshot` 再点，不重试旧 ref
   - 侧边栏等文本项常常**没有 ref** → 在 `browser_console` 里按 `textContent` 正则匹配后 `el.click()`；多个菜单项会挤在同一个节点里，**用宽松正则不用全等**
6. **要老板操作的环节**（扫码/实名认证）——**优先从 DOM 提二维码，别靠截图**：登录/认证弹窗里的二维码是 `<img src="data:image/png;base64,...">`（按 `naturalWidth===128` 之类筛掉 logo），`browser_console` 取完整 dataURL → base64 解码存 PNG → 回复带 `MEDIA:<路径>`。**为什么不用 `browser_vision` 截图**：截图极易落在弹窗未渲染或已关闭的一瞬，反复「截不到」纯耗轮次，而 DOM 里的二维码一直在。发给老板后等他完成 → **重新 snapshot 验证状态字样**（如「认证成功」）再继续，不凭他的口述当成功；二维码有时效，过期就重新取一张，这比换登录方式快
7. **CDP 直控**——ref 点不出来、React 事件不认账、要传文件时，走 `browser_cdp`：
   - 调 `DOM.*` / `Page.*` **必须带 `target_id` 或 `frame_id`**，不带会报 `'DOM.getDocument' wasn't found`。**那不是"域被禁用"，是没路由到页面**——本条别当"工具不支持"记
   - **无状态调用之间 `nodeId` 不持久**：上一跳拿到的 nodeId 下一跳用会报 `Could not find node with given id`。要串多步（`DOM.getDocument` → `DOM.querySelector` → `DOM.setFileInputFiles`），**每步都带同一个 `frame_id` 走 live session** 才有效；`frame_id` 从 `browser_snapshot` 的 `frame_tree` 里取（top 那条）
   - **上传文件只有这一条路**：文件选择器在无头环境弹不出来，`DOM.setFileInputFiles({files:[绝对路径], nodeId})` 直接喂给 `input[type=file]`；有多个 file 输入时先用 `accept`（如 `.zip`）区分，别喂错框
   - 传完**回读页面确认**（如「已选择 18 个文件，总大小 166.1 KB」），不凭接口返回 `result:{}` 当成功

## 图文笔记发布（实测全流程，按此顺序）
发布页 `/publish/publish` 顶部 4 个 tab（上传视频 / 上传图文 / 写长文 / 发播客）**默认停在「上传视频」**：
1. **先切「上传图文」**，判定标准是回读 `input[type=file]`：`accept` 变 `.jpg,.jpeg,.png,.webp` **且 `multiple:true`**——不是看 tab 高亮（高亮类 `creator-tab active` 只是辅助）
2. **CDP 传图**（文件选择器无头环境弹不出，只有这条路）：`DOM.getDocument` → `DOM.querySelector('input[type=file]')` → `DOM.setFileInputFiles({files:[绝对路径...], nodeId})`，**三步带同一 `frame_id` 走 live session**；传完回读「图片编辑 5/18」这类字样，`result:{}` 不算成功
3. **标题**：`input[placeholder='填写标题会有更多赞哦']`，用 React 受控写法（见下节）
4. **正文是 TipTap/ProseMirror**（`div.tiptap.ProseMirror[contenteditable]`）：`ed.focus()` → 用 `createRange` 把光标移到末尾 → `document.execCommand('insertText', false, text)`。换行会转成段落（`innerText` 显示 `\n\n`），属正常
5. **话题**：正文末尾直接追加 `#词1 #词2`（词内无空格）；**优先用页面推荐的活动话题**（编辑器下方 `.bottom` 区列的 `#howto用好AI` 之类，带活动流量扶持）；插话题前**光标必须已在编辑器内**，否则点推荐词不进正文
6. **字数**：介绍/正文各有上限（正文 `1000`，Red Skill 介绍 `10000`），改完回读字数角标
7. **发布前全表单回读**：标题 / 正文长度 / 图片数 / 话题数 / 各开关状态 / 按钮 `disabled` ——一次读全再点

### 两个开关的完整操作（都放最后一步）
- **定时发布**：`browser_snapshot` 里「定时发布」文字后面的 clickable/checkbox ref 点开 → 时间字段是 `.post-time-wrapper` 内的 `input.d-text`（格式 `YYYY-MM-DD HH:mm`），用 React 受控写法设值 → **回读页面渲染出的时间文本**（受控组件只改 `input.value` 会回滚）；成功标志 = 底部按钮文案从「发布」变成「定时发布」
- **原创声明**：点开关必弹《原创声明须知》——先勾弹窗里「我已阅读并同意」的 checkbox，「声明原创」按钮才从 `disabled` 变可点；声明成功后预览区出现「已声明原创」
- 这两个开关都可能触发 `?from=tab_switch`（见下方坑），所以**字段与图片全部就绪、本地留好副本之后才动它们**

### 坑（都真实踩过，代价是整轮重填或多一轮往返）
- **`?from=tab_switch` 会卸载发布按钮**：点「原创声明」或「定时发布」开关后 URL 变 `?from=tab_switch`，底部「暂存离开 / 发布」按钮从 DOM 消失，Esc / 滚动 / resize / 弹层移除都救不回来，**只能刷新重填**。规避：先做完所有不触发 tab_switch 的配置，**把这两个开关放在最后一步**，且点之前确保文案与图片本地都有副本（重填成本低：图片在本地、文案在手）
- **tab 的 ref 顺序不稳定**：`e4~e8` 是 4 个 tab，但每次 navigate 后哪个 ref 对应「上传图文」会变——**点完必须回读 `accept`，不猜顺序**；连点几个 ref 都不切 tab 时，先 `browser_snapshot` 拿新 ref，不要重试旧 ref
- **点击是否真的到达页面，用监听器验**：`document.addEventListener('click', e=>log.push(e.isTrusted), true)`，点完读 `log.length`；**count=0 就是事件没到页面**（`browser_click` 返回的 success 不等于页面收到）。此时 navigate 换页重建会话再试，别把同一个点击连点三次；**重建后 count 仍是 0（连 Tab 键都不动焦点）= 输入通道冻死，立刻止损降级**：把文案与图直接发聊天框、由老板手机 App 发，并如实分列「已自动完成的环节」与「卡住的一步」——别把轮次烧在第 8 种恢复法上
- **网页端草稿不是交付**：填写过程会自动往网页端草稿箱存（`草稿箱(N)` 会涨），但老板在手机 App 侧找不到这些稿子。他说「存好我自己发」时，**交付 = 聊天框里的文案 + 图**，网页草稿只当我方保险副本，别让他去草稿箱找——会白跑一趟
- **改一个字段会重置其他字段**（重新渲染清掉已选标签/已勾选项）：每改完一处重查全表单，这是最常见的"按钮又灰了"

## 运营：什么时候发、怎么蹭流量
- **发布时段**：凌晨是流量最低谷；新号首篇靠**首小时 CES**（评论×4、转发×4、关注×8，权重远高于点赞）决定系统给不给推流——凌晨发=首小时没人=系统判定内容差=不推流。**最佳 7:30–9:00 或 20:00–22:00**，不在时段内宁可开「定时发布」也别硬发
- **正文结尾用提问式**（「你卡在哪一步？评论区说」），直接抬 CES 里权重最高的评论项
- **配图文案要一次交齐**（见 deliverable-first-delivery）：文案、图片、标签、话题是同一套交付物，别分次发让老板来要

## 表单与状态验证（发布类操作通用）
- **设值用 React 受控写法**：`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set.call(el, v)`，然后**必须**补 `dispatchEvent(new Event('input',{bubbles:true}))` + `change`；直接 `el.value = v` 不触发任何校验，字数角标和按钮状态都不会动
- **点击生效与否，读状态类不读假设**：`--active` / `--checked` / `disabled: false` 才是事实。JS 派发事件对部分 React 组件就是不认（tab 切换可能死活不动），先换 `browser_click(ref)`，仍不行再用事件序列 `mousedown→mouseup→click`；**每次点完都回读状态类**，没变就换法子，别重复同一种点击
- **改一个字段会重置别的字段**：重新渲染会清空已选标签、已勾选项——**每改完一处就重查全表单**，别拿改之前的快照当现状（这是最常见的"按钮又灰了"原因）
- **成功的判定是回读页面**：找「发布成功」「审核中」这类落地状态字样，不是看点击有没有报错

## 发布前两道闸（老板钦定，缺一不发）
1. **证明能用**：按包内说明端到端跑一遍，看到真实产出文件才算数——没跑过的包不传（协议 4.7 也是这条）。测试在**技能目录外**的工作区做，跑完回数技能目录文件数（测试本身可能往里写垃圾）
2. **跟付费版有区隔**：免费包与付费包必须一眼分得开。口径是团队成员的**“不是阉割，是形态所限，天然分层”**——免费给本机直连/纯标准库的部分，付费给联网取数与交付级成品；市场版另起带 `-lite` 后缀的 slug 并降版本号，与完整版同名同号会互相打架。免费包若与付费包完全相同，付费版就没人买
3. **压完回读验收**：文件数、无垃圾文件、zip 完整性、SKILL.md 在包内——验收不过不算“已打包”

## 内容形式与人设（老板拍板的口径）
- **图文 70% + 录屏视频 30%**：工具/教程类内容靠搜索长尾（小红书日均搜索超 8 亿次），图文先做、也最吃得住产能；视频只做**不出镜的录屏 + 配音、约 2 分钟**（吃平台中长视频扶持），不拍 vlog——拍摄成本会把日更拖垮
- **每篇必须有老板本人的真实判断**（他 多年投资经验的原话、案例、反直觉结论）：平台在打击 AI 批量输出内容，官方口径是“AI 仅为工具，核心价值是创作者的真实表达”——真实观点是护身符，也是别人抄不走的差异化。分工：我出框架与初稿 → 他补 1~2 句 → 我定稿
- **效率/数字对比必须口径统一**：写"过去 X 天 vs 现在 Y"时两边必须同口径（都算完稿或都算初稿），且写成"**行业标准** X 天"而非"我以前要 X 天"——混口径会被读者抓住"拿初稿比完稿""你自己慢"两个把柄，一次评论区纠错就毁掉人设
- **发稿前正文丢给第二方模型盲审**（通道与调用代码见 `model-matrix`）：要求"只挑毛病 + 每条给问题/严重程度/修改建议"，它抓逻辑漏洞比自查可靠；但它报的**数字、文号、统计口径要回一手资料核过再改**——审查方自己也会编数
- **人设措辞**：对外一律"多年投资经验/产业投资"，不写"投行"（评论区追问"哪家投行"即人设崩塌，他的履历是产业投资不是券商投行）
- **账号资料（昵称/头像/简介）在 www 端或手机 App 改**：creator 创作服务平台 13 个菜单里没有任何资料编辑入口，`账号概览`点进去是纯数据页

## 合规红线（每一步都过，不绕）
- **对外文案先过脱敏闸**：禁写具体公司名（只写“3 家世界 500 强”“知名产业投资集团”，数字背书如操盘规模可留）；禁“代写/接单”（写“撰写/编制”）；禁真名、生日、薪资、低谷期经历——内部履历档案明令禁止进对外包
- **不批量留言 / 机器互动**：平台在打击 AI 托管账号，这是封号最快路径
- **不做无货源搬运代拍**：平台明令禁止，跨平台电子面单会被自动识别
- **不刷量、不批量模拟调用**：Skill 协议明文禁止
- 卖虚拟产品/特定类目有额外准入门槛（粉丝数、流水、入驻时长等），**动手前查平台官方规则原文，不信二手教程**
- **站外导流是封号级**：《交易导流违规管理细则》定义含“主动直接引导、**暗示间接**索取信息引导至私域或站外三方平台”，覆盖笔记/评论/置顶/用户资料/私信，官方出口只有小红书商城、直播间购物车、留资组件三条；谐音字、把联系方式放图片里都被识别。新号第一个笔记就违规基本等于养废
- **付费与免费必须分层隔离**（老板定的策略）：**笔记与 Red Skill 详情页只讲免费**，任何付费/商店/外部平台字眼都不出现在小红书内容里；把人往商店带的动作全部放在**用户主动安装之后的 Skill 文件内部**——那不在小红书管辖范围。同理：小红书只发免费版，付费版与商店维护归团队成员
