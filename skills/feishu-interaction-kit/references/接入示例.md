# 接入示例（四种接法）

本套件是**命令行工具**，只要你的智能体能执行 shell 命令或发 HTTP 请求，就能接。
下面是四种典型接法，选一种抄。

---

## 一、Shell / 任何 Agent 的 bash 工具

最直接：把命令当工具调用，解析输出的一行 JSON。

```sh
export FEISHU_APP_ID=cli_xxx FEISHU_APP_SECRET=xxx FEISHU_RECEIVE_ID=oc_xxx

# 一轮交互
C1=$(python scripts/feishu_card.py think-card | python -c "import sys,json;print(json.load(sys.stdin)['card_id'])")
python scripts/feishu_card.py update --card-id "$C1" --element-id think_live --text "💭 正在查资料"
C2=$(python scripts/feishu_card.py result-card | python -c "import sys,json;print(json.load(sys.stdin)['card_id'])")
python scripts/feishu_card.py update --card-id "$C2" --text "结论：……"
python scripts/feishu_card.py close  --card-id "$C1" --summary "查看完整思考过程"
python scripts/feishu_card.py close  --card-id "$C2" --summary "结论：……"
```

## 二、Python

```python
import json, subprocess

CLI = ["python", "scripts/feishu_card.py"]

def card(*argv):
    out = subprocess.run(CLI + list(argv), capture_output=True, text=True).stdout
    return json.loads(out) if out.strip() else {"ok": False}

think = card("think-card")                       # {"ok":True,"card_id":"c_1",...}
card("update", "--card-id", think["card_id"], "--element-id", "think_log", "--text", "检索中…")

result = card("result-card")                     # 战果独立成卡
card("update", "--card-id", result["card_id"], "--text", "第一段结论…")

card("close", "--card-id", think["card_id"], "--summary", "查看完整思考过程")
card("close", "--card-id", result["card_id"], "--summary", "第一段结论…")
```

**想自己发 HTTP 请求**（不加一层 subprocess）也可以，四个接口就够用了：

```
GET  /open-apis/auth/v3/tenant_access_token/internal   ← 换 token
POST /open-apis/cardkit/v1/cards                        ← 建卡
POST /open-apis/im/v1/messages?receive_id_type=chat_id  ← 发卡（interactive）
PUT  /open-apis/cardkit/v1/cards/{id}/elements/{eid}/content   ← 更新元素
POST /open-apis/cardkit/v1/cards/{id}/elements          ← 追加元素（带 type）
PATCH /open-apis/cardkit/v1/cards/{id}/settings         ← 关流式（注意是 PATCH）
```

## 三、Node.js / 任何语言

```js
const { execFileSync } = require("child_process");

function card(...args) {
  const out = execFileSync("python", ["scripts/feishu_card.py", ...args], { encoding: "utf8" });
  return JSON.parse(out.trim());
}

const think = card("think-card");
card("update", "--card-id", think.card_id, "--text", "正文…");
```

只要能执行子进程，语言不限（Go / Java / PHP / 易语言都一样）。

## 四、纯伪代码（跨框架 / 无 shell 环境）

```
think_card   = create(think_card_json)  并发送        → card_id_1
result_card  = create(result_card_json) 并发送        → card_id_2

循环(思考或工具调用):
    update(card_id_1, "think_log",  完整思考日志)
    update(card_id_1, "think_live", 最新一行)        # 节流 ≥0.5s

当正文开始:
    update(card_id_2, "streaming_content", 已生成正文)  # 打字机，节流 ≥1s

收尾:
    update(card_id_1, "think_title", 标题 + " ✅")      # 定格，停 spinner
    close(card_id_1, summary="查看完整思考过程")
    append(card_id_2, after="streaming_content", 状态行) # 耗时 / token / 模型
    close(card_id_2, summary=正文首行)
```

## 五、一轮完整交互长什么样

```
┌─ 卡 1（思考卡）─────────────┐
│ ▶ 思考和工具调用过程 ⚔️     │   ← 折叠面板，展开才看全量日志
│ 💭 正在核对数据源            │   ← 面板外一行实时窗
└────────────────────────────┘
┌─ 卡 2（战果卡）─────────────┐
│ 🏆 战果                     │
│ 结论正文……（打字机生成）      │
│ ✅ 已完成 · 12.3s · ↑103k ↓835│  ← 自动追加的状态行
└────────────────────────────┘
```

**为什么正文不放卡 1**：卡 1 里有思考噪音，长按整卡复制会连噪音一起复制。
正文单独成卡后，**长按卡 2 复制拿到的就是干净答复**。

## 六、性能与礼貌

- **节流**：思考窗 ≥0.5s 一次，正文 ≥1s 一次。刷太快既费额度又容易撞 `sequence` 问题。
- **不发消息也能自检**：`probe` 只建卡不发消息，适合 CI 或上线前跑。
- **长内容**：>15 行的正文不要塞卡片（手机端会被挤成一行一个字），走文件或云文档链接。
