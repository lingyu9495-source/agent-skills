# 错误码对照表（飞书 AI 卡片接入）

> 标 **【实测】** 的，是在生产环境真实复现并修好的；标 **【文档】** 的来自飞书开放平台文档，未亲测。
> 遇到没列出的码，先跑 `python scripts/feishu_card.py probe` 定位是哪一步挂的。

## 一、最常撞的四个

### `99992402` field validation failed 【实测】

**表象**：追加元素（`POST /cardkit/v1/cards/{id}/elements`）被拒，卡上什么都看不到。

**根因**：必填字段没给全 —— `type` 必填（`insert_after` / `insert_before` / `append`）。

**修法**：

```json
{
  "type": "insert_after",
  "target_element_id": "streaming_content",
  "elements": "[{\"tag\":\"markdown\",\"content\":\"hello\"}]",
  "uuid": "……"
}
```

### `9499` Invalid parameter type in json: Elements 【实测】

**表象**：和上面长得像，但报的是类型问题。

**根因**：`elements` 传成了 **JSON 数组**。这个接口要求它是 **JSON 字符串**（字符串里面再放数组）。
SDK 的类型提示本身就矛盾，照抄会踩。

**修法**：`"elements": json.dumps([...])`，不是 `"elements": [...]`。

### `300317` sequence number compare failed 【实测】

**表象**：卡片更新**偶发丢失**，日志里刷 `300317`。不是每次都失败，所以最容易被忽略。

**根因**：同一张卡被**并发写**，各自发号，序号重复或乱序。
（实测：三路并发写同一张卡，3 分钟内丢了 4 次更新。）

**修法**（二选一）：

- **单写者场景**：干脆不传 `sequence` —— 飞书不做乐观锁校验，最省心。本套件 CLI 默认如此。
- **多写者场景**：**每张卡一把锁**，把"发号 + 调接口"整体串行化：

```python
async with self._card_lock(card):           # 一把锁管一张卡
    card["sequence"] += 1
    await update(card["card_id"], seq=card["sequence"])
```

### `11310` 自定义色相关 【实测】

**表象**：卡片带自定义颜色时建卡/更新失败。

**根因**：自定义色必须 **明暗两套都写**，只写 `light_mode` 就报错。

**修法**：

```json
"style": {"color": {"cus-1": {
  "light_mode": "rgba(139,90,43,1)",
  "dark_mode": "rgba(200,155,105,1)"
}}}
```

## 二、路径与方法类

| 现象 | 根因 | 修法 | 来源 |
|---|---|---|---|
| 关流式报 `404 page not found` | `settings` 接口写成了 `PUT` | 用 **`PATCH`** `/cardkit/v1/cards/{card_id}/settings` | 【实测】 |
| 建卡后发消息，卡不出现 | `content` 结构不对 | `msg_type=interactive` + `content` 为 `{"type":"card","data":{"card_id":"c_xxx"}}` 的**字符串** | 【实测】 |
| 更新元素没反应 | `element_id` 写错 | 元素 id 必须与建卡 JSON 里的 `element_id` 完全一致 | 【实测】 |

## 三、权限与账号类

| 错误码 / 现象 | 含义 | 处理 | 来源 |
|---|---|---|---|
| `99991672` / `99991663` | 应用权限不足 | 后台开 `im:message`、`im:message:send_as_bot`、`cardkit:card:write`，**并发布版本** | 【文档】 |
| `230002` | 机器人不在该会话里 | 把机器人拉进群，或改用与它有会话的 `chat_id` / `open_id` | 【文档】 |
| 建卡成功、发消息失败 | 只有 CardKit 权限没有发消息权限 | 补 `im:message`；或先用 `send` 命令（1.0 静态卡，不需要 CardKit 权限） | 【实测】 |
| 换 token 失败 | `app_id` / `app_secret` 不对，或应用未发布 | 用 `token` 命令单测凭据 | 【实测】 |

## 四、排查套路（比记错误码更管用）

1. **最小复现**：`probe` 四步就是最小链路 —— 建卡 → 打字机 → 追加状态行 → 关流式。哪步挂就是哪类错。
2. **参数校验类报错，先查必填字段与类型**，别先怀疑权限或额度（`99992402` / `9499` 都是这类）。
3. **偶发丢更新，先想并发与序号**（`300317`），别怀疑网络。
4. **每个附加动作都单独统计成功率** —— 主流程成功、附加行 100% 失败，很容易长期没人发现
   （真实案例：状态行连续失败 59 次才被捞出来）。
