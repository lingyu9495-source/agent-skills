# 中文网络检索 (Chinese Web Search)

## 什么时候使用
- 任何需要检索**中文内容**的任务：市场调研、热点追踪、平台规则查询、竞品分析、政策法规核实
- 终端 curl 检索被反爬拦截，或需要批量跑多个搜索关键词时

## 搜索引擎回退阶梯（按顺序试，被拦就换下一个）
| 引擎 | 终端(curl)可用性 | 备注 |
|---|---|---|
| **360资讯搜索 news.so.com** | ✅ **2026-09-30实测可用（查平台规则/政策首选）** | `https://news.so.com/ns?q=<urlencoded>`——返回**按时间排序的媒体稿**，每条带出处+发布时间（如「新浪财经 2026-06-04 20:42」）。查**平台新规/官方公告/政策落地**时质量**明显高于**网页搜索（后者命中多为跨站重复的 SEO 洗稿）。页尾「为您推荐/换一换」块=360实时热点清单，可顺手当当日热点用 |
| **360搜索 so.com** | ⚠️ 2026-08-09起不稳 | 搜索页本身通常可用（300-400KB），但结果里的 `/link?m=` 跳转链接**反爬加重，常直接 HTTP 400**（本会话4个跳转全400）；连续查询会限流返回 NO RESULTS。仍是主力，但跳转链接失效时换搜狗 |
| 百度 baidu.com | ⚠️ 看运气 | 偶尔成功，但常触发「百度安全验证」反爬页（仅~1.4KB）；HTML 结果常嵌在 JSON 里，正则解析易失配；site: 检索也常被验证码拦（1438字节） |
| 搜狗 sogou.com | ✅ **2026-08-09实测可用（比旧记录强）** | 旧记录「❌ 通常被拦」**已过时**——本次实测带 UA 返回完整 HTML（388-556KB），小说/书源类查询命中率极高（能列出 10+ 个推文站直达链接）。`https://www.sogou.com/web?query=<urlencoded>`，结果链接 `/link?url=...` 同样要二次解析 `window.location.replace("真实URL")` |
| 必应 cn.bing.com | ⚠️ 有坑 | curl 返回 "Object moved" 重定向（需 -L）；页面可能是 GB2312 编码，UTF-8 解码报错 |
| **搜狗网页 sogou.com** | ⚠️ 时好时坏 | 2026-09-30 实测仅回 5.6–15KB 空壳（引擎选择每次先 `-w "%{size_download}"` 量体积，<30KB 立刻换家） |
| 内置浏览器 | ⚠️ 看环境 | browser_navigate 可能 auto-launch 失败（Chrome 未写 DevToolsActivePort）；可用时优先于 curl，但别依赖 |

**关键原则**：把「某引擎某次被拦」当**信号**而不是永久结论——回退阶梯本身就是模式。被拦 → sleep 3 → 换下一个引擎或换关键词重试。

## 脚本
`scripts/so_search.py` — 360搜索命令行检索+提取（标题/摘要/链接，最多10条，写文件并打印前3000字符）：

```bash
python scripts/so_search.py "关键词 关键词 2026" output.txt
```

要点：
- 用脚本文件而不是 `python -c` 内联（内联 -c 会被命令审批标记，且转义易错）
- 中文关键词加年份（2025/2026）和具体限定词，召回质量明显更好
- 结果链接是 `/link?m=...` 跳转，需要正文时再 curl 一次

`scripts/fetch_article.py` — 解析 so.com `/link?m=` 跳转 → 抓真实正文页（自动 utf-8/gbk/gb18030 解码）→ 打印标题/日期/关键词上下文（每词最多3处±120字），核实措辞不用整页进上下文：

```bash
python scripts/fetch_article.py "<so.com链接>" "中塔公路,二期,试运行"
```

## 批量调研模式（避免上下文膨胀）
1. 每条搜索写独立文件：`s1.txt s2.txt ...`（脚本第二参数指定）
2. 并行发 2 个 terminal 调用（每个 timeout 60-90s），互不依赖
3. 只把需要的摘要读进上下文，中间文件留在 `research_tools/` 目录
4. 同一引擎连续快速查询会限流（返回 NO RESULTS）→ 两条之间 `sleep 3`
5. 检索+提取的全量原始页先落盘，报告写完后可按需回查

## 调研报告产出模式（中文市场调研通用）
- **结论先行**：开头一页「核心结论」6-8条，每条是一个判断而非事实罗列
- **表格为主**：门槛/收入/风险/对比用表格呈现
- **数据带来源**：关键数字每行注明 `（来源: XXX, 日期）`，文末附来源清单
- **区分口径**：营销话术（"日入500+""月入过万"）与真实常态水平分开写，标注"头部个案"vs"常态"
- **时效声明**：平台政策/门槛迭代快，报告注明"以 APP 内官方最新公告为准"

## 陷阱
- **识别 SEO 洗稿**（2026-09-30 实测）：同一套说法（如「小红书2026最严新规，红线有三条…」）在多个不同站点**逐字重复出现**、且无官方公告名/日期 → 判为洗稿，**不采信为平台规则**；只采信带**官方公告名 + 发布日期**的转引并标「二手转引」。
- so.com 页面对提问式关键词会插入 **AI 问答块**（src 含 `ai.so.com`）——可参考但属 AI 生成摘要，权威性低，要标注
- 360 搜索会混入大量广告与引流站（"云码资源"等教程站），判断可信度看域名与发布日期
- 政策类数据（分成比例、保证金、粉丝门槛）各来源口径常打架（如直播分成 30%/50%/80% 并存）——优先官方公告，其次近期媒体，标注冲突
- **Windows 输出路径坑**（2026-08 实测）：git-bash 下给脚本 outfile 传 MSYS 风格 `/c/Users/...` 会 FileNotFoundError（Windows Python 不认 MSYS 路径）——输出路径必须用 `C:/Users/...` 正斜杠 Windows 格式
- **搜索词过长 → NO RESULTS**：360 对完整问句（>15字）常直接 NO RESULTS；拆成短词+限定词，如「视频号 实名 一个身份证 几个」比完整问句召回好
- **so.com 结果链接是 JS 跳转**：结果里的 `/link?m=...` 用 curl 直抓只得到 `window.location.replace("真实URL")`（约 300-370 字节）；先 `curl -s <link> | grep -oP 'window\.location\.replace\("[^"]+"\)'` 取出真实 URL 再抓正文
- **百度 curl 有时能拿到完整 HTML**（2026-08 实测带 UA 返回 ~988KB）：规则类问题页尾的「AI总结N篇结果」块是多源聚合+官方社区摘要（如微信开放社区），有用但属 AI 生成需标注
- **GBK/GB2312 编码坑**（2026-08 实测）：央广网 cnr.cn、部分政府/官媒站返回 GBK 编码，UTF-8 解码抛 UnicodeDecodeError 导致整页拿不到——抓正文按 utf-8 → gbk → gb18030 依次尝试解码（`scripts/fetch_article.py` 已内置）
- **重发旧闻带新页面日期**（2026-08 实测）：搜索结果页日期≠事件日期。门户/自媒体会按新日期重发旧事件稿（例：大象网 2026-06-28 页面标题「喀喇昆仑公路二期建成通车」，实际事件是 2020 年）——核实必须看**正文内的事件日期**，不能信搜索结果/页面上的日期
- **微信公众号文章：服务器/IDC IP 被全线拦截（2026-10-14 实测）**：本机抓 `mp.weixin.qq.com/s/...` → 所有 UA（iPhone 微信/安卓微信/桌面 Chrome/搜狗蜘蛛）＋参数（`?f=json`/`?scene=1`/`?src=11`）一律返回同一张「环境异常·完成验证」页（约 18165 字节、无 title）＝**IP 级拦截，不是指纹级**；headless 真浏览器同样过不去；`r.jina.ai`／archive.org／archive.today 在国内机房**不可达**；按 sn 反查 bing/360/搜狗 **0 命中**、百度触发安全验证；镜像站 freewechat/wxnmh/weixinyidu 不可达（ershicimi 首页可达但检索接口未通）。→ **别在服务器上反复试抓微信文**，直接请用户在自己设备「长按复制正文／截图」发来，或交家用宽带侧成员机代抓。
- 本机 `python` 可用（3.11）；不同环境可能只有 `python3`，脚本内不硬编码解释器名

## 内容溯源 / 找小说后续（2026-08-09 实测验证）

用户发截图问「这是哪本书/帮我找到后续」时，直接搜文字往往搜不到（弹幕流/短推文小说书名不公开、平台是小程序）。**正确流程**：
1. **先用视觉模型（GLM-4V）完整识别截图文字**——不只是书名，还有开头段落、角色名、平台名（页面顶部标题常是平台名如「辜铭书屋」= 抖音/微信小程序推文站，不是书名）
2. **开头原句精确搜**（`so_search.py "大学暑假第一天 我妈就给我安排了一场相亲"`）——大概率搜不到，正常
3. **问用户补充角色名**（男主/女配/配角名字）——这是定位关键！例：用户说「男主陆圳轩、女配江盈」→ 一把搜到《闺蜜说我让相亲对象侵犯她，我靠弹幕剧透杀疯了》（作者雨筠）
4. **搜到后确认渠道**：抖音推文小说多在非正规聚合站（翰墨读书屋/月华文学/霜叶文学阁/妙笔书单），正文反爬严重（`/link?m=` 跳转后常 400/反爬）；**提示用户去原平台（抖音小程序）搜书名看正版，聚合站有侵权风险不推荐硬抓**

**要点**：找不到书名 ≠ 找不到书——**角色名是最强检索锚点**（比平台名/开头句都强）；弹幕流/短篇推文书的名字带完整剧情梗概（如「闺蜜说我让相亲对象侵犯她，我靠弹幕剧透杀疯了」），搜书名关键词也能命中。平台名（辜铭书屋等）一般搜不到，别浪费时间。

**推文站正文抓取（2026-08-09 实测，反爬现状）**：
- 这类聚合站多为 **JS 渲染壳站**（首页只有备案图片+模板壳，如 qidiank.com/news/<ID>.html、gxadr.com/anfff/<ID>/），curl 直接抓正文拿不到；且**站点反爬=按 IP 封**（首个跳转能通、连续抓 2-3 个全 400/SSL 拒绝）
- SSL 证书错误（`CERTIFICATE_VERIFY_FAILED`）→ 用 `ssl.create_default_context(); ctx.check_hostname=False; ctx.verify_mode=ssl.CERT_NONE` 跳过
- 搜狗/360 的跳转链接二次解析会**随机指向站内其他文章**（同前缀不同 ID），抓到的可能不是目标书——抓正文前先确认页面标题含目标书名
- **结论：抖音推文短篇（如本单 9174 字 1 章节）别硬抓正文，直接给用户「原平台（抖音小程序）搜书名」的正版路径**，聚合站有侵权风险且反爬白费时间

## 新闻事实核查 / 核实报告（2026-08-12 实测）

用户要核实某新闻/论断（如「XX公路通车」「XX政策落地」）时，目标是**验证真伪+给出可写事实**，不是堆搜索摘要。流程：

1. **拆可核验原子**：论断里的每个 名称/日期/状态词 都是独立可核验点（公路名、口岸名、通车日期、信源）。逐个搜，别一次搜整句
2. **搜「名称+年份+状态词」**：`so_search.py "中塔公路 通车 2026"`、`"中塔公路 复工 2026"`——状态词换着试（通车/试运行/复工/竣工/贯通/开工），不同状态词召回不同进展
3. **优先一手权威源**：涉外项目→中国驻外使馆官网（`tj.china-embassy.gov.cn` 这类直接可 curl，是最高权威，含剪彩仪式、大使署名文章）；国内→新华网/央广网/政府网。媒体转载（腾讯号、网易号）降权且标注「自媒体转引」
4. **抓正文核对原文措辞**：别信搜索摘要——用 `scripts/fetch_article.py` 抓正文，确认原句是否真说了某状态（「试运行」≠「全线通车」）
5. **区分状态动词，不许混写**：通车/试运行/复工/竣工/贯通/开工含义不同。初稿若写「通车」而事实是「试运行」或「复工」，报告要明确纠正
6. **明确说「无」**：搜不到近期新闻时，直接结论「无 2026 年 X 月新通车新闻」，并给出**最近一条可写事实**（具体名称+日期+信源），供改写锚定

**核实报告格式（用户偏好，200-300字）**：
- 结论先行：先答「有没有」——1）近期（如2026年7-8月）无新通车/有重大进展（注明是复工非通车）2）最近可写事实锚点（名称+日期+信源+连接城市/口岸）3）权威信源+日期 4）无近期新闻时的替代事实
- 每条事实带信源+日期；自媒体来源标注；最后给「建议」：初稿表述应如何修正
- 旧闻重发陷阱：页面日期新≠事件新，正文内事件日期为准
