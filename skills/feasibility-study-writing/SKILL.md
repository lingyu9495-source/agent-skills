# 可行性方案（可行性研究）写作框架

## 触发条件

当用户需要以下任一任务时，激活此skill：
- 「帮我写一份XX的可行性方案/可行性研究/可行性报告」
- 「评估XX能不能做/值不值得做」
- 「XX方向调研一下，出一份分析」
- 「帮我分析XX的可行性」

## 核心原则

1. **结论优先** — 开篇给出总纲判断（如庙算总分/星级评分），不是从背景开始铺垫
2. **数据驱动** — 每个维度必须有最新市场数据支撑，标注来源等级（A/B/C/D）
3. **交叉验证** — 核心数据至少2个独立来源，矛盾处必须说明
4. **先搜后写（强制⚠️）** — 不凭知识库中过时的数据推断，必须做实时搜索。修改完后发之前要再次检查。**用户已连续多次纠正「不做搜索就写/搜索不够深入」，这条是硬性要求不是可选。** 搜索时：先广(3-5个关键词并行)→再精(打开关键文章提取数据)→再交叉(多源验证)
5. **迭代优化** — 用户通常会要求多轮修改（本session达5+轮），每轮都要比上一轮更深一层。保持「先理解用户反馈核心意图→整理修改清单→按优先级逐一改→再融合」的顺序
6. **视角对齐（重要⚠️）** — 写之前先问自己：**读者是谁？ta最关心什么？** 如果读者是合作方（如合作方管理层），ta们关心三个问题：为什么可行？能赚钱吗？怎么干？如果读者是投资人，ta们关心：市场多大？壁垒多高？增长逻辑？退出路径？**以读者的视角写，不是以写作者的视角写。**
7. **数据来源透明** — 每个数据点必须标注来源和可信度等级，末尾附完整数据来源表和关键假设说明清单

## 前置工作流（必做）

### Step 0: 先写指令 → 再干活 → 先尽调 → 再写作（强制四步）

#### 0a. 先写指令（给自己）
动笔/动手做任何事之前，先写一条清晰的指令给自己——说明「要做什么、用什么视角、期待什么产出」：
```
示例：「写AI智能体定制的商业可行性方案，视角=合作方管理层（关注三个问题：为什么可行？能赚钱吗？怎么干？），格式=飞书云文档（含Unicode框线表格），先做4引擎搜索再写。」
```
写完指令再开始执行。这个模式与「先分析用户真实意图→再拆步骤」规则并行，适用于所有任务。

#### 0b. 先尽调 → 再写作（强制⚠️ 用户多次纠正）
**核心铁律：绝对不允许「不搜索/不尽调就直接动笔写方案」。** 用户已多次纠正此问题——任何分析报告/方案/研究必须先做充分的信息采集，有了数据支撑再动笔。用户原话：「你忘记联网做深入尽调后再开始写方案了吗？尽调后再写东西才有说服力啊。」

顺序必须如下：
```
① 搜索尽调（多引擎+CDP百度） → ② 收集/整理数据 → ③ 交叉验证 → ④ 再动笔写
```
绝对不能：
```
① 动笔写 → ② 搜索补数据（这是错的！用户已纠正两次）
```

**搜索尽调时按以下步骤执行：**

```
第0步：知识库先行（MANDATORY ⚠️）
- 加载两个 IMA 技能
- 用简单关键词搜索知识库（单关键词比长短语效果好）
- 跨账号策略：一个账号搜空后自动换另一个
- 个人库文件可读全文，订阅库记录标题和框架参考即可
- 知识库提供的研究框架可作为联网搜索的"导航图"

第1步：回忆（session_search）
- 搜索历史对话中关于该主题的讨论
- 找出之前达成的结论、遗留问题、用户偏好

第2步：调研（多引擎搜索 + CDP百度强制前置）
⚠️ 禁止不搜索直接写。必须执行以下搜索协议：

```
引擎优先级（2026年7月验证有效）：
  1. CDP百度（最可靠）→ node ~/scripts/baidu_search.js "关键词" 2>&1 | head -50
  2. search.js all → cd ~/scripts && node search.js "关键词" all 2>&1 | head -80
  3. 浏览器的Bing国际版 → 适合英文查询
  4. 浏览器的搜狗搜索 → 常用于中文内容，但可能触发反爬

工作流：
  并行发起3-5个搜索查询，每个都通过CDP百度执行
  → 返回结果中提取URL列表
  → 用browser_navigate访问关键文章
  → browser_snapshot(full=true)提取全文
  → 注意识别AI生成内容（百家号可能标注"内容由AI智能生成"，数据降级使用）

每条数据标注：来源URL + 采集时间 + 权威性等级
```

第3步：合成
- 把已有知识（回忆/之前沉淀的文档）和最新搜索数据合并
- 检查数据一致性，矛盾处做交叉验证说明

第4步（新增）：迭代优化协议
当用户要求修改方案时，遵循以下流程：
1. **先理解用户反馈的核心意图** — 用户说的不一定是字面意思，要分析ta深层想解决的问题
2. **整理修改清单** — 把用户反馈拆成具体可执行的项目
3. **按优先级逐一修改** — 不是一次性全改，而是围绕核心问题展开
4. **多版本融合** — 当有多个版本时，提取每个版本的核心优势（收费模式/增长路径/数据支撑等）融合成一个完整版
5. **不要跳任务** — 用户要求做好一件事前，不要做无关的事
```

## 标准结构（10模块）

### 模块一：总纲结论

前置输出：庙算评分 + 一句话结论 + 置信度标注

### 模块二：市场可行性

- 市场规模（最新数据，标注来源等级）
- 竞争格局（四层分析法：大厂/中端/低端/高端）
- 需求分层（按入局优先级排序）
- 关键判断：窗口期长度、入场时机

### 模块三：技术可行性

- 技术栈验证状态（✅已跑通 / ⚡部分跑通 / ❌待验证）
- 交付周期测算（基础版/标准版/旗舰版分别列出）
- 成本结构测算（含各项成本的详细拆解）
- 关键技术挑战与解决方案

### 模块四：运营可行性

- 合作模式（如有合作伙伴，列出条款+谈判状态）
- 交付流程标准化SOP（接单→搭建→上线→运维）
- 启动阶段行动路线图（按周排布）
- 岗位分工（一人公司+AI员工模式）

### 模块五：财务可行性

- 收入预测（保守/乐观/爆发三个场景）
- 支出预测
- 利润模型（你的实际收入）
- 盈亏平衡点计算

**⚠️ 需要 IRR/NPV/回收期/17表勾稽/敏感性分析时 → 加载 `mh-calculation`（蜜獾测算）技能**，用其 scripts/calculator.py 精算，别手写财务模型。本模块管"财务叙事与利润公式"，mh-calculation 管"项目级精算"，产出接回本模块展示。

## ⚠️ 重要变体：服务型商业模式的可行性方案

**当方案论证的是「以服务交付为核心的生意」（AI定制/咨询/代运营/SaaS服务），而非「卖产品的生意」时，不能照搬上面的标准结构。**

标准结构先讲市场再讲财务，但服务型生意的读者（合作方/投资人/自己）最关心的是 **「这个模式到底能不能赚钱、怎么赚钱、能赚多久」**——这不是财务章节能说清楚的，必须有专门的商业模型章节。

### 服务型方案应采用的优先结构

将以下内容作为 **独立的「商业模式」章节**（放在市场数据之前或之后），而不是塞在财务模块里：

```
第一章：商业模式本质
├── 一句话说清：我们到底在卖什么
│   ├── ❌ 错误表述：「卖AI产品/卖技术方案」
│   └── ✅ 正确表述：「帮企业整理专属知识库、帮企业配置AI工作流，交付一个懂业务的AI智能体」
│       核心价值不是技术，是「技术到业务的翻译能力」
│
├── 技术中立原则（重要⚠️）
│   ├── 智能体底座用OpenClaw还是Hermes、大模型用哪个——全部按客户需求选型
│   ├── 不受任何技术平台绑定，不推销特定厂商
│   └── 我们的工作是「技术搬运整合+业务场景匹配」
│
├── 核心公式：总收入 = 新客数 × 客单价 × 转化率 + 老客数 × 续费率 × 续费单价
│
├── 收费模式模板（已验证，可直接套用）：
│   ├── 前期开发费：¥5,000（一次性）——覆盖需求调研+知识库搭建+智能体配置+上线
│   ├── 年维护费：¥5,000/年——覆盖知识库更新+模型调优+技术支持
│   └── 基础设施费用：客户自担——服务器/算力/硬件客户自行采购，我们不做中间商
│
├── 成本结构：
│   ├── 人力成本（70%+）：首年约¥3,000-5,000/客户，续费约¥200-500/年
│   ├── 算力/API成本（30%-）：首年约¥200-500/客户，续费约¥200-500/年
│   └── 结论：无固定资产投入、无库存、有单就赚
│
├── 边际成本曲线
│   ├── 第1个客户需要X天（从零）
│   ├── 第5个同行业客户只需30%时间（模板复用）
│   └── 结论：每做一个同行业客户，成本打6折
├── 收入模型（三阶段）
│   ├── 验证期（1-3月）：免费/成本价跑3-5家，目的不是赚钱
│   ├── 爬坡期（4-8月）：月增X家，验证可复制性
│   └── 稳定期（9月起）：续费收入占比上升，利润率大幅攀升
├── 12个月盈利能力模拟（表）
│   ├── 逐月列出：新增客户数/新增收入/续费收入/总成本/净利润
│   └── 关键转折点：第几个月起续费开始显著贡献利润
└── 风险边界
    ├── 续费率<30%才真正有威胁
    ├── 产能瓶颈通过模板化+SOP缓解
    └── 多模型切换应对API涨价
```

### 为什么服务型方案必须先讲商业模式

| 原因 | 说明 |
|:-----|:------|
| 读者第一反应是「这能赚钱吗？」 | 不回答这个问题，后面的市场数据没有锚点 |
| 服务型生意有经营杠杆 | 固定成本低但边际成本递减，模式自洽意味着越做越赚 |
| 续费是服务型生意的命门 | 必须从一开始就论证续费逻辑（而不是一年后才想） |
| 合作方最关心分成和可持续性 | 没有清晰的商业模型，合作方无法判断值不值得投入 |

### 服务型 vs 产品型结构对比

| 维度 | 产品型生意 | 服务型生意 |
|:-----|:----------|:-----------|
| 核心问题 | 市场够大吗？产品有竞争力吗？ | 这个模式能持续赚钱吗？怎么赚钱？ |
| 收入结构 | 一次性销售为主 | 首次收入+续费，越做越轻 |
| 关键指标 | 转化率、客单价 | 续费率、边际成本、客单价 |
| 壁垒 | 技术/专利/品牌 | 行业知识积累、本地化服务、客户信任 |
| 方案结构重心 | 市场→产品→技术→财务 | **商业模式→市场验证→产品→交付→财务** |

### 判断何时用服务型结构

当项目具有以下特征时，必须采用服务型优先结构：
- ✅ 人力投入是核心交付要素（而非代码/产品）
- ✅ 有续费/订阅模式
- ✅ 边际成本随经验积累递减
- ✅ 本地化服务是壁垒之一
- ✅ 没有硬技术专利壁垒（壁垒来自know-how和信任）

## 📈 投资分析深度（进阶模块）

当用户是合作方/潜在投资人，或要求「投行级别」分析时，在标准方案基础上增加以下深度分析维度。

### 深度维度一：行业生命周期判断

| 判断维度 | 导入期特征 | 成长期特征 | 当前表现（以AI智能体为例） |
|---------|-----------|-----------|------------------------|
| 技术成熟度 | 概念验证 | 规模化应用 | 基础模型可用，但行业适配不足 |
| 渗透率 | <5% | 5-30% | 约10%（长江商学院2026调研） |
| 客户认知 | 极少数尝鲜 | 早期大众接受 | 听说过但不知道怎么用 |
| 竞争格局 | 少数玩家 | 大量进入 | 大厂占头部，长尾未覆盖 |
| 商业模式 | 探索期 | 验证期 | 大厂高价方案vs低价需求矛盾 |

**写方案时：** 先用这个表格定位行业所处阶段，然后基于阶段特征论证入局时机的合理性。

### 深度维度二：四层竞争格局分析

```
竞品分层框架：

L1 - 大厂全栈（价格30-50万+，目标：大型集团）
  → 如华为云、腾讯云、百度千帆
  → 与我方关系：不构成直接竞争（客群不同）

L2 - RPA转型厂商（价格15-50万，目标：中大型企业）
  → 如实在智能、来也科技、弘玑、金智维
  → 与我方关系：间接竞争（主打自动化，非知识库）

L3 - 垂直AI服务商（价格5-20万，目标：行业特定中小企业）
  → 如小禾AI、环曜
  → 与我方关系：部分重叠（场景不同）

L4 - 个人/小团队（价格3-10万，目标：微型企业）
  → 自由开发者、小型工作室
  → 与我方关系：直接竞争但规模小
```

**写方案时：** 按此框架定位我方，论证为什么要做这个价位段、为什么这个价位段有未被满足的需求。

### 深度维度七：区域竞争环境分析方法

当方案需要论证「某地区是否有竞品/竞争强度如何」时，使用以下方法：

**四引擎交叉搜索协议：**

| 引擎 | 搜索内容 | 验证目的 |
|:----|:---------|:---------|
| CDP百度 | 本地公司搜索（"本地 AI智能体 公司"） | 主要搜索 |
| 搜狗 | 同关键词交叉验证 | 验证百度结果 |
| 360搜索 | 补充搜索 | 查漏补缺 |
| Bing国际版 | 验证是否有全国性竞品进入 | 全局视角 |

**搜索判定标准：**
- 四引擎均未找到匹配公司 → 该区域为空白（可信度高）
- 找到公司但方向不同 → 标注差异（如"做内容生成，非企业智能体"）
- 找到直接竞品 → 详细对比分析（价格/服务/区域）

**写方案时：** 在竞争格局章节中单独列出"区域竞争环境"小节，输出搜索结果和结论。可放入表格：

```
| 搜索方式 | 搜索结果 | 结论 |
|---------|---------|------|
| 百度CDP | 未找到匹配公司 | 无直接竞品 |
| 搜狗 | 同上 | 同上 |
| 360 | 同上 | 同上 |
| Bing | 同上 | 同上 |
```

### 深度维度八：市场规模分层（TAM/SAM/SOM）

当需要全面展现市场规模时，用三维分层替代单一数字：

| 市场层级 | 定义 | 规模（年份） | 说明 |
|---------|------|------------|------|
| **TAM**（总可触达市场） | 全行业市场规模 | XX亿 | 来源，CAGR XX% |
| **SAM**（可服务市场） | 我方目标客户可触达部分 | XX亿 | 按份额/比例估算 |
| **SOM**（可获得市场） | 区域/细分首次可达 | XX亿 | 按渗透率估算 |

**三层结构的意义：** TAM画饼（行业天花板高）、SAM切饼（目标清晰）、SOM吃饼（现实可达）。

### 深度维度九：方案依据与假设清单

末尾附完整表格：

| 来源 | 具体数据引用 | 可信度 |
|------|-----------|--------|
| 来源A（详细出处） | 市场规模XX | ⭐⭐⭐⭐⭐ |
| 来源B（详细出处） | 渗透率XX% | ⭐⭐⭐⭐ |
| 来源C | 竞品定价 | ⭐⭐⭐（需独立验证） |

关键假设清单（列出所有重要假设及其依据）：
| 假设 | 取值 | 依据 |
|------|------|------|
| 市场增长率 | XX% | 来源A报告 |

#### ⚠️ 服务型方案的成本哲学（用户核心认知，必须遵循）

**核心理念：** 服务型生意的成本结构极其简单——**就只有人力成本和研发算力成本，有单接基本上就是盈利的。**

| 成本项 | 说明 | 特征 |
|-------|------|------|
| 人力成本（70%+） | 需求调研+知识库搭建+配置+测试+培训 | 随经验积累递减，模板化后可再降40-60% |
| 算力/API成本（30%-） | 调试期间的大模型API调用 | 按量计费，可控，最高¥500/单客户/年 |
| 硬件/固定资产 | **客户自担** | 我们不做中间商，不赚硬件差价 |

**写方案时遵循以下原则（违反即被用户纠正）：**
1. **不写复杂财务模型** — 用户明确不要敏感性分析、不要退出路径、不要股市分析、不要三年利润表预测。财务部分写清楚收入和成本的基本公式即可
2. **「有单就赚」是核心认知** — 成本没有固定摊销，每一单单独核算，利润率透明
3. **利润公式极简** — `总利润 = 新客数 × (¥10,000-¥5,500) + 续费客数 × (¥5,000-¥1,000)`
4. **当用户明确要求简化财务时，直接砍掉对应模块** — 不要犹豫，不要问「要不要加回来」。用户说「不做敏感性分析」就一个字都不要提
5. **其他板块要做专业深度** — 简化财务≠简化方案。市场、竞争、商业模式、交付流程这些板块要做到投行级深度

### 迭代优化模式（本session沉淀的5轮经验）

当同一个方案需要多轮迭代时，遵循以下节奏：

```
第1轮：写出核心框架和基础内容
  → 用户反馈：深度不够、数据不足
  
第2轮：增加市场数据和竞争分析
  → 用户反馈：缺尽调、先搜再写

第3轮：先做多引擎搜索再写
  → 用户反馈：视角要投行级别

第4轮：投研视角重构（三级火箭/TAM-SAM-SOM/单位经济）
  → 用户反馈：删掉敏感度分析、退出路径、股市

第5轮：融合版（取各版本精华：收费模式/增长路径/数据支撑）
  → 最终满意
```

**关键教训：**
- 不能跳任务（用户要求先做A，不要同时做B）
- 每一轮都要比上一轮有实质性进步（不只是改格式）
- 多版本时，主动提取每个版本的最佳部分融合成一个完整版
- 先理解用户真实意图，再动手改（用户说"不够深度"不是要更长的废话，是要更扎实的数据）

## 🎯 进阶方法论：三视角论证框架（业务策划PPT专用）

**适用场景：** 当用户要求「论证更扎实/可行性更强」时，用于已有方案/PPT的深化改造。从三个专业视角交叉论证，让方案的每个论点都有多重支撑。

### 为什么需要三视角？

单一视角的方案容易被挑战：
- 只说市场大 → 「数据哪来的？口径是什么？」
- 只说能赚钱 → 「凭什么小团队能做？风险在哪？」
- 只说产品好 → 「市场验证了吗？用户真的需要？」

三视角论证的核心优势：**同一论点从不同专业视角各自论证一次，互相印证形成「论证三角」——单个视角可能被质疑，三个视角交叉的结论几乎无法反驳。**

### 三视角定义

| 视角 | 核心问题 | 典型表达 | 输出物 |
|------|---------|---------|--------|
| **投行/投资视角** | 「这个生意能赚多少钱？能赚多久？」 | 市场规模、LTV/CAC、单位经济、增长曲线 | 财务模型、市场验证表、规模化逻辑 |
| **企业运营视角** | 「具体怎么干？一个人行不行？」 | 成本结构、时间分配、供应链、风险矩阵 | 落地路径、成本清单、人员配置 |
| **产品经理视角** | 「用户为啥要买？怎么用起来？」 | 用户旅程、转化漏斗、MVP定义、功能优先级 | 产品路线图、用户地图、AB测试方案 |

### 论证框架

对方案中的每个核心论点，从三个视角各写一段论证：

```
【论断】：AI员工服务方向可行

┌─ 投行视角 ─────────────────────────────────────────┐
│ 2026年中国AI Agent市场480亿元（CAGR 53.7%），      │
│ 中小企业采用率35-42%（vs大型78%=填补空间），        │
│ 63%企业计划增加投入。LTV/CAC比6-15倍>3倍健康线。    │
└────────────────────────────────────────────────────┘

┌─ 企业运营视角 ─────────────────────────────────────┐
│ 一个人+¥5,000可启动（服务器¥100/月+API按量），     │
│ 每个客户交付工时从10天→3天（模板复用），            │
│ 月¥80,000-120,000时仍为一人管理（40个客户）。       │
└────────────────────────────────────────────────────┘

┌─ 产品经理视角 ─────────────────────────────────────┐
│ 用户旅程：¥9.9诊断→免费试用→个人版→企业版→锁定，  │
│ 每个环节设计「爽点」（记得住→有效果→省时间→换不掉），│
│ 双产品矩阵（引流¥999+利润¥1,999-6,999/月）形成闭环。 │
└────────────────────────────────────────────────────┘

=> 三重验证结论：市场有空间 ✅×运营能落地 ✅×产品有闭环 ✅ = 方向可行
```

### 使用流程

#### Step 1: 提取原方案核心论断

从原始方案/PPT中提取3-5个核心论断（不是全部细节，而是支撑结论的关键论点）。例如：
- 「AI员工市场正在爆发」
- 「大厂不会来抢这个市场」
- 「一个人低成本就能启动」

#### Step 2: 每个论断三视角论证

对每个核心论断，从三个视角分别写论证段落。每个段落：
- 投行视角：市场数据+财务数据+对标案例 → 回答「这数据靠谱吗？」
- 运营视角：成本+流程+资源+风险 → 回答「这能干成吗？」
- 产品视角：用户+场景+体验+增长 → 回答「用户会买吗？」

#### Step 3: 标注论证强度

每条论证标注来源等级：
- ⭐⭐⭐ = 一手数据（IDC/Gartner/政府）
- ⭐⭐ = 二手数据（媒体报道/行业分析）
- ⭐ = 推理/类比（历史模式推演）

#### Step 4: 融合输出

将三视角论证整合进原有方案：
- **PPT场景**：正文只加脚注标记（¹²³），详细论证放speaker notes
- **文档场景**：每个核心章节后加「多维验证」段落
- **口语场景**：准备三个角度的「一句话版」供讲述时切换

## ⚡ 反推思考法（逆向提案框架）

**适用场景：** 当用户说「反推思考一下，改改内容」——即合作方/客户有初步想法，需要出一份能打动对方的方案。

### 核心逻辑

不是技术驱动路线（我有技术→能做什么→卖给谁），而是反过来从对方的痛点出发：

```
❌ 正向（技术驱动）：
   技术能力 → 产品功能 → 市场分析 → 定价
   → 对方看完内心OS：「这跟我有什么关系？」

✅ 反推（客户痛点驱动）：
   对方现状+痛点 → 不做会损失多少 → 解决方案 → 能赚多少钱 → 对方只需做xxx
   → 对方看完内心OS：「这说的不就是我吗？！怎么做？」
```

### 反推五步法

```
Step 1: 共情 — 先讲对方的困境
   用事实和数据说出对方最头疼的事，不是想象出来的。
   例：「获客越来越难，电话销售拒接率95%+，地推覆盖有限」

Step 2: 制造紧迫感 — 讲不做会损失什么
   算账对比：不做会损失多少？同行做了会怎样？
   例：「你不做，同行会做。到时候不是要不要做的问题，是被别人抢走多少客户的问题」

Step 3: 给药 — 这时候才讲你的方案
   不讲技术细节，只讲「能帮对方解决什么」。
   例：「一个让企业主自己扫码体检、发现问题、主动找你们解决的AI工具」

Step 4: 算账 — 讲能赚多少钱
   用最直白的三层漏斗算账：引流→筛选→利润。
   重点算：月成本多少、转化几个客户回本、多出来的都是利润。

Step 5: 降低行动门槛 — 讲对方只需要做xxx
   让对方觉得「这事很简单，不用懂技术，出点力就行」。
   例：「你们只需要做5件事——提供LOGO、发二维码、正常接待...全部很简单」
```

### 核心原则

| 原则 | 说明 |
|:----|:------|
| **删光技术术语** | Node.js/DeepSeek/MySQL等一个都不提，只保留对方听得懂的话 |
| **先痛后药** | 前30%篇幅讲痛，70%讲药。不要上来就讲产品 |
| **每页算一笔账** | 每讲一个功能，马上跟一个「这能帮你省多少钱/赚多少钱」 |
| **风险前置** | 主动说出对方可能的顾虑，逐个回答，而不是等对方来问 |
| **收尾要可执行** | 最后一步必须是对方立刻能做的事（确认意向→给资料→等上线） |

### 反推版 vs 技术版对比

| 维度 | 技术版（❌） | 反推版（✅） |
|:-----|:------------|:------------|
| 开头 | 市场背景·技术栈·产品功能 | 你的困境·你的损失·你的机会 |
| 技术描述 | Node.js+DeepSeek+MySQL | 手机扫码即用·3分钟出报告 |
| 数据来源 | 企查查API·爬虫引擎 | 国家公开数据·免费·安全 |
| 合作模式 | 藏在末尾一小段 | 独立成章，3个方案可选 |
| 风险 | 不提 | 常见顾虑逐一回答 |
| 语言风格 | 技术白皮书 | 商业提案·说人话 |

### 反推版的标准交付物组合

当用户说「先帮规划个方案给对方看」时，默认产出两份：

| 交付物 | 用途 | 生成方式 |
|:-------|:-----|:---------|
| **PDF** | 对方详细阅读，逐章看 | pandoc→wkhtmltopdf |
| **PPTX** | 对方开会演示，视觉冲击 | python-pptx编程生成·蓝色主题 |
| **两份一起发** | PDF细读+PPT展示 | MEDIA附件直接发聊天框 |

PPT设计规范（用户偏好）：
- 主色调：蓝色系（深蓝#0F2B5B + 主蓝#1A56DB + 浅蓝#3B82F6）
- 每页一个核心信息，不要信息过载
- 多用卡片+对比表格，少用纯文字
- 第一页封面必须有标题+副标题+出品方

### 实战案例

本session 某AI问诊平台方案（v1→v2转换）：

| v1（技术版❌） | v2（反推版✅） |

## 注意事项和常见陷阱

- ❌ 不要写空话大话——每个判断都要有数据支撑
- ❌ 不要跳任务——用户要求先做好这个重要事情，说明ta偏好一件事做到完成再进入下一件
- ❌ 不要忘了标注数据来源和等级——否则读者无法判断可信度
- ❌ 不要只写乐观场景——必须同时写风险和最坏情况
- ❌ 不允许不搜索直接写——用户已两次纠正，这条是强制要求
- ❌ 标题不含合作方名称——不要写给合作方这类字样
- ❌ 不提交初版就完事——用户通常要2-5轮迭代，每轮都要有实质性进步
- ⚠️ 财务模型要保守，别用乐观数据算保本点
- ⚠️ 技术可行性不能只列技术方案，要标注各方案的实际验证状态
- ⚠️ 数据来源降级规则：标注AI生成的文章（如百家号标内容由AI智能生成）降为B级或C级
- ⚠️ 迭代节奏：用户每次提修改意见，先理解ta真实意图（ta要的不仅是改格式，而是更有深度），再动手改
- ⚠️ 搜索限制：Bing国际版对中文查询无效（会被解析为年份），Bing国内版被屏蔽。中文搜索首选CDP百度
