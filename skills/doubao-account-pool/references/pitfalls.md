# 豆包多账号池自动化 · 坑清单

> 每条包含 ［症状］［根因］［正解］三要素，按危害程度排序。

---

## 1. 后台标签页 hidden 导致注入/发送无效

**症状**：脚本注入提示词后发送，对话里出现空消息或零新生成图；`SET_LEN=0`，但页面无报错。

**根因**：Chrome 标签页处于 hidden 状态（`visibilityState=hidden`），JS 注入对 hidden 标签页不生效；同时浏览器渲染被挂起，DOM 交互全部静默失败。

**正解**：用 `doubao_cli.py visible <n>` 把标签页提到前台恢复可见性；窗口位置在配置里用 `chrome_args_extra` 固定成屏内坐标，确保每个窗口露出 ≥100×100 像素。验证 `@@VISIBLE slot=<n> AFTER {...}` 里 `vis=visible`。**不要把窗口挪到屏幕外当"后台"用**——屏幕外的窗口在 Windows 上可能被渲染引擎标记为 hidden。

## 2. outerWidth/outerHeight=0 的自动化指纹

**症状**：脚本检测到 `window.outerWidth === 0 && window.outerHeight === 0`；页面某些功能（如视频生成按钮点击）不响应。

**根因**：`--window-position=-3000,-3000` 把窗口移到屏幕外，Chromium 将 outerWidth/outerHeight 报告为 0；部分 React 组件依赖这些值判断窗口状态。

**正解**：窗口挪回屏内并设置合理的 outerWidth/outerHeight（≥100×100）。用 `doubao_cli.py visible <n>` 恢复可见性。启动号位时不要用极端负坐标，改用能露出窗口角的坐标（在配置的 `chrome_args_extra` 里定）。

## 3. 富文本编辑器（TipTap/ProseMirror）注入失败与发送按钮定位

**症状**：`SET_LEN=0`（注入量为 0），或注入成功但点发送无反应；页面无报错。

**根因**：
- TipTap/ProseMirror 编辑器需要通过 `div.editor.commands.setContent(text)` 同步内部状态，直接设置 DOM innerHTML 不触发编辑器的 React 状态更新。
- 发送按钮 `#flow-end-msg-send` 只在会话页存在；首页或新对话页需按兜底规则查找（无文字 + 含 svg + 位于页面下半部）。
- 编辑器未就绪时（冷账号刚导航到 `/chat/`），注入返回 `SET_LEN=0` 但脚本仍点了发送——发出空消息。

**正解**：
1. 点"视频生成"后轮询编辑器就绪：`document.querySelector('[contenteditable=true],textarea')` 存在，最多 10 次×2s。
2. 注入后校验 `SET_LEN>0`，为 0 就重试（×5，间隔 3s）。
3. 仍为 0 **不要发送**，标记该镜待重投。
4. 发送成功判据：输入框内容归 0 + URL 变为 `/chat/<对话id>` + 消息区出现提示词回显。
5. JS 合成 click 对 SPA 无效，必须用 CDP `Input.dispatchMouseEvent` 真点击。

## 4. 取图必须做基线闸

**症状**：报告"成功 3/3，全部 2848×1600 合格"，但实际拿到的是上一轮的旧图。

**根因**：取图逻辑写成"页面上找最大的生成图"——找的是**页面上现存的**图，不是**本轮**的图。并发或上一轮残留会导致旧图被当新图搬回。

**正解**（三道闸缺一不可）：
1. **投喂前数 `img[src*='rc_gen_image']` 数量记基线**。
2. 轮询到"正在生成"消失后，复读数量**必须 > 基线**。
3. 再等 8–10 秒复读一次（等这一轮出齐），数量没增长 = 本轮无新图，**报 FAIL 并终止**。
4. 下载过滤：只取 `naturalWidth>2000` 的真图（缩略图 ≈490px）；单文件过小（<20KB）跳过。
5. 落盘原子性：先写 `<目标>.tmp` 再 `os.replace` 覆盖——基线闸未过时磁盘零残留。

## 5. 不同文件名 md5 相同 = 静默失效

**症状**：三个不同文件名的图，md5 完全一致；甚至就是上一轮的旧产物。链路没有报错、文件尺寸也对。

**根因**：并发批次抢号导致取图逻辑把旧图当新图搬回；或页面残留上一轮生成结果。

**正解**：每批产出必须跑 md5 去重检查：
```bash
md5sum <产出目录>/*.jpg | awk '{print $1}' | sort | uniq -d
```
出现重复 = 整批不可信，**如实报"这批作废"并给根因**，不把"尺寸正确"当成功证据。先去重体检、再进质检——拿重复图去质检只会得到一致的高分，掩盖失效。

## 6. 额度耗尽的静默拒答

**症状**：提示词发出、零回复、不出确认卡、不报错；脚本报 `@@FAIL 本轮无新生成图(base=0 cnt=0)`。

**根因**：豆包免费额度耗尽后，页面文本写着"抱歉，我无法生成你要求的内容"或"今日视频生成免费额度已用完"——是**内容安全前置过滤拒答**或**额度用完**，不是脚本坏了。暴力词（`血`/`砍`/`杀`/`尸`/`屠`）与族裔特征词同现时命中率最高。

**正解**：
1. 拿到 `@@FAIL` 后**先读页面文本**，确认是否含"无法生成"/"免费额度已用完"。
2. 确认是额度问题 → 该号当天停止，等次日刷新。
3. 确认是拒答 → 扫描提示词敏感词（`{血:0, 砍:0, 杀:0, 尸:0, 屠:0}`），改写为安全正向表述。
4. 脚本层止血：拿到输出后立刻判断页面文本是否含"无法生成"，命中就 `@@REFUSED` 立即返回，别白等 300 秒。

## 7. 二维码过期/取到死码

**症状**：发出去的二维码扫不出来，提示"二维码已过期"。

**根因**：二维码有效期只有 1–2 分钟；截图到发出之间如果超过有效期，对方拿到的就是死码。

**正解**：
1. 取码前后检查页面是否显示"二维码失效"/"刷新二维码"。
2. 取码后**立即**发出，不要攒批。
3. 如果过期，用 `doubao_cli.py login <n>` 重新出码（自动勾选同意协议）。
4. 不要用整屏截图发二维码——`doubao_cli.py login <n>` 直接输出裁切放大的单张 PNG。

## 8. JS 合成 click 对 SPA 无效

**症状**：`document.querySelector('button').click()` 执行后页面无反应；截图字节数完全不变。

**根因**：豆包是 React SPA，组件的 onClick 是 React 合成事件，不绑定在原生 DOM 事件上；`element.click()` 不经过 React 的事件系统。

**正解**：必须用 CDP `Input.dispatchMouseEvent` 发送真实鼠标事件（mousePressed + mouseReleased）。React 芯片组件（如"视频生成"按钮、模型选择器）全部走这条路径。

---

## 9. 下拉/弹层是开关式的

**症状**：点开模型选择下拉菜单后"什么都找不到"；或点比例/时长选择器后选项消失。

**根因**：下拉/弹层是**开关式**的：点一次开、再点同一处就关。连续点两次等同于没点。

**正解**：
1. 点击前先确认目标元素存在且可见。
2. 点击后等 1–2 秒再读取弹层内容。
3. 不要在同一位置连点两次。
4. 读完选项后，点别处或按 Esc 关闭弹层再进行下一步。

---

## 10. 复用别人的号位目录导致 cookie 串号/互相踢下线

**症状**：号位 A 和号位 B 同时在线，一个突然掉登录；或号位 A 的操作出现在号位 B 的对话里。

**根因**：共享了同一个 Chrome user-data-dir，两进程竞争同一份 cookie/session 存储。

**正解**：
1. 每个豆包号 = 一个独立 Chrome user-data-dir + 独立 CDP 端口（端口约定：号位 n → 9230+n）。
2. **绝对不复用别人的号位目录**。
3. 登录态存在 user-data-dir 磁盘上，关掉浏览器不会掉登录——不需要共享目录来保持登录。
4. 脚本只用 pidfile 杀自己的进程树，**永不** `taskkill /IM chrome.exe`。

## 11. 批量并发不做错峰会触发风控

**症状**：多个号位同时提交，全部被风控拦截或限流；号被标记异常。

**根因**：同 IP 多账号同时操作会触发豆包的异常行为检测。

**正解**：
1. 多号轮转时错开节奏，不要 5 个号同时狂点。
2. 号间 sleep ≥3 秒错开。
3. 提交后固定等 5 分钟再回来看结果，禁秒级轮询。
4. 实际安全并发 6–10 个号位（按内存和风控边界定）。
5. 同一动作连续失败 3 次 → 立即停手，硬试 = 风控加速器。

## 12. 环境里没有 ffprobe/wmic 时的规格探测替代方案

**症状**：无法用 `ffprobe` 或 `wmic` 探测视频规格（宽高/时长/帧率/音轨）。

**根因**：系统 PATH 里没有 ffprobe/ffmpeg；wmic 在部分 Windows 版本中被弃用。

**正解**：用 PyAV（`import av`）：
```python
import av
container = av.open('video.mp4')
stream = container.streams.video[0]
print(f"宽高: {stream.width}x{stream.height}")
print(f"帧率: {stream.average_rate}")
print(f"时长: {float(container.duration) / 1e6:.2f}s")
for s in container.streams:
    if s.type == 'audio':
        print(f"音轨: {s.codec_context.name} {s.rate}Hz")
container.close()
```
需要 ffmpeg 时从剪映/WEMedia 插件目录取（`glob('**/JianyingPro/*/ffmpeg.exe')`），别写死版本号目录。

## 13. 抽帧差分必须用 `%03d` 零填充命名

**症状**：用 `p%02d.png` 抽 193 帧 → 文件名 `p01…p99, p100…p193`，`glob` 字典序把 `p100` 排到 `p10` 后面 → 帧序错乱 → 逐帧差分裂出假尖峰 → 误报"片中有 2 处硬切"。

**根因**：文件名长度不一致导致字典序≠数字序。

**正解**：抽帧一律 `%03d`；判"有无跳切"前先自检帧序单调（帧数==抽帧数、抽样差分无孤立尖峰）。

## 14. cv2.imwrite 在中文路径下静默失败

**症状**：脚本运行无报错，日志打 OK，但文件根本没写出来。

**根因**：`cv2.imwrite(中文路径, img)` 返回 False 但不抛异常。

**正解**：
```python
ok, buf = cv2.imencode(".jpg", img, [int(cv2.IMWRITE_JPEG_QUALITY), 96])
assert ok
buf.tofile(out_path)  # 写盘后断言文件存在且字节数 > 0
```
PIL 的 `Image.save()` 无此问题；只有 OpenCV 的读写函数要绕。

## 15. 账号套餐档位 ≠ 视频额度档位

**症状**：以为"已登录且有视频入口"就能免费出视频，编排批次后发现 1/3 的镜头排进了扣款路径。

**根因**：号位的套餐档位（免费/标准/加强/高级）和它的视频额度档位（当日是否还剩免费额度）是两回事。额度按日刷新，同一批 6 个号里能免费出视频的可能只有 4 个。

**正解**：每次开工都要重新探一遍——用探针逐号各试一次，读确认卡文本判 FREE/PAID：
- 确认卡里出现"付费额度/订阅/专业版" → PAID，停该号，改派给 FREE 号。
- 只有明确免费才回确认。
- **闸门要"每镜每号"都过**，不是开工时过一次——同一号连投数镜后额度可能中途耗尽。
- 批次按 FREE 号数量切，不要按号位总数切。

## 16. 内容安全前置过滤拒答的敏感词陷阱

**症状**：同一批提示词全过，换几个词全挂；暴力词 + 族裔特征词同现时命中率最高。

**根因**：豆包的内容安全过滤会在提交前拦截，不扣额度但静默拒答。负面清单本身也算输入——`【禁止】…血、伤口、尸体、断肢、刀剑加身或被砍中的瞬间…` 里的 血/尸/砍 会加重命中。

**正解**：
1. 投料前对提示词做敏感词扫描：`{血:0, 砍:0, 杀:0, 尸:0, 屠:0}`。
2. 负面清单改写成安全正向表述：`不出现伤口与倒卧的人形、兵器触及人身的瞬间`。
3. 族裔标签去掉，只留装束视觉特征（圆顶皮帽/左衽短袍/皮甲片/单侧辫发）。
4. 踩坑词替换：`屠城` → `破城`/`兵祸`/`战争大场面`；`砍杀` → `紧追不舍地逼向`/`兵器高举未触及任何人身`。
5. `压抑` 单独出现也可能被拦 → 统一用"安静克制/忧虑/凝重"替代。

## 17. 强杀批量脚本会留僵尸锁

**症状**：下一批次对应 slot 干等（每 6 秒重试，最多 900 秒），表现为"迟迟不出图"。

**根因**：脚本在 `finally` 里释放 `_lock_slotN.lock`；强杀主进程时 finally 不执行，锁文件残留。

**正解**：
1. `ls -la --time-style=+%H:%M:%S _lock_slot*.lock` 看时间戳。
2. 查是否还有活着的相关进程。
3. **不要盲删**：删活锁会报 `Device or resource busy`——这报错本身就是"锁是活的"天然探针。
4. 只有确认持锁进程已全 GONE 且时间戳陈旧，才 `rm -f _lock_slotN.lock`。

## 18. 高清原图 URL 返回 PNG 字节但按 .jpg 命名

**症状**：`Image.open()` 能打开（按内容识别），但文件真身是 PNG，做后续处理时格式不一致。

**根因**：豆包高清原图 URL 返回的是 PNG 字节（`cpreview` 变体），但脚本按 `.jpg` 命名保存。

**正解**：
- 做垫图用途：保留 PNG 无损更好。
- 只做审看/交付：JPEG 更省流量。
- 报告尺寸/md5 时务必说明真实格式，别只看扩展名。

## 19. 静帧先人眼挑再拿去 i2v

**症状**：带"AI生成"角标的静帧被垫图喂给视频生成，角标原样烤进成片。

**根因**：静帧阶段未处理掉角标就直接当垫图用。

**正解**：多张静帧候选里**先挑干净且人物关系正确的那张**，确认四角无"AI生成"标签后，再拿去 i2v。带角标的参考图会污染产出。

## 20. 编辑器未就绪 → 注入静默失败还发了空消息

**症状**：冷账号刚导航到 `/chat/` 时，注入返回 `SET_LEN=0`，脚本仍点了发送——白跑一轮（对话里多一条空消息，无视频/无图）。

**根因**：TipTap 编辑器尚未挂上 DOM，注入命令无法作用于不存在的编辑器。

**正解**（铁律三步）：
1. 点"视频生成"后轮询编辑器就绪（最多 10 次×2s）。
2. 注入后校验 `SET_LEN>0`，为 0 就重试（×5，间隔 3s）。
3. 仍为 0 **就不要发送**，把该镜标记待重投。

## 21. 有的账号首页根本没有"视频生成"入口

**症状**：按钮选择器找不到"视频生成"按钮；`NO_VIDEO_BTN`。

**根因**：个别账号或偶发情况下，豆包首页不显示"视频生成"入口。

**正解**：
1. 按钮选择器放宽：`button,div,span,a` + innerText 归一化后等于或以"视频生成"开头、取最小元素。
2. 点不到先 `Page.navigate https://www.doubao.com/chat/` 重试一次。
3. 仍点不到就**换号**——把该镜改派给已验证有入口的号，别死磕。
4. 开工前逐号位先探一遍（`doubao_cli.py check <n>` 后确认「视频生成」入口存在），别等投料时才发现。

## 22. 抽帧差分误报"跳切"

**症状**：一镜到底的视频被判"有 2 处硬切"。

**根因**：帧序错乱（见第 13 条）或抽帧数不足导致差分出现假尖峰。

**正解**：抽帧一律 `%03d`；判"有无跳切"前先自检帧序单调。引擎会"续拍跑偏"（如前 6.3s 箭钉门板，6.5s 起切成走路镜头）是真实存在的，下载后必做帧间差扫描定位真实画面切换点。

## 23. 垫图接管构图/服装/头盔/兵器

**症状**：用定妆图垫图时，模型把参考图的服装/兵器/头盔一起抄下来，即使提示词里写了不同的造型。

**根因**：模型把参考图的整体造型一起抄下来，不只锁脸。

**正解**：垫图提示词**第一段必须是参考图使用说明**，句式固定：
> "只参考这张参考图中人物的**面部特征**（五官、族属长相、年龄感）与**身体比例**；**服装、头盔、兵器、发式一律按下面的文字描述重新设计，不要沿用参考图里的服装与兵器**。"

漏写这段 → 出图造型＝参考图造型，文字描述里怎么写都不生效。

## 24. 台词漏写 = 出片没人声

**症状**：视频生成出来没有台词配音，只有环境音。

**根因**：音画同步引擎按提示词出人声，不写台词原文就不说。"谁在说"但没有"说什么"→ 模型自编台词或干脆不念。

**正解**：凡是有对白的镜头，提示词必须带**引号包住的台词原文**。句式：
> 角色名（性别/年龄/音色质感/情绪/语速）："台词原文。"

多角色对白可放在同一条提示词里，模型按"角色名（音色描述）"自动分配声线。

---

## 25. 相邻镜画面雷同是隐性坑

**症状**：两条不同镜的投料（同人物同场景）产出画面高度相似（同机位同景别），拼进成片后像同一镜头重播。

**根因**：提示词相似度过高，模型复用了相同的构图/景别/机位。

**正解**：投料前横向比对两条提示词，相似度高的当场改；提示词里锁死差异化维度（景别/机位高度/朝向/前景遮挡/动作阶段）至少差两项。

---

## 26. 保守约束把镜头拍成"会动的图片"

**症状**：为防走形写"极轻微呼吸式微动/不推不摇不甩" → 模型交出一条 10 秒几乎静止的片。

**根因**：模型取最省事的解——不动就不会错。

**正解**：约束要写成**正面、可执行的表演动词**（睁眼/转头/肩被压沉/嘴唇开合并说出台词），并明确**允许的运动范围**（可以移入画、可以前倾，只锁"不起身、不重叠"）；不要用"轻微/极小/几乎不动"去描述你希望发生的表演。

## 27. 多轮连锁修图不要并行

**症状**：两轮编辑并行跑，得到两条互不相容的分支，无法合并。

**根因**：每轮编辑只改一处，下一轮必须拿上一轮的输出当底片。

**正解**：多版并行只在**同一轮内**做（一轮出 4 版选 1 版）；轮与轮之间串行推进。选版三项都过才可用：①目标区改得干净 ②人物区改动最小 ③背景无崩坏。

## 28. 【跨机器头号坑】PYTHONUTF8=1 + 中文 Windows → 收尾静默失效

**症状**：号位起得来、出图出片都正常，但 `down` **杀不掉进程**。日志里飘一段 `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xb3`，
进程却以返回码 0 正常退出——**看起来像成功，实际浏览器还在占内存**。

**根因**：现代 Python 环境常设 `PYTHONUTF8=1`（很多环境如此）。此时 `subprocess.run(..., text=True)` 按 **UTF-8** 解码，
而中文 Windows 的 `powershell` / `taskkill` 输出是 **GBK**（0xb3 就是 GBK 里的字）。解码在 `subprocess` 的 reader 线程里抛异常——
线程异常只往 stderr 打一份 traceback，**不会中断主流程**，于是 `except Exception: pass` 把失败吞掉，函数返回"杀 0 个进程"。

**正解**：所有会读输出的 `subprocess.run` 必须显式写死解码兜底，不要依赖 `text=True` 的默认编码：

```python
subprocess.run(cmd, capture_output=True, text=True,
               encoding='utf-8', errors='replace', timeout=25)
```

**验收法**（不验这步等于没修）：起号位 → `down` → ① 返回码 0；② stderr 里**没有** `UnicodeDecodeError` / `_readerthread`；
③ CDP 端口已释放（裸 socket 连不上）；④ 系统的 chrome.exe 进程数回到起号位之前的数字。

## 29. 【自检坑】改完代码验证时，`__pycache__` 的旧字节码会把 ImportError 盖住

**症状**：刚把 A 文件改成有问题的样子，跑 B 却"成功"了——因为 "改" 这个动作根本没进字节码，
Python 复用 `__pycache__` 里那一份旧编译产物，掩盖了真实的导入错误。

**正解**：任何"改完再验"的环节，验证前先清 `__pycache__`，或全程带 `PYTHONDONTWRITEBYTECODE=1`：

```bash
find <dir> -name __pycache__ -type d -prune -exec rm -rf {} +     # 或
export PYTHONDONTWRITEBYTECODE=1
```

**推论**：子代理/协作者报"已验证通过"时，必须**自己清缓存再跑一遍**。只看对方的输出文本，等于没验。

## 30. 【架构坑】两套浏览器启动器 → 收尾漏杀

**症状**：`down` 报 `killed=1`，但浏览器还活着；或某些号位关得掉、某些关不掉。

**根因**：多个模块各自写了一份"启动 Chrome"的代码（`subprocess.Popen(--user-data-dir=...)`），
**各自约定不同的 pidfile 路径**。收尾逻辑优先读 pidfile，读的是 A 模块的路径，而进程是 B 模块起的、
pidfile 写在别处 → 找不到 → 只能靠"命令行含号位目录"兜底匹配。一旦某份启动器改动了
`--user-data-dir` 命名规则，兜底也失效，进程就永久泄漏。

**正解**：**启动/关闭/探活只能有一处实现**（本包是 `doubao_core.up/down/alive`）。
其它模块一律 `from doubao_core import up` 调用，禁止自带启动器。
验收法：`grep -c "subprocess.Popen"` 扫全包，除底座外应为 **0**。

**推广**：任何"资源生命周期"（进程/端口/临时文件/子代理）都要有唯一的管理入口。
多入口 = 迟早漂移 = 泄漏。

## 31. 【协作坑】并行产出模块时，接口契约会各自漂移

**症状**：几个模块单看都能编译、`--help` 都正常，合在一起跑就 `ImportError` / `TypeError`。

**根因**：多路并行开工时没有冻结接口。实测踩到三种漂移：
① 底座把 `up(n)/alive(n)` 写成 `up(port)/alive(port)`（号位号 vs 端口号，同名不同义）；
② `log()` 有的地方单参、有的地方双参；
③ 同一份文件被前后两个执行者按不同契约重写。

**正解**：派活之前**先把跨模块接口冻成清单**（函数名、参数个数与含义、返回值、错误形态），
写进任务书里逐条抄给每一路；收口时用一次"全模块 import + 真跑主路径"做联合验收——
单模块 `--help` 通过 **不等于** 集成通过。
