# 豆包多账号池 · 出图/批量出图工作流

> 出图/批量出图的完整细节，从新对话隔离到验收。

---

## 一、新对话隔离

1. **每镜必须开新对话**：投喂前导航到 `https://www.doubao.com/chat/` 新建对话。
2. **不做这步会把上一个角色的上下文带进下一条**（如少女出成成年男性）。
3. 豆包没有跨对话记忆——一致性 100% 靠喂料包三件套（同一垫图 + 逐字特征块 + 同场景调色描述），与哪个窗口/账号无关。
4. 每镜开新对话反而防上下文污染。
5. `fresh_chat(n)`：导航回 `/chat/` 并轮询等编辑器就绪。

---

## 二、提示词结构

### 2.1 角色定妆展板提示词（8 段结构）

1. **【画面质感·最重要】** 强调"真实拍摄的电影剧照，不是动画/插画/CG"+ 皮肤纹理、布料纤维、浅景深、胶片颗粒。
2. **【年代与地域】** 如 1937 年广州西关（或对应年代）。
3. **【人物定位·决定服装档次】** 社会身份 → 决定料子与配色。
4. **【服装】** 发型/上装/下装/配饰/配色 逐项列，**要具体到盘扣、挽袖、磨损**。
5. **【排版】** 上排 3 格三视图（正面/侧面/背面，同身高同服装）+ 下排 5 格（4 情绪 + 1 手部物证）。
6. **【硬性要求】** 八格同一张脸同一套服装；**写明该角色的识别锚点并要求每格可见**；无文字；手指不畸形。
7. **【光影】** 指定主光源方向与冷暖关系，明确"不要平光、不要棚拍柔光"。
8. **【背景】** 轻微虚化 + 环境元素清单 + "背景要虚，不能抢主体"。

### 2.2 通用提示词尾部硬约束（每条必加）

```
不得出现任何文字、字母、数字、印章、题字、Logo、角标、UI 元素、人名条、字幕条、签名。
画面里不要出现第二个人（除非提示词明确要求多人），不要出现现代物件。
```

### 2.3 提示词格式规则

- 纯中文自然句 + 全角标点。
- 不用 Markdown 符号 / 【】 / 编号 / emoji。
- 参考图用"第一张""第二张"指代。
- 视频镜提示词五段结构：规格与风格 → 画面按秒 → 台词逐字 → 声音（音效+配乐） → 禁止项。

## 三、垫图规则

1. 一镜只喂该镜出场角色，不混图。
2. 最多两张垫图（角色定妆 + 场景/道具），不塞拼图。
3. 垫图提示词第一段**必须是参考图使用说明**（见 pitfalls.md 第 23 条）。
4. 场景/道具类镜头：宁可不传垫图用纯文字描述，避免垫图接管构图。
5. 静帧先人眼挑再拿去 i2v——确认四角无"AI生成"角标。

---

## 四、高清原图取法

1. 生成图在 DOM 里是 `img[src*='rc_gen_image']`。
2. 取路径里带 `cpreview` 的高清变体 = **2848×1600 原图**（带 `cthumb` 的缩略变体只有 384×216，不能当垫图）。
3. 筛选条件：`naturalWidth>2000`（缩略图 ≈490px）；单文件过小（<20KB）跳过。
4. 同一 md5 出现在不同文件名下 = 抓到重复图，整批不可信。
5. 落盘原子性：先写 `<目标>.tmp` 再 `os.replace`。

## 五、批量 spec 格式与结果 json 结构

### 5.1 Spec 格式（每条资产一行 JSONL）

```json
{"id":"LQ_front","kind":"char","name":"凌乾","view":"正面全身","prompt":"…"}
```

- `id` 命名：角色 `<简写>_front` / `<简写>_face`；场景 `SC_<拼音>`；道具 `PROP_<拼音>`。
- 落盘文件名即 `<id>_01.jpg`，回头垫图直接按 id 找。
- 重抽时**先删旧图再投**，否则新旧混在一个目录里分不清哪张是修正版。

### 5.2 Result JSON 结构

```json
{
  "asset_id": {
    "slot": 1,
    "name": "角色名",
    "files": [{"path": "raw/LQ_front_01.jpg", "kb": 1234}],
    "gen": "2026-09-12T10:30:00"
  }
}
```

### 5.3 产物验收三件套（缺一不算成功）

1. 文件存在。
2. 体积 >1MB。
3. PIL 打印宽高（横屏定妆/场景/道具图应为 **2848×1600**）。
   - 宽高或体积不符 = 画幅/构图不对，按失败处理重出。
   - 画面美感不在脚本层判——那由主脑看。

## 六、并发上限与错峰参数

1. 每号位一线程，从 `queue.Queue` 领任务，互不干扰（独立 CDP 端口）。
2. 号间 sleep ≥3 秒错开投喂。
3. 提交后固定等 5 分钟再回来看结果，禁秒级轮询。
4. 实际安全并发 6–10 个号位。
5. 每个 slot 一个锁文件（`_lock_slot<N>.lock`，`O_CREAT|O_EXCL` 抢占，mtime 超 20 分钟视为陈旧锁自动清）。
6. **多批次并发是常态，不锁必踩**：后到的投喂会把前一批的取图窗口搅乱。

## 七、验收流程

### 7.1 基线闸（取图前必须过）

1. 投喂前数 `img[src*='rc_gen_image']` 数量记基线。
2. 轮询到"正在生成"消失 → 复读数量**必须 > 基线**。
3. 再等 8–10 秒复读一次（等这一轮出齐）。
4. 数量没增长 = 本轮无新图，**报 FAIL 并终止**。

### 7.2 md5 去重

```bash
md5sum <产出目录>/*.jpg | awk '{print $1}' | sort | uniq -d
```

- 出现重复 = 整批不可信。
- 不同文件名 md5 相同 = 静默失效（见 pitfalls.md 第 5 条）。

### 7.3 尺寸核对

| 类型 | 预期尺寸 | 异常处理 |
|:--|:--|:--|
| 横屏定妆/场景/道具 | 2848×1600 | 不符 = 画幅错，重出 |
| 竖屏素材 | 1600×2848 | 不符 = 画幅错，重出 |
| 文件体积 | >1MB | <20KB = 缩略图，未点开高清 |

### 7.4 双引擎质检（出图后）

固定五项问答（**固定问法才会得到可比的答案**）：

```
这是AI短剧的角色/场景定妆设定图。只回答以下五项，每项一行，不要展开：
1.画面里有几个人（0/1/多人）
2.性别（男/女/无人物）
3.大约年龄
4.画面里是否出现任何文字（有/无，如有请写出来）
5.是否为全身站姿（是/否/不适用）
```

- 引擎：`glm-4v-flash`（智谱，免费）+ `qwen3-vl-flash`（百炼，免费）。
- 两引擎同判才算数；不一致 = 降级人眼。
- 第 4 项任一报出文字 = 直接废图重抽。
- **可信度分布**：性别/人数/年龄/有无文字 → 可信；服装/风格类细节 → 不可信，禁止据此判死。

## 八、开拍卡口

1. 缺料先补料。
2. 先只打 3 镜样片（开局异常镜/人物出场镜/高光镜）给使用者验。
3. 点头才铺满一集。
4. 未验样片就全量投料 = 返工一整集的额度与时间。

## 十、重投纪律

1. 对 N 个槽一一标记"成功/NO_LINE/没跑"。
2. **只补后两类，绝不整批重跑**（整批重跑 = 白烧额度 + 覆盖已成功产物）。
3. 重投写**新的 spec 文件**（`_spec_fixN+1.json`），不复用上一批的 spec。

---

## 十一、开工前资产库校验

`01_资产库/` 里可能躺着**上一个项目**的图。开工前做一次交集校验：

```bash
# 用本剧主要角色名 grep，命中 0 就是零交集
grep -rl "角色名1\|角色名2" 01_资产库 2>/dev/null | wc -l
```

**零交集 = 这批资产与本剧无关，本剧定妆完成度按 0 计。** 别把它们的张数当"已完成量"报进度，也别拿它们垫图。

---

## 十二、归类三步法（豆包文件名 ≠ 镜号）

1. **md5 去重**（同文件重复下载常见）。
2. **用视觉模型看中间帧**，报候选镜头清单（含每镜目标画面一句话）让模型选。
3. 不匹配任何候选 → 描述实际内容，Agent 决定降级当备胎或废弃。
