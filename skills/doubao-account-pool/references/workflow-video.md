# 豆包多实例工作台 · 出视频工作流

> 十二步链路、确认卡、防误购保护、免费档 vs 付费档、用量机制、抓链、规格核对。

---

## 一、十二步链路（逐步说明）

| 步骤 | 操作 | 说明 |
|:--|:--|:--|
| 1 | 选实例 | 从实例池中选一个 FREE 号（当日基础用量还有的号）。探针结果从 `_vid_pool_status.json` 读取。 |
| 2 | 新建对话 | 导航到 `https://www.doubao.com/chat/`，等页面加载完（URL 含 `/chat/`）再操作。**必须在聊天页操作，`/chat/video` 是死链。** |
| 3 | 点"视频生成" | 用 CDP `Input.dispatchMouseEvent` 点底部工具条"视频生成"芯片。JS `.click()` 对 React 组件无效。 |
| 4 | 选比例 | 16:9（横屏剧）或 9:16（竖屏投放），全片统一，先定死再开拍。 |
| 5 | 选时长 | 默认 10s（实测会出 10.04s，引擎忽略精确时长请求）。投料就按 10 秒写节拍。 |
| 6 | 上传垫图 | `input[type=file] accept=".jpg,.png,.jpeg,.webp"` → 只吃图片，不能传视频。最多两张（角色定妆 + 场景/道具）。 |
| 7 | 注入提示词 | `div.editor.commands.setContent(text)` 同步 TipTap 内部状态，校验 `SET_LEN>0`。 |
| 8 | 检查确认卡 | 读确认卡文本，判 FREE/PAID（见第三节防误购保护关键词表）。 |
| 9 | 发送 | CDP 真点击发送按钮。 |
| 10 | 等 5 分钟 | **稳定性保护铁律：禁秒级轮询**。提交后固定等 5 分钟再回来看结果。 |
| 11 | 抓视频链接 | 视频没有下载入口、没有直链暴露。从 `performance.getEntriesByType('resource')` 里取含 `/video/` 或 `mp4` 的 URL。 |
| 12 | 下载 + 规格核对 | curl 下载，`ffprobe`/PyAV 核对规格：必须有音轨（音画同出确认）。 |

## 二、确认卡长什么样

确认卡是豆包在提交前弹出的确认对话框，包含以下信息：

```
模型：Seedance 2.0 Mini
时长：10 秒
比例：16:9
消耗：本次消耗基础用量 / 本次将消耗付费用量
```

**判据**：
- 确认卡里出现"基础用量"→ FREE，可继续。
- 确认卡里出现"付费用量"→ PAID，停手并报给使用者。
- 确认卡里出现"订阅"/"专业版"/"开通会员"→ 付费墙，Esc + 离开。

## 三、防误购保护关键词表

任何一条命中 → 停手并报给使用者，绝不自动确认：

| 关键词 | 含义 |
|:--|:--|
| "付费用量" | 当日基础用量已用完，本次扣费 |
| "订阅" | 需要付费订阅 |
| "专业版" | 需要升级到专业版 |
| "开通会员" | 需要开通会员 |
| "立即升级" | 付费墙弹窗 |
| "继续升级" | 付费墙弹窗 |
| "标准 ¥68月" | 标准档月费 |
| "加强" | 高级档位 |
| "高级" | 高级档位 |
| "专业" | 专业档位 |
| "5 倍消耗" | Seedance 2.5 的消耗倍数 |
| "2 倍消耗" | Seedance 2.0 的消耗倍数 |

## 四、免费档 vs 付费档实测对比

### 4.1 模型档位

| 档位 | 消耗倍数 | 可用性 |
|:--|:--|:--|
| Seedance 2.0 Mini | 1 倍（免费档默认） | 免费号可用 |
| Seedance 2.0 Fast | — | 快速出片 |
| Seedance 2.0 | 2 倍 | 需订阅 |
| Seedance 2.5 | 5 倍 | 需订阅 |

### 4.2 同提示词同垫图实测对比结论

**免费 Mini 不输付费档**：码率/亮度/运动量/音量更好。

| 维度 | 免费 Mini | 付费档 |
|:--|:--|:--|
| 码率 | 更高 | 较低 |
| 亮度 | 更亮 | 偏暗 |
| 运动量 | 更丰富 | 较保守 |
| 音量 | 更大 | 较小 |
| 画质 | 可用 | 略好但差距不大 |

**结论：默认走免费档，用付费档前先报备。**

## 五、用量机制实测

### 5.1 基础用量

- **基础用量约 3 条/号/天**，远少于官方宣称的 10 条/天。
- 5 秒档 ≈ 50 秒，10 秒档 ≈ 100 秒。
- 用量按 Mini 计（每号约 10 次 × 10 秒）→ 实际远低于此。

### 5.2 耗尽表现

- **静默拒答**：提示词发出、零回复、不出确认卡、不报错。
- 页面文本写着"今日视频生成基础用量已用完"或"抱歉，我无法生成你要求的内容"。
- **不要误判成脚本坏了**（见 pitfalls.md 第 6 条）。

### 5.3 统计窗口

- **近 7 天滚动池，非每日重置**。
- 即：今天用完 3 条，明天不一定恢复 3 条——要看 7 天内总共用了多少。
- 实例池状态与探测结果都要落盘（哪个号 free/paid/out、什么时候探的）。

### 5.4 赠送套餐到期日

- 赠送套餐有到期日，**必须卡在生产排期之前**。
- 到期后该号降级为无用量，探针探测结果标记为 OUT。
- 生产排期前一周检查所有实例的套餐到期日。

### 5.5 探针法（零消耗探测用量）

1. 进视频模式 → 上传参考图 → 注入提示词 → 发送。
2. 用量只在跟引擎确认那一下消耗，发送本身不扣用量。
3. 用探针逐号各试一次，读确认卡文本判 FREE/PAID：
   - 出"确认，开始生成"卡 = 还有基础用量。
   - 回"今日视频生成基础用量已用完，本次将消耗付费用量" = 只剩付费。
   - 回"今日次数用完 / 开通会员" = 无用量。
4. 一次扫描省掉一整轮白跑的片子。

## 六、抓链与重抓

### 6.1 视频链接特点

- **没有下载入口、没有直链暴露**。
- 视频消息是 `div.block-video-*` 容器。
- 封面是短链 `https://aka.doubaocdn.com/s/xxx`（直接 curl 会 404，必须走浏览器上下文）。
- 视频绑在各自独立会话里：每个镜 = 一个会话。

### 6.2 抓取流程

1. 侧边栏会话列表：`a[href*='/chat/']` → `(cid, title)`。
2. **默认只渲染最近若干条，必须先强制滚动侧边栏**（找 `width 120–430 && scrollHeight > clientHeight+120` 的容器 `scrollTop = scrollHeight`，滚 5-7 次）。
3. 按标题关键词过滤，滤掉私人旧聊天。
4. 逐个 `Page.navigate` 到 `https://www.doubao.com/chat/<cid>` → 等 9-11 秒 → 向下滚 → 点击 `div[class*='block-video']` 容器（点封面中心）→ 等 6 秒 → 播放层里取 `video` 元素 src / `performance.getEntriesByType('resource')` 里含 `/video/` 或 `mp4` 的 URL。
5. 下载用 curl（`-sL --max-time 240 --retry 2`，带 `Referer: https://www.doubao.com/`）。
6. 失败兜底：CDP `Browser.setDownloadBehavior` 让浏览器自己下。

### 6.3 落盘命名

- `_harvest/slot<N>_<cid>.mp4`（**用 cid 不用序号**，序号会随滚动变化）。

### 6.4 重抓

- 如果下载失败，用 cid 重试（不是序号）。
- 已下载的 cid 跳过，续跑未下载的。

## 七、规格核对

### 7.1 必须有音轨

每条下载的视频必须有音轨（音画同出确认）：

```bash
ffprobe -i video.mp4 2>&1 | grep -E "Duration|Stream"
```

预期输出：
```
Duration: 00:00:10.04
Stream #0:0: Video: h264, yuv420p, 1280x720, 24fps
Stream #0:1: Audio: aac, 44100Hz, stereo
```

- 无音轨 = 生成失败，重投。
- PyAV 替代方案：
  ```python
  import av
  container = av.open('video.mp4')
  has_audio = any(s.type == 'audio' for s in container.streams)
  container.close()
  ```

### 7.2 规格标准

| 维度 | 标准值 | 异常处理 |
|:--|:--|:--|
| 分辨率 | 1280×720（横屏）/ 720×1280（竖屏） | 不符 = 画幅错 |
| 帧率 | 24fps | 不符 = 生成异常 |
| 时长 | ~10.04s（引擎会出 10.04s） | 不符 = 生成异常 |
| 音轨 | AAC 立体声 44100Hz | 无音轨 = 生成失败 |
| 文件体积 | >1MB | <500KB = 可能是封面图 |

## 八、台词与音画同步

### 8.1 台词必须写进提示词

- 提示词里没写台词原文 → 模型自编词或不念。
- 凡有对白的镜头，提示词必须带**引号包住的台词原文**。

### 8.2 正确写法

```
苏明澜（年轻女子，二十出头，声线清冷平稳、一字一顿、压着怒气）："鞋上的泥，是哪个河滩踩回来的。"
```

- 角色名 +（性别/年龄/音色质感/情绪/语速）+ 冒号 + 引号内台词原文。
- 不说话的当场次写清"只有沙哑喘息气声，不成句、不给他配说话声"。
- 补声音边界："全片只有上面这一句人声对白，不要旁白、不要配乐、不要其他说话声"。

### 8.3 音频参考能力边界

- 豆包网页版视频生成：**只收图片**，没有音频/音色上传位。
- 音色只能靠提示词文字描述。
- 想做"声音定妆"（固定音色库）要走即梦 Seedance 2.0（支持 `@音频1` 引用 mp3/wav）。

## 九、引擎行为实测

### 9.1 时长需求被无视

- 投料写 5s/6s，产出全是 1280×720 / 10.04s / AAC 立体声。
- **投料就按 10 秒写节拍**，多余部分剪辑时裁掉。

### 9.2 引擎会"续拍跑偏"

- 投料"箭钉门板特写（3s）"，前 6.3 秒确实是箭钉门板，6.5 秒起引擎自主切成走路镜头。
- **下载后必做帧间差扫描**定位真实画面切换点，按需要的段落裁切。

### 9.3 一镜一句台词才稳

- 实测 10 秒片里准确吐出一句中文台词。
- 多句长台词**不要塞进一镜**，拆镜分摊。

### 9.4 横屏是模型的"母语"

- 训练数据以电影级横屏为主。
- 9:16 是稀缺比例，容易构图失衡、人物被挤。
- 横屏裁竖屏可行、竖屏放横屏必崩。

## 十、抽帧质检

### 10.1 抽帧命令

```bash
ffmpeg -i video.mp4 -vf "fps=2,scale=512:-1" -frames:v 4 shots/sNN/frame_%d.jpg
```

- 后半段细查用 `fps=2 -frames:v 8`。
- Windows 下 ffmpeg 路径必须用 `C:/` 正斜杠原生格式（MSYS 路径对原生 exe 不转换）。

### 10.2 质检判定分级

| 级别 | 标准 | 处理 |
|:--|:--|:--|
| 直接过审 | 要素全对无畸形 | 归档 |
| 带瑕疵过审 | 快切镜头里看不出的小瑕疵 | 归档+记瑕疵 |
| 降级备用 | 不合格但画面质量好 | 当过渡镜/剪短用 |
| 意外收获收编 | 生成与设定不符但氛围佳 | 收为闪回插入镜 |
| 重抽 | 叙事功能缺失且无降级空间 | 改一个变量重抽 |
| 顺势改剧本 | AI 稳定偏差但叙事等价 | 改剧本不改片 |

### 10.3 抽帧必须用 `%03d` 零填充

- 用 `%02d` 会导致文件名长度不一致 → 字典序 ≠ 数字序 → 帧序错乱 → 差分误报假尖峰。
