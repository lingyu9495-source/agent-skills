# 豆包多实例工作台 · 稳定性纪律

> 不可协商的铁律，违反 = 实例不可用。全文可执行条文，不写叙事。

---

## 一、提交后固定等待

1. **提交后固定等 5 分钟**再回来看结果。
2. 禁止秒级轮询、禁止反复刷新页面、禁止连续切换对话。
3. 5 秒/10 秒的生成任务实际耗时约 1–5 分钟，等 5 分钟是安全余量。
4. 等待期不截屏、不读 DOM、不发任何 CDP 命令；状态变化才查。

---

## 二、一次只推进一个动作

5. 一次只推进一个动作，动作之间留停顿（≥2 秒），不要连点。
6. 批量投喂时号间 sleep ≥3 秒错开，不要 5 个号同时狂点。

---

## 三、同一动作连败 3 次停止

7. 同一动作连续失败 3 次 → **立即停手**，不要硬试。
8. 硬试 = 稳定性保护加速器。停手后记录失败原因，排查后重试。

---

## 四、多号错峰

9. 多实例轮转时错开节奏，不要多个号同时操作。
10. 实际安全并发 6–10 个实例（按内存和稳定性保护边界定）。
11. 同 IP 多实例同时操作会触发豆包的异常行为检测。

---

## 五、只走主路径不乱逛

12. 能不导航就不导航，能读 DOM 就不截图。
13. 只访问必须的页面路径：`/chat/`（新对话）和 `/chat/<cid>`（指定会话）。
14. 不刷不必要的页面，不点无关按钮，不探索新功能。
15. 点击"视频生成"前确认按钮可见，点不到先重试一次，仍点不到就换号。

---

## 六、防误购保护优先于一切

16. 遇到"是否消耗付费用量"弹窗 → **一律停手并报给使用者**，绝不自动确认。
17. 遇到"开通会员"/"立即升级"/"继续升级" → **一律 Esc + 离开**，绝不停留。
18. 防误购保护关键词表（任何一条命中 → 停手）：
    - "付费用量"
    - "订阅"
    - "专业版"
    - "开通会员"
    - "立即升级"
    - "继续升级"
    - "标准 ¥68月"
    - "加强"
    - "高级"
    - "专业"
19. 确认卡里出现上述任何关键词 → 该号标记为 PAID，改派给 FREE 号。
20. **闸门要"每镜每号"都过**，不是开工时过一次——同一号连投数镜后用量可能中途耗尽。

---

## 七、只杀本实例进程

21. 脚本只用 pidfile 杀自己的进程树，**永不** `taskkill /IM chrome.exe`。
22. 不要动别人已开的固定实例端口（不属本实例池的 CDP 端口一律不碰）；桌面 Chrome/Edge 永不 taskkill。
23. 任务结束必须跑 `doubao_cli.py down --all`（不管成功失败都要跑；异常也要 try/finally 收尾）。
24. 回收兜底：自己挂一个定时任务（如每 30 分钟一次）——CDP 端口无 ESTABLISHED 连接 ≥20 分钟即判定"没人用"自动关（只杀进程，user-data-dir 登录态保留）。兜底是保险，不是替你记事。

---

## 八、不开用户自己的浏览器不抢焦点

25. 起始命令：`--no-first-run --no-default-browser-check --disable-extensions --disable-default-apps --disable-popup-blocking --disable-translate --disable-background-timer-throttling --disable-renderer-backgrounding --disable-backgrounding-occluded-windows --disable-ipc-flooding-protection`
26. 窗口位置：`--window-position=-3000,-3000`（挪到屏幕外，不弹窗、不抢使用者焦点）。
27. **不要改用户默认浏览器设置**。
28. 实例窗口不要遮挡用户的桌面操作。
29. 如果需要让实例窗口可见（如注入前），用 `doubao_cli.py visible <n>` 恢复，操作完再挪回去。

---

## 九、其他稳定性保护细节

30. 单实例 ≈ 8 个 chrome 进程 ≈ 700MB 常驻；实例上限按机器可用内存估算（本包默认 `max_slot=20`），实际安全并发 6–10。
31. 按需启停：跑完即 `down`（不常驻占资源）。
32. 扩容新实例：`doubao_cli.py up <n>` → `doubao_cli.py login <n>` 弹登录出码 → 把 PNG 发给要扫码的人扫 → `doubao_cli.py status --deep` 确认 logged=true。
33. 登录成功判据：URL 含 `from_login=1` 且页面已无"登录"按钮。
34. 登录弹窗里"已阅读并同意"的勾选框用 DOM 定位点，别用死坐标（坐标会因弹窗布局变化而点到遮罩、把弹窗点没）。

---

## 十、标准作业循环（单镜）

```
填提示词 → 提交 → 【等 5 分钟】 → 看一眼生成结果
  → 成功：下载 → 落盘 → 抽帧质检 → 下一镜
  → 失败：记录原因，等 5 分钟再试 → 连败 3 次停手
```

---

## 十一、稳定性保护误伤记录与解法

| 触发词/场景 | 现象 | 解法 |
|:--|:--|:--|
| `1厘米旧疤` / `黑眼圈` | 触发侵权检测拒生成（用量不扣） | 人物提示词只写"严格保持参考图面容"，疤痕靠垫图锁 |
| `压抑` 单独出现 | 可能被拦截 | 统一用"安静克制/忧虑/凝重"替代 |
| `屠城` | 内容安全拒答 | 改写为"破城"/"兵祸"/"战争大场面" |
| `砍杀` / `追砍` | 内容安全拒答 | 改写为"紧追不舍地逼向"/"兵器高举未触及任何人身" |
| 暴力词 + 族裔特征词同现 | 命中率最高 | 去掉族裔标签，只留装束视觉特征 |
| 负面清单含`血/尸/砍` | 加重命中 | 改写成安全正向表述："不出现伤口与倒卧的人形" |
