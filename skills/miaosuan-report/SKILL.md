# 🏛️ 庙算报告产出流水线

> 定位：这是**执行层**。判断逻辑（五事七计/多维交叉/多AI交叉）见本文及配套方法论，本 skill 是把「研判需求 → 完整可交付报告 → 沉淀 → 交付」整条链跑通，**每一步都标准化**，以后不用临时拼。

## 触发

当用户说：**研判 / 庙算 / 要不要做X / 值不值 / 入局报告 / 给X做个判断 / 这事能搞吗** → 自动加载本 skill。

## 完整流水线（强制走完，不许跳步）

```
研判需求 → ① 定研判对象&层次 → ② 联网多AI交叉验证 → ③ 三线评分 → ④ 报告撰写
        → ⑤ 反思+审查修正 → ⑥ 沉淀Obsidian → ⑦ 飞书聊天框交付 → ⑧ 复盘是否要淬炼回流
```

---

## Step 0 · 定研判对象 & 策略层次（30秒，先做这个）

- 研判对象是啥？一句话说清（如"入局一人公司"、"接这个银行客户"、"做这个AI产品"）
- 定孙子策略层次：
  - 🥇 伐谋（卖认知/信息差）→ 你最擅长
  - 🥈 伐交（用人脉/合作）→ 第二优势
  - 🥉 伐兵（投钱投人硬打）→ 谨慎
  - 🏔️ 攻城（拼价格/规模）→ **避开**

**示例（人公司入局）**：伐谋 → 卖"AI员工+托管"认知；伐交 → 收编标准化SaaS做渠道；攻城 → 避。

---

## Step 1 · 联网多AI交叉验证（必须，不猜市场）

用 web_search / 多源搜索抓**当前数据**而非拍脑袋。至少抓 3 组关键信号：

| 信号 | 抓什么 | 示例（OPC） |
|:----|:----|:----|
| 成本锚点 | 替代成本 vs 人力成本 | 数字员工3-5万/年 vs 人力5-8万/年 |
| 渗透/增速 | 市场渗透率、CAGR、风口期 | 30%部署、预计两年翻倍 |
| 竞争态势 | 谁在卷、你打不打得过 | 标准化SaaS下沉、大厂生态 |

> ⚠️ 铁律：**数据必须是真实抓取的**，来源URL标注在报告里。绝不编造市场数字。

## Step 3 · 报告撰写（用标准模板）

一份合格庙算报告 = **8 段**：

```markdown
# 🏛️ 庙算报告：{研判对象}

## 一、核心结论（30秒看版）
一句话结论 + 庙算总账分数 + 判定档

## 二、市场速查
关键成本锚点 + 增速/风口判定（当前数据，带来源 URL）

## 三、五事七计分析
道/天/地/将/法 逐项，各带判定分

## 四、三线评分总表
六维表格 + 庙算总账

## 五、风险与备选
至少2条对症风险+对策；备选路线（降级/升级各1）

## 六、建议第一步行动
现在能落地的一件事（具体、可执行）

## 七、审查记录
反思+审查修正+达标声明（报告铁律）
```

## Step 4 · 反思 + 审查修正（报告铁律，强制）

出稿前过 3 问：
1. **反思** 数据完整吗？来源可靠吗？有没有过度推断？
2. **审查** 结论与证据匹配吗？有没有漏反方观点？
3. **修正** 发现问题立即改，改完复查一遍。

> 宁晚交不错交。审查不通过绝不出。

### ⚠️ 关键参数实测铁律（2026-09-13 庙算后验淬炼，强制）

凡决定项目生死的核心参数——**补贴标准 / 客单价 / 单位成本（人力·租金）/ 政策兑现周期 / 资金回笼节奏**——
必须**实测给出区间数字**；查不到就写明「需客户提供」并单列成必补项，**禁止写「按当地标准」「视情况而定」「依据实际」糊过去**。

> 依据：一次项目操盘指引把「补贴标准」留白，客户拿不到「这事挣不挣钱」的量化答案 → 等于把决策风险退还给本就迷茫的客户 = **假交付**。
> 判据：一份入局指引若读完仍不知道「月度盈亏平衡点在哪」，就是没写完。

---

### ⚠️ 建议与红线交叉校验铁律（2026-09-27 庙算后验淬炼，强制）

出报告前，把「建议动作清单」与「本报告/自有口径的红线清单」**交叉过一遍**：

- 任何一条建议，若其见效方式依赖**绕红线**（虚假交易/刷单/知情不报/越权代操作），一律**删掉换路**，不得因为「见效快」保留。
- 典型翻车：闲鱼破零建议里写「请朋友下一单 + 带图好评」——踩虚假交易，且与同一份报告里的「一律不碰红线」自相矛盾。
- 涉及需客户本人操作的动作，如实标注（不越界代操作）；工具采购给**可自判阈值**，不给「到时候再说」。
- 根因提醒：把 KPI（破零率/升级率）当终点，就会逼出越线动作——**指标定义不清，必然逼出错误动作**。

- 路径：`<知识库>/<项目成果>/`
- 若属**方法论/复盘类** → 放 `<知识沉淀>/` 或 `<复盘日志>/`

---

## Step 6 · 飞书聊天框交付（双输出铁律，强制）

1. **聊天框先给核心结论**（30秒看版：一句话+分数+判定档+2-3条建议）——用户手机直接看，结论先行。
2. **MEDIA: 附件发完整报告**——用户手机点开能看全。
3. 不要只存知识库不发飞书（用户看不到=没交付）。

**简短**：交付后最多提一次后续建议，用户不接话就停（沟通纪律）。
