# 决策门清单（Go / Kill / Hold / Recycle）

> 出处：Robert G. Cooper 的 Stage-Gate®（阶段门）体系——在每个阶段前设一道"门"，
> 用**明确的准则**做 Go/Kill 决策，而不是靠感觉推进。
> 本清单把它改造成**单个项目研判**用的门槛表：先定"什么算过"，再去论证。

---

## 一、门的六条通用准则（Cooper Stage-Gate 官方六准则）

| 准则 | 问什么 | 本项目怎么答（填） |
|------|--------|------------------|
| 战略契合 Strategic Fit | 这事和我们的主业/资源方向搭不搭？ | |
| 产品与竞争优势 Product & Competitive Advantage | 客户为什么买我们而不是别人？优势能维持多久？ | |
| 市场吸引力 Market Attractiveness | 市场够大、够增长、够赚钱吗？ | |
| 技术可行性 Technical Feasibility | 技术上做得到吗？我们做得出来吗？ | |
| 协同与核心能力 Synergies / Core Competencies | 能借用现有能力、渠道、供应链吗？ | |
| 财务回报与风险 Financial Reward / Risk | 赚多少、多久回本、最坏会怎样？ | |

> 六条不是打分表，是**必答清单**：任何一条答不上来，就不该获批推进。

## 二、四种决策（不只是"做/不做"）

| 决策 | 含义 | 对应动作 |
|------|------|---------|
| **Go** | 通过 | 进入下一阶段，批准资源与时间表 |
| **Kill** | 终止 | 停止投入，写明终止理由并归档（避免下次重复评估） |
| **Hold** | 暂缓 | 条件未成熟，挂在架上等（写明"等什么信号"再启动） |
| **Recycle** | 打回重做 | 方向可以，但方案/数据不够，退回上一阶段补课 |

> 实战提示：绝大多数"说不清"的项目，正确答案是 **Hold** 或 **Recycle**，而不是勉强 Go。

## 三、本项目门槛表（把"什么算过"写死）

| 维度 | 门槛（写死阈值） | 现状 | 判定 |
|------|----------------|------|------|
| 市场容量 | 目标市场 ≥ 现有产能的 1.5 倍 | | |
| 竞争壁垒 | 至少具备一项结构性优势（规模/转换成本/网络效应/资源独占/品牌） | | |
| 政策合规 | 无禁止性红线；必需审批可取得 | | |
| 单位经济 | 单件/单客户毛利为正，回收获客成本 ≤ 12 个月 | | |
| 财务回报 | 全投资 IRR ≥ 8%；回收期 ≤ 8 年；NPV > 0 | | |
| 偿债能力 | 利息备付率 ≥ 2；偿债备付率 ≥ 1.3 | | |
| 风险可控 | 前三大风险均有可执行的应对措施，且无"一旦发生就翻盘"的暴露 | | |
| 致命假设 | 全部高影响假设已验证；无已证伪项 | | |

> 把上面这张表填完，项目结论实际上就出来了——论证过程只是为这张表找证据。

## 四、Conclusion 的三种表述（不要只写"可行/不可行"）

1. **可做（Go）**：全部门槛通过 → 给出建议的投资节奏与下一步动作
2. **有条件可做（Conditional Go）**：主要门槛通过，但存在阻塞项 → 明确列出"补齐哪几项后即可推进"，并给验证计划与时间表
3. **不可做（No-Go）**：存在证伪的致命假设／财务不达标／触碰红线 → 说明是"方向不行"还是"条件不具备"（后者可改为 Hold）

**每种结论都必须附**：证据等级说明、关键假设清单、下一步该验证什么。
