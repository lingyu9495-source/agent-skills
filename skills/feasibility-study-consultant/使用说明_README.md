# 项目可行性论证教练 · 使用说明

> 给 AI 智能体（Claude/GPT/豆包/千问/DeepSeek/Hermes 等）使用的**技能（Skill）**：
> 让任何智能体都能按专业方法回答"这事**能不能做**、**值不值得做**、**怎么做才成**"。

## 一、它解决什么问题

大部分"项目可行性分析"的通病是：**问不清楚、选错方法、验证不了**。

| 通病 | 表现 | 本技能怎么治 |
|------|------|------------|
| 问不清楚 | 客户给一句"我要做个项目"，AI 就开始编市场数据 | 一页纸《项目卡》+ 三轮提问法（含六类项目的追问库），缺什么列清单、红线先问 |
| 选错方法 | 用"市场空间很大"回答"值不值得投" | 方法论库 10 个方法，按**问题类型**（能不能做／值不值／怎么选／怎么做）选 3–5 个组合 |
| 验证不了 | 结论写"客户有意向""政策支持"，没人能核 | **假设台账**：每条假设 → 影响×不确定性排序 → 验证方法 → 判据阈值 → 状态（未验证/验证中/已验证/已证伪） |
| 结论没法用 | 只写"可行/不可行" | 决策门输出 **Go / 条件 Go / No-Go**（含 Hold / Recycle），带门槛表与下一步动作 |

## 三、怎么用

### 最快的方式（3 条命令看效果）

```bash
# 1) 假设台账：先验最要命的假设
python3 scripts/assumption_ledger.py --demo --plan

# 2) 门槛评分：能不能做/值不值 → Go / 条件Go / No-Go
python3 scripts/feasibility_scorecard.py --demo

# 3) 看输入格式，换成你自己的项目
python3 scripts/feasibility_scorecard.py --print-schema
```

### 标准用法（跟着手册走）

1. **采集**：把 `templates/项目卡.md` 发给项目方填，或用 `templates/引导提问清单.md` 口头过一遍（三轮提问）
2. **判型**：确定问题类型 × 项目类型 × 研究阶段 × 读者 → 一句话判型结论
3. **选型**：查 `references/方法论库.md`，选 3–5 个方法，写下每个方法要什么数据
4. **论证**：联网尽调（先搜后写）→ 六动作（市场/竞争/单位经济/财务/风险/合规）→ 成文
5. **验证**：填 `templates/假设台账.csv` → 跑 `assumption_ledger.py` → 按优先级逐条验证
6. **结论**：填 `templates/决策门清单.md` → 跑 `feasibility_scorecard.py` → 出结论 + 下一步

### 依赖

**无。** 两个脚本只用 Python 3 标准库，无需 pip 安装任何东西。

## 四、什么样的项目适用

- **创业/新业务**：这个方向能不能做？值不值得投时间
- **企业立项**：新厂、新线、新门店、新平台，要不要批预算
- **投资研判**：收购/入股一个标的，划不划算
- **政府项目前期**：立项必要性、资金平衡、合规前置（正式可研报告按发改委大纲另出）
- **方案比选**：选址 A/B、规模大中小、自建 vs 合作 vs 并购

## 五、设计原则（为什么它不一样）

1. **门槛先定**：动笔前先写死"什么算过"（IRR 下限、回收期上限、单位经济为正、致命假设全验），避免论证沦为"为已有结论找材料"
2. **先验最要命的，不是先验最容易的**：假设按 影响×不确定性 排序，最高优先级不能跳过
3. **判据必须可核查**：不是"客户有意向"，而是"3 家头部客户签意向书，锁定 60% 库容"
4. **承认边界**：查不到的写"待验证"，证据分级 A/B/C/D，比硬编数字专业得多
5. **结论可执行**：Go / 条件 Go / No-Go（+ Hold / Recycle），每种都带下一步该验证什么
