# 客户只改了概述/某章，让整篇对齐到它（可研修订子类）

> 场景：客户把报告的第一章（概述/提要）改好了原样发回，说「其他部分匹配概述的逻辑和数据改出来」。这是「客户发来让改」里最常见也最易翻车的子类。核心是**内容一致性纪律**，不是格式配方。

## 先锁基线，再扫描，再改——顺序不能反

### 1) 锁基线：先判「有没有原版可 diff」
**两种情况，先分清再锁基线：**
- **A. 客户单独回传一份改过的概述/章节（或原版还在手）** → 用 python-docx 同时打开「客户回传版」和「自己原版」，**diff 概述部分**，精确列出客户改了哪几个字段（如总投资300亿→1000亿、工期5-8年→3-5年、地点表述、分期期数、融资工具名称、新增空间格局）。这份 diff 就是全部对齐基准。
```python
import docx
a,d = docx.Document(原版), docx.Document(客户版)
# 取双方概述段，逐段比对打印差异
```
- **B. 只收到一份「客户改过后的 docx」，没有独立原版**（最常见，如文件带回 `_4` / `_修订` 后缀）→ **没有可 diff 的参照**。此时基线**不能靠 diff 得到**，而是：①在整个文档里辨认出「客户亲手改的」那一段作为**权威章节**（通常=概述/第一章，或文件名/内容突兀改写处）；②把它当作唯一准绳；③**全文档扫描其余部分，凡与它的口径/定性/数字冲突的表述即视为「正文没跟上」**，需对齐到它。判据是「这一章是不是明显更口语/更跳动/与其余章口径不同」，而非有没有原版。别因为没有原版就卡住——客户改过的那一章本身就是基线。

### 2) 全文档扫描
把基线里每个变了的值，用程序在**整个文档（正文段落 + 所有表格单元格）**搜一遍所有出现位置，逐个判性质。别只扫概述周边的章节——总盘数字会散落在各分册报头、资金筹措、财务段、归属表里。

### 3) 三种性质，只改一种（核心红线）
同一个数字如「300亿」在报告里出现，性质截然不同：
- **① 项目/集群总盘**：`总投资约300亿`、`纳入总报告X亿汇总表`、`为整个X亿产业集群`、`总投资约300亿的重资产属性` → **要改**为基线新值。
- **② 分册/板块单册投资**：`本分册约84亿`、`本板块81亿`、`油库25.2亿+船队45亿`、`已框定136.5亿` → **不能改**，这是该板块自己的测算。
- **③ 行业市场数据**：`无人机订单300亿`、`鱼胶市场300亿`、`海水淡化290万吨`、`游客3983万人次` → **绝对不能改**，这是市场和行业数据，不是项目投资。

> 判错②③=把客户项目测算和行业数据改了，等于替客户拍数，是致命错误。用程序列出全部出现位置后，**逐一按上下文（总盘/单册/市场）分组再决定**，绝不全局替换。

### 4) 不拍数：保原值 + 强化标注
分册单册投资测算、财务IRR/NPV 等**保留原值**，只在表述上给它贴「待尽调/待测算」标签（如「二期700亿待各板块子项目单元论证后补充」）。总盘口径通过「表述+口径说明」对齐，而不是重算财务模型——这既是投行纪律，也符合「宁晚交不错交」。

### 5) 用内部自洽化解冲突，不动数字
总盘「一期300亿」vs 明细「一期290亿」看似矛盾，但若原版已有「预留约10亿元合理浮动空间」，则 290明确+10浮动=300——不用改任何一个数，只需把该节统一定性为「**一期口径**」、写明承接关系即可。**先把数字间的勾稽关系找出来，再决定要不要动数字**，别见冲突就改。

### 6) 改完做全面复核扫描
把所有「要改的总盘表述」残留、错别字（`概概述`、`依托依托` 重复）、基线字段再扫一遍，确认0残留，且**概述部分一字未动**。

## python-docx 就地改 run 的三种替换写法（保留格式）
```python
def sub_in_par(p, old, new):
    if old not in p.text: return "未找到:"+old[:25]
    for r in p.runs:              # 1) 优先单run内替换（最常见，不破坏格式）
        if old in r.text:
            r.text = r.text.replace(old, new); return "单run替换"
    # 2) 跨run: 全段重建, 继承首run格式
    full = p.text.replace(old, new)
    for r in list(p.runs): r.text = ""
    p.runs[0].text = full; return "整段重写"
```
表格单元格：`set_cell` 清空 cell 内所有 run 后赋首run；删多余行用 `t._tbl.remove(t.rows[-1]._tr)`（改期数、改行数时）。

**⚠️ 表格 cell 可能是多段落的**——cell 内 `tc.iter(qn('w:p'))` 可能不只一个 `<w:p>`（数字被拆成多 run/多段时常见，如 `1000亿` 被拆成 `10`+`00亿`）。改 cell 文本时，除了清多余 run，**还要删除首个 `<w:p>` 之外的多余段落**，否则残留空段落：
```python
def set_cell_text(tc, newtext):
    paras=[Paragraph(p, doc) for p in tc.iter(qn('w:p'))]
    if not paras: return
    first=paras[0]; runs=first.runs
    if not runs: first.add_run(newtext);
    else:
        for r in list(runs)[1:]: r._element.getparent().remove(r._element)
        runs[0].text=newtext
    for p in paras[1:]: p._element.getparent().remove(p._element)  # 删多余段
```

**⚠️ 遍历「全文档每一段」必须同时覆盖表格内段落**——只 `for p in doc.paragraphs` 会漏掉所有表格 cell 里的文字（总盘数字常散落在分期表/投资表/指标表里）。正确走法：
```python
def iter_paras(doc):
    for child in doc.element.body.iterchildren():
        if child.tag == qn('w:p'):
            yield Paragraph(child, doc)
        elif child.tag == qn('w:tbl'):
            for row in child.findall(qn('w:tr')):
                for tc in row.findall(qn('w:tc')):
                    for p in tc.iter(qn('w:p')):
                        yield Paragraph(p, doc)
```
**改前先 dump 目标段 run 数**（`len(p.runs)`）——单 run 直接改最稳，多 run 才走整段重写；否则盲目整段重写可能吞掉段内加粗/字体差异。

## 判是否「该由客户拍板」的分界
改动量可能差一个数量级：只对齐总盘表述+保原值（可控、投行纪律），还是连分册投资额、财务IRR/NPV 都按新总盘重算（要拍数、风险高，且无尽调依据只能比例放大）。**走到这一步先问用户走哪档**，不擅自决定重算——这直接决定工作量方向和交付会不会被认定为「编数」。

## 交付
- 改完备份原始客户回传版（`<项目>_原样备份.docx`），交付版用干净中文文件名（`<项目>_可研报告.docx`），客户版不带版本状态标签。
- Word→PDF 转出核对时，**数字会被插空格**（`1000 亿元`而非`1000亿元`），pymupdf `get_text()` 搜索前先 `re.sub(r'\s+','',txt)` 再匹配，别因搜不到误判「没进去」——文本其实在。（详见 document-delivery-qa 的 Word→PDF 空格坑）
