# 报告解剖（review-report.md 怎么读、怎么用）

> 报告 12 个章节各自的用途与读法。**结论在最前面，证据在中间，局限在最后**——
> 「附 ② 局限声明」必须与结论一起读，否则会高估这份报告。

## 章节地图

| 章节 | 一句话用途 | 读的时候看什么 |
|---|---|---|
| 0 执行摘要 | 6 行读完结论 | 裁定、加权总分、共识 P0 数、否决赛席数、角色投票分布 |
| ① 多角色评分矩阵 | 谁打了多少分 | **偏差列**（自报总分 vs 复算加权分之差，>10 要降权看）；维度均分表找集体短板 |
| ② 分歧矩阵 | 议题 × 角色命中图 | 一行被多席命中 = 共识；只有 1 席 = 单点视角 |
| ③ 钱的性质审查 | 第一性问题 | 几席判「不匹配」；判不匹配即结构性错误，优先级高于多数 P0 |
| ④ 政府基金专项 | 国资的钱能不能进来 | 5 个专项维度的均分与判定；「硬伤」= 国资这条路走不通 |

| ⑦ 加权总分与 Go/No-Go | 可审计的裁定 | 规则回溯（哪条规则命中、扣了多少分）、逐席裁定与否决规则 |
| ⑧ 修改优先级清单 | 照着改 | 排序「先严重度、后共识度」；Top 3 是「若只有一天」的取舍 |
| ⑨ 复审建议 | 下一轮怎么跑 | 复审触发条件、重点复看的页、预计轮次、分数异常的处理 |

| 附 ② 构成与局限 | 这份报告能信到什么程度 | 实际调用模型数、跳过的 provider 及原因、引用校验三档、失败席位 |

## 分歧矩阵读法

```
| 议题 | 角色A | 角色B | … | 共识度 | 涉页 |
| 财务勾稽与口径 | 🔴 P0 | 🔴 P0 | … | 共识 7/9 | [12, 7, 1] |
| 市场规模与测算 | · | 🔴 P0 | … | 分歧 ×1 | [6] |
```

- `🔴 P0 / 🟠 P1 / 🟡 P2` = 该角色就此议题给出的**最高**严重度；`·` = 未提
- **共识 7/9** = 7 席独立提了同类问题 → 必改
- **分歧 ×1** = 只有 1 席提 → 人工判断：若该角色对应本次融资的真实资金属性（如拿国资就要看政府基金角色），必改；否则记入「已知不适用」清单

**反直觉但重要**：共识度衡量的是「观点普遍性」，不是「危害大小」。
8 席里只有财务尽调官发现的 10 倍勾稽错误，其他 7 席都没看出来——但它足以让估值故事归零。
**单角色 P0 要单独过一遍，不要只看共识项。**

## 打分口径（为什么有「复算分」）

| 字段 | 定义 |
|---|---|
| `自报总分` | 模型自己给的整体印象分 |
| `复算加权分` | 我方用 `Σ(维度分 × 角色权重) / Σ权重` 重算的分 |
| `偏差` | 两者之差的绝对值 |

- `偏差 > 10` → 该角色打分与自己的维度分不自洽，趋势比较时以**复算分**为主锚
- `偏差 > 25` → 判为「整体印象分失效」，该席的**总分**从基础分中剔除
  （但它的**维度分、P0 提问、否决权全部照常计入**）

## Go/No-Go 判定公式（可复算）

```
基础分 = 自洽席位复算加权分的算术平均
红线扣分（按比例，避免评审团越大扣越狠）：
    共识 P0 议题 × 4 分          （上限 −16）
  + 否决赛席比例 × 20            （上限 −10）
  + No-Go 票比例 × 12            （上限 −6）
最终加权总分 = max(0, 基础分 − 红线扣分)

裁定：
  No-Go          ← ≥2 个共识 P0，或（有角色否决 且 ≥2 个 P0 议题），或 ≥3 票 No-Go
  Conditional-Go ← 存在 P0 或角色否决，但未达 No-Go 门槛
  Go             ← 无 P0、无否决、无 No-Go 票
```

报告 ⑦ 会逐条打印命中的规则与每一项扣分，**不需要相信结论，可以自己复算**。

## 引用校验三档（决定一条质疑能不能引用）

| 档 | 判据 | 能不能用 |
|---|---|---|
| **逐字命中** | 归一化（去空白/标点/markdown 装饰符）后是子串 | 可直接作对客材料依据 |
| **近似改写** | 字符 bigram 覆盖率 ≥ 0.90（改写幅度 ≤10%） | 语义可信，但引用前须回原文核对 |
| **疑似编造** | 其余 | **不得采信**，报告 6.2 单列并标 🚨 |

校验基准是 `bp-text-*.txt`（= 模型实际看到的 BP 文本），不是原始 BP 文件——
yaml/json 会被拍平成带字段路径的形式，模型摘的就是拍平后的原文。

## 分数不升反降怎么办

复审后分数低于上一轮，**不要怀疑模型**，按顺序查：

1. 该轮是否引入了新的口径冲突 → 先看 ⑤ 的「财务勾稽与口径」簇；
2. 修订的是实质还是表述 → 第 ⑧ 节要求的是「把 X 改成 Y」，不是「说得更好听」；
3. 是否只有 1 席提出的 P0 在反复出现 → 该角色视角可能与本轮资金性质不匹配，
   用 `--roles` 摘掉该角色并在报告中说明评估范围（**不要**为此改低它的否决阈值）。

## 交付纪律

- 报告是**过程产物**，不是对客材料：给客户前必须按第 ⑧ 节清单修订 BP，
  再由用户决定是否把评审意见作为「陪跑服务」的一部分呈现；
- 报告中带 🚨「疑似编造」或 ⚠️「近似改写」标记的引用，**整理成对客材料前必须回原文核对**；
- 「附 ② 局限声明」里关于降级模式、缺席 provider、失败席位的说明要照实转述，
  不要只转述对自己有利的结论。
