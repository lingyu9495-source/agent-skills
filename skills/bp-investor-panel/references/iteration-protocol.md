# 投资人评审团 · 迭代规程（初稿 → 评审 → 修订 → 复审）

> 这是本模块的**运行宪法**。硬要求来自用户：**BP 初稿必须经至少两个其他智能体/大模型扮演投资人
> 阅读并提意见之后，才能出正式报告。** 本规程把这句话落成可执行、可审计、可复现的循环。

---

## 一、循环定义

```
        ┌────────────────────────────────────────────────┐
        │                                                │
   BP初稿 ──▶ [第N轮评审] ──▶ 聚合报告 ──▶ 修订 ──▶ 复审 ──┘
              investor_review.py   aggregate.py         │
              (多角色×多模型)      (分歧矩阵/Go-NoGo)      │
                                                        │
                          无 P0 且无否决 ──▶ ✅ 出正式报告
```

| 环节 | 动作 | 命令 | 完成判据 |
|---|---|---|---|
| **① 初稿** | 准备 BP（yaml / json / md） | — | 项目方自己能说清"要融哪一轮、钱的性质（美元/人民币/国资）" |
| **② 评审** | 9 个投资人角色（三层：6 家市场化 VC/PE + 2 家政府基金/国资平台 + 1 名财务尽调官） × 自动派单的多个模型，逐页挑刺打分 | `python3 investor_review.py --bp <bp> --round N --tag vN` | ≥9 席出结果；引用校验通过率 ≥90% |
| **③ 聚合** | 出分歧矩阵、钱的性质审查、政府基金专项、共识/分歧、P0 汇总、Go/No-Go、修改优先级 | `python3 aggregate.py` | 报告含 ①–⑨ 全部章节 |
| **④ 修订** | 按报告第 ⑧ 节优先级清单改 BP；**先改共识 P0，再改单角色 P0，最后 P1** | 改 BP 文件 | 每条 P0 有对应的修改痕迹 |
| **⑤ 复审** | **换模型/换角色**重跑整团（不是只找提问题那个角色复核） | 同 ②，`--round N+1 --tag v(N+1)` | 分数轨迹已更新；无新 P0 |
| **⑥ 收敛** | 无 P0 且无角色触发否决阈值 | `python3 aggregate.py --verdict-only` | `verdict = Go` 或 `Conditional-Go` |

## 二、硬性规则（不满足就是流程违规）

1. **评审必须在正式报告之前**，不能一边写正式稿一边补评审意见。
2. **至少两个不同的评审主体**：优先"不同 provider 的不同模型"（本模块自动跨 provider 轮转派单）；
   若外部 key 只够一个模型，则降级为"同模型 + 角色 prompt 严格隔离 + 分轮独立调用"，
   **并在报告中明写这一局限**（`aggregate.py` 的"局限声明"第 2 条会自动标注）。
3. **引用必须为真**：模型给的 `quote` 必须逐字出自 BP。脚本会回原文校验，
   校验失败的条目在报告 4.2 节单列，**不得**作为对客材料的依据。
4. **复审必须换脑子**：同一角色连续两轮由同一模型评审，容易形成"确认偏误"（上一轮的意见被当成本轮的前提）。
   复审时优先换模型组合（`--degrade` 关掉即可自动轮转）。
5. **轮次上限 3 轮**。3 轮后仍有共识 P0，说明问题不是"材料没写好"，而是**生意本身不成立**——
   此时应停手，回到商业模型层面重做，而不是继续抛光 BP。
6. **钱的性质必须先定性**：BP 未写明「这笔钱是谁的」（币种／期限／返投／对赌回购／考核方式）时，
   报告第 ③ 节会全团判 `matched=false`。**这一项不修，其他项改了也会在尽调阶段崩**——
   修订顺序上它排在所有 P0 之前：先定钱的性质，再改全文口径与条款设计。
7. **每轮必须落盘评分轨迹**（`score-history.json`），否则迭代无法复盘。

## 三、评分轨迹与"分数不升反降"的处理

每轮跑完，`investor_review.py` 会把该轮各角色的**复算加权分**追加进 `review/score-history.json`：

```json
[{"round":1,"tag":"v1","scores":{"early_vc":{"total":49,"weighted":48.7,"go_no_go":"No-Go","P0":3,"veto":true}, ...}},
 {"round":2,"tag":"v2","scores":{...}}]
```

`aggregate.py` 会自动渲染成轨迹表（报告"附 ① 评分轨迹"）+ 逐角色首末对比。

**判读规则：**

| 现象 | 含义 | 动作 |
|---|---|---|
| 分数上升、P0 清零 | 修订有效 | 收敛，出正式报告 |
| 分数上升、P0 减少但未清零 | 方向对、力度不够 | 再跑一轮，专攻剩余 P0 |
| **分数不升反降** | 修订**引入了新的口径冲突**（常见于改财务数字时忘了同步改结论页） | 不要怀疑模型；先查 ③ 共识问题里的"财务勾稽与口径"簇 |
| 分数持平、P0 持平 | 改了表述没改实质（换皮） | 回到"动作"层：报告第 ⑧ 节要求的是"把 X 改成 Y"，不是"说得更好听" |
| 单角色 P0 持续只有 1 席提出 | 该角色视角（如政府基金的返投要求）**与本次融资的钱的性质不匹配** | 用 `--roles` 把该角色从评审团里摘掉，并在报告里说明评估范围 |

**关键纪律：比较基准是复算加权分，不是模型自报总分。**
自报总分带主观整体印象，多个模型的自报分与自身维度分偏差可 >10 分（报告中已标 `偏差` 列），
用自报分做趋势比较会把"模型心情"当成"BP 变好"。

## 四、修订优先级规则（怎么用报告第 ⑧ 节清单）

排序原则：**先严重度，后共识度**。

1. **共识 P0（≥2 席命中）** 必须全改——一个动作同时安抚多个投资人，性价比最高。
2. **单角色 P0** 逐个判断：
   - 若该角色对应本次融资的真实资金属性（如拿国资就必看政府引导基金角色）→ **必改**；
   - 否则 → 记录到"已知不适用"清单，报告中说明。
3. **P1** 尽量改，它们决定估值谈判区间。
4. **P2** 属于专业观感，正式稿排版阶段统一处理。

> 反直觉但重要：**共识度低的 P0 往往是最致命的**。
> 9 席里只有财务尽调官发现的 10 倍勾稽错误，其他 8 席都没看出来——
> 但它足以让整个估值故事归零。共识度衡量的是"观点普遍性"，不是"危害大小"。

## 五、与报告生产流水线的接口

本模块是 `consulting/report-production-pipeline` 的 **P2（多智能体并行）→ P3（反思迭代）** 环节的具体实现：

- P2 的"挑刺员（红队）"在此升级为 **9 席结构化投资人评审团**（6 家市场化 VC/PE + 2 家政府基金/国资平台 + 1 名财务尽调官）**+ 跨模型交叉验证**；
- P3 的"独立一轮审查"在此落成"**复审必须换模型**"的硬规则；
- 评审通过（无 P0）是进入 P4（正式交付/排版/双输出）的**前置闸门**。

## 六、实测样例：本仓库真实跑过的两轮（可直接对照 verify.txt）

| | 第 1 轮 v1（初稿 `engine/bp_content.yaml`，15 页） | 第 2 轮 v2（修订稿 `sample_bp_v2.md`，18 页） |
|---|---|---|
| 评审团 | 9 席（6 市场化 VC/PE + 2 政府基金 + 1 尽调官），9/9 出结果 | 同上，9/9 出结果 |
| 模型 | 5 个模型 / 2 provider（DeepSeek + 阿里云百炼 Qwen） | 5 个模型 / 2 provider |
| 评审团均分（复算加权） | 54.9 | **68.9（+14.0）** |
| 加权总分（扣红线后） | 28.9 | **42.2** |
| 触发否决席位 | 8 / 9 | **3 / 9** |
| 共识 P0 议题 | 7 个 | **9 个**（打在 v2 新增内容上） |
| 引用逐字校验通过率 | 97.3%（73 条） | 94.0%（67 条） |
| 「钱的性质」审查 | **9 席全判 matched=false** | **0 席判不匹配** |
| 裁定 | 🔴 No-Go | 🔴 No-Go |

**逐角色分数轨迹（就是报告"附 ①"里那张表）**

| 角色 | 第1轮 | 第2轮 | 变化 |
|---|---|---|---|
| 国资创投原型 | 63.9 | 70.0 | +6.1 |
| 制造业深耕型 | 61.9 | 64.5 | +2.6 |
| 长期研究驱动型 | 58.8 | 70.3 | +11.5 |
| 赛道卡位型 | 72.8 | 77.4 | +4.6 |
| 投人型 | 58.7 | 74.1 | +15.4 |
| 产业整合型 | 60.0 | 67.2 | +7.2 |
| 政府引导基金原型 | 63.9 | 69.3 | +5.4 |
| 地方产业投资平台原型 | 6.2 | 67.7 | +61.5（首轮该席自报分与维度分冲突，已剔除其整体分） |
| 财务尽调官 | 47.6 | 59.2 | +11.6 |

**这一轮教了我们什么（按本规程第三节判读表对照）**

1. **「钱的性质」是第一性问题，且它真的能一票挡住整个流程。**
   第 1 轮 9 席全判 `matched=false`——BP 通篇没写这 5,000 万是谁的钱。
   第 2 轮加了"资金性质与条款边界"专页后，9 席全部转为匹配。
   → 结论：修订顺序上它必须排在所有 P0 之前。

2. **分数上升 ≠ 收敛。** 均分 +14.0、否决席位 8→3，但 P0 议题 7→9。
   原因：评审团对**修订稿独立重审**，抓到了修订引入的新矛盾——
   - v2 自己写"2026 年收入 4,600 万 = 首年可获取池 4,224 万的 **109%**"，被 3 席独立抓住；
   - v2 的国资落地页把"本地采购 / 用工 / 纳税"三种不同量纲直接加总算 1.5 倍返投，4 席指出不可加总；
   - v2 新增"前五大客户占收入 38%"却没列明细，5 席追问；
   - 财务下修后未同步补应收账款/应付账款周转与经营性现金流测算，4 席要求补表。
   → 结论：这正是规程第三节"分数上升但 P0 未清零 → 方向对、力度不够，再跑一轮"的场景，
   **绝不能因为均分涨了就放行**。

3. **换模型复审确实能换出不同的看法。** 同一角色的模型在两轮之间保持一致（便于对比分数），
   但不同角色之间始终是不同 provider 的模型，因此 P0 议题天然带跨模型分歧。
   下一轮若想进一步降低"同模型系统性偏好"，可对同一角色跑两个模型做 A/B。

4. **打分不自洽要能被识别出来。** 第 1 轮"地方产业投资平台原型"自报 38 分，
   但它自己给的六维分加权复算只有 6.2（偏差 31.8）——报告自动把它从基础分里剔除，
   同时保留它的维度分、P0 提问与否决权。**没有让一个前后矛盾的分数污染总分。**

## 七、一轮实测的完整命令序列（可复制）

```bash
cd <工作目录>

# 第 1 轮：初稿评审
python3 investor_review.py --bp ../engine/bp_content.yaml --round 1 --tag v1
python3 aggregate.py --raw review-raw.json --out review-report.md

# 按报告第 ⑧ 节清单修订 → 产出修订稿 v2
python3 investor_review.py --bp sample_bp_v2.md --round 2 --tag v2
python3 aggregate.py --raw review-raw.json --history score-history.json --out review-report-v2.md

# 只看裁定（CI/脚本里用）
python3 aggregate.py --raw review-raw.json --verdict-only
```
