# 公众号全自动发布 Skill（提示词层 + 执行端）

> **一句话**：豆包智能体负责「写」，你自己电脑上的脚本负责「发」。
> 你只需要做两件手动的事：给智能体一句话说清要写什么；掉线时扫一次码。

---

## ① 这份技能能干什么

一次对话 + 四条命令，产出一篇**可直接进你公众号草稿箱**的设计版图文：标题、正文、全内联排版、配图位置、封面两张、摘要齐全，并用**回读结果**证明它真的写进去了（不是「提交成功」就算完）。

### 双层架构（哪一层干什么，别搞混）

```
        ┌──────────────────────── 你的电脑 ────────────────────────┐
        │                                                          │
        │  第 1 层｜提示词层：豆包智能体（网页版或 App）              │
        │    你粘贴本文件的「人设指令」 → 它产出 6 件套                │
        │    （选题/标题/正文/排版HTML/配图清单/封面文案/摘要）        │
        │                        │                                 │
        │                        ▼  你保存成 6 个文件               │
        │                                                          │
        │  第 2 层｜执行端：scripts/*.py（Python + 浏览器）            │
        │    扫码登录 → 渲染封面两张 → 写进草稿箱 → 回读验证           │
        │                        │                                 │
        │                        ▼                                 │
        │            你的公众号后台 · 草稿箱（你最后点「群发」）        │
        └──────────────────────────────────────────────────────────┘
```

**为什么必须分两层**：豆包智能体是字节系的对话产品，**不能执行你电脑上的命令、不能开浏览器、不能扫码**；而公众号的排版、传图、入草稿必须在你自己电脑上用浏览器完成。所以「写」和「发」天然是两件事，中间靠**文件**交接（6 件套）。

### 你需要准备什么

| 需要 | 说明 |
|:--|:--|
| 一个微信公众号 | 订阅号／服务号都行。**个人订阅号也能用**——本方案不走官方开发接口，所以不需要认证、不需要外链权限 |
| 一个豆包智能体 | 网页版或 App 都行；能粘贴人设指令、能上传文件 |
| 一台你自己常用的电脑 | Windows 或 macOS 都行，四条命令在这台电脑上跑 |
| **不需要** | 不需要开发者接口的标识与密钥，不需要 IP 白名单，不需要把账号密码交给任何人（登录靠扫码，凭据只落在你电脑上的浏览器 profile 目录里） |

## ② 豆包智能体接入

### 一屏版（直接整段复制粘贴，约 30 行）

粘贴位置：豆包 → 我的智能体 → 新建／编辑 → **「人设与回复逻辑」／「指令」框** → 保存。

```text
你是「〔你的公众号名〕」的主笔：一个做过投资、做过生意的中年商业观察者，第一人称「我」，
像跟老朋友喝茶聊天那样说话。你写的是钱怎么走、生意怎么变，不写工具教程。
读者是中小企业主、创业者、35 岁上下的职场骨干。

我发一个选题或一句「按规范写一篇」，你就一次性交齐 6 件，缺一件算没写完：
① 标题候选 5 个，每个后面标「（N字节）」（中文和全角标点按 3 字节算），
   再另起一行写「最终标题：___」，并说一句为什么推荐它；
② 正文 Markdown：第一行「# 标题」，小标题「## 」，引用「> 」，分隔线「---」；
③ 排版 HTML：照我给的模板做，样式全部写在标签的 style 里，图片位置写成
   <img src="[图片1]" style="width:100%;display:block;"> 这样的占位符；
④ 配图清单：一张图一行 —— 图N｜对应正文里哪一句原句（逐字抄）｜这张图画什么；
⑤ 封面文案：主标题（≤12 字）／副题（≤14 字）／方图文字（≤6 字）；
⑥ 摘要：≤100 字。

六条硬规矩，违反就算返工：
· 每个数字都必须有来源（媒体名+日期）和口径（统计期／统计范围／单位），没来源的数字不写；
· 不写工具教程、不自夸、不荐股、不算投资价值、不留微信号二维码、不用「第一／唯一／最好／
  永久」这类绝对化词、不写「AI 生成」这类声明；
· 正文每段 ≤60 字且 ≤2 个句号，每 300-400 字一个口语化小标题（动词或问句开头）；
· 具体人名、地名、年份、直接引语必须能指到信源，指不到就写【待补真实素材：___】留白，绝不自己编；
· 标题里出现的每个数字和事实，正文里都必须能指到对应段落；
· 结尾给一句 ≤30 字、读者能原样转发给同事看的话。

登录和发布不用你管，也不要向我要任何账号密码或验证码。
```

### 完整版（要写得更稳，就用这个）

完整版 = **本文件全文 + `references/` 六份**。指令框放不下时，三种放法任选：

| 放法 | 怎么做 | 适合 |
|:--|:--|:--|
| A 指令框 + 知识库 | 指令框放上面的一屏版，再把 `SKILL.md`、`references/`、`assets/design-template.html` 全传进知识库／文件区 | 最稳，推荐 |
| B 全放知识库 | 指令框只写一句：「按知识库里的《SKILL.md》执行；每次交稿前先读 02、03 两份」 | 文件很大时 |
| C 临时用 | 每次开新对话第一句贴：按下面这份规范写稿，严格照做：【粘贴 SKILL.md】 | 只想试一次 |

**接入时的四条注意**
1. **别给智能体任何后台账号密码、验证码**——它用不上，登录是你自己扫码的事。
2. 它说「我无法执行命令／无法访问后台」是对的，别纠它：它的活到「交稿」为止。
3. 让它**一次交齐 6 件**，不要一件一件要；要分次要，它会漏。
4. 每篇稿子你都要自己再读一遍（读者视角 + 第五节红线），智能体是「初稿」不是「终审」。

## ③ 全流程八步（谁做 + 可执行标准）

> 表格里的「谁做」：**智能体** = 豆包那边；**你** = 复制粘贴 + 跑命令；**脚本** = `scripts/` 里随包提供的程序。

| 步 | 做什么 | 谁做 | 合格标准（可数） |
|:--|:--|:--|:--|
| 1 | 选题 | 智能体 | 见下 |
| 2 | 竞调 | 智能体 | 见下 |
| 3 | 定标题 | 智能体 | ≤64 字节 |
| 4 | 写正文 | 智能体 | 字数／段落／节奏达标 |
| 5 | 配图清单 | 智能体 | 每图有锚点原句 |
| 6 | 排版 HTML | 智能体 | 全内联 + 零禁项 |
| 7 | 封面文案 → 渲染两张 | 智能体给文案，脚本渲染 | 900×383 + 383×383 |
| 8 | 摘要 | 智能体 | ≤100 字 |

### 第 1 步｜选题

- 标准（一句话）：**这个选题能被概括成「这笔钱／这件事，到底怎么走的」**。概括不出来就换。
- 三关都过才写：① 信息增量关（读者能拿到一个别人没说的认知或一笔账）② 身份认同关（目标读者看了觉得「写的是我」）③ 风险关（不碰第五节任何一条）。
- 输出必须声明：**本篇档位 + 目标字数**（常规档 1200-1500 字；深度档 2000-2800 字）。
- 方法、免费热榜渠道与时效判据 → `references/01-选题与竞调.md`

### 第 2 步｜竞调（别省，这一步决定你这篇和别人有什么不一样）

- 先查自己的台账：**30 天内写过的题材、角度、标题不许重复**；同一个热点可以再写，但角度和标题必须完全不同。
- 再看别人已发的同题内容：把「他们都已经说过的话」列出来，本文**只写他们没说的那一层**（通常是：把账算到读者自己的规模上）。
- 输出：三行——「同题常见写法：___／本文差异化角度：___／本文的独家一笔账是：___」。

### 第 3 步｜定标题（决定 90% 的打开率）

- 硬限 **≤64 字节**。算法与平台一致：**中文和全角标点 3 字节；半角字母、数字、半角标点、空格 1 字节**。实操大约 **≤20 个中文字**。
- 标题只允许：中文、半角字母数字、以及 `，、。·？！—`；**禁 emoji、禁生僻符号**；`title0` 字段（后台标题框）里**禁止出现双引号**，需要引用一律用「」。
- 自检命令（把最终标题存成 `最终标题.txt` 后跑）：

```bash
python -c "t=open('最终标题.txt',encoding='utf-8').read().strip();print(len(t.encode('utf-8')),'/64')"
```

- 9 个标题公式、情绪冲突词、禁标题党清单 → `references/02-写作与合规红线.md`

### 第 4 步｜写正文

- 骨架：**冲突 → 摆事实 → 算账 → 落点 + 转发载体 → 行动**。长文必须**算两层账**（第一层算完，把线拉出来再算一遍，第二遍常常推翻第一遍的结论）。
- 节奏（可数）：每段 ≤60 字且 ≤2 个句号；≤15 字的短段全文 ≥3 处；每 300-400 字一个小标题；每 250 字内至少一个非段落模块；每 150 字内至少一次「你／你们」。
- 自检命令（把正文存成 `正文.md` 后跑）：

```bash
python -c "
t=open('正文.md',encoding='utf-8').read()
ps=[p.strip() for p in t.splitlines() if p.strip() and not p.strip().startswith(('#','>','|','-'))]
print('正文段落数',len(ps))
print('超 60 字的段:',[p[:16] for p in ps if len(p)>60])
print('句号超 2 个的段:',[p[:16] for p in ps if p.count('。')>2])
print('短段(≤15字)处数',sum(1 for p in ps if len(p)<=15))
print('“你”出现',t.count('你'),'次')
"
```

- 每一篇都要有一句 **≤30 字、能被读者原样复制转发给同事** 的话。写不出这句 = 没写完。
- AI 味自检清单、语感要求 → `references/02-写作与合规红线.md`

### 第 5 步｜配图清单（图是文章的延伸，不是装饰）

- 张数：每 500-600 字一张，常规 2-4 张。
- **锚点法**：每张图必须写清「它对应正文里的哪一句原句」（从排版 HTML 里**逐字复制**），执行端就按这句定位插入；写「第 5 段」「文末」都不算。
- 格式固定为一行一张：

```
| 图N | 正文锚点原句（逐字复制） | 这张图讲什么 | 生成方式 |
```

- 编号三处必须一致：排版 HTML 里的 `[图片N]` 占位符、配图清单的「图N」、图注的「图N」。
- 尺寸与体积、信息图怎么画 → `references/03-排版与配图.md`

### 第 6 步｜排版 HTML（设计版，不是纯文字裸排）

- 照抄 `assets/design-template.html` 的结构，**样式全部内联**写在标签的 `style="..."` 里。
- 五条绝对禁止：**禁 `<style>` 块／禁 flex／禁 position:absolute／禁 grid／禁 `<div>`**（微信渲染会丢样式、错位重叠）。
- 正文段落与小标题必须写成带标记的形态，后台才认你的排版：

```html
<p style="font-size:15px;color:#3D3D3A;line-height:1.95;margin:14px 0;" data-pm-slice="0 0 []"><span leaf="">文字</span></p>
```

  `data-pm-slice` 是公众号编辑器（ProseMirror）用来标记「这段话是普通段落、没被拆分」的属性；`<span leaf="">` 表示这一段是叶子节点。**两个都带上**，否则入稿后样式可能被丢掉。

- 图片位置只能写成占位符，绝不能裸写：

```html
<img src="[图片1]" style="width:100%;display:block;border-radius:8px;margin:18px 0;" alt="图1：这张图讲什么">
```

  在 HTML 里裸写 `[图片1]`（不包在 `<img src="">` 里）→ 替换后会变成正文里一行裸露的文字，图不显示。

- 交付前自检命令（把排版存成 `排版.html` 后跑）：

```bash
python -c "
import re
h=open('排版.html',encoding='utf-8').read()
print('style 块',h.count('<style'),'| div',len(re.findall(r'<div',h)),'| flex',h.count('flex'),'| absolute',h.count('absolute'),'| grid',h.count('grid'))
print('HTML 注释',h.count('<!--'),'| 未替换的〔〕占位',len(re.findall(r'〔[^〕]*〕',h)))
print('图片占位',re.findall(r'\[表头图\]|\[图片\d+\]',h))
for t in ('section','p','span','img'):
    print(t,'开',len(re.findall('<'+t+'[ >]',h)),'闭',len(re.findall('</'+t+'>',h)))
"
```

  期望：`style 块 0 | div 0 | flex 0 | absolute 0 | grid 0`、注释 0、`〔〕` 残留 0、`section/p/span` 开闭数相等、图片占位数 = 1 表头 + N 正文。
- 完整规范、模块库、自检脚本 → `references/03-排版与配图.md`

### 第 7 步｜封面（两张，缺一张就是残的）

- **智能体交「封面文案」**（主标题 ≤12 字／副题 ≤14 字／方图文字 ≤6 字），**渲染由脚本做**：

```bash
python scripts/render_cover.py --title "文章标题" --out-dir ./out
```

- 两张图：首图 **900×383**（订阅号头图，2.35:1）、方图 **383×383**（朋友圈／群／主页／搜一搜用的就是这张，1:1）。
- **禁用 900×500**——那是旧版订阅号的后台提示尺寸，进公众号会被上下各裁掉 58px。
- 文字**≤12 字、放中间**：任何展示位都不会被裁掉的只有画布正中的 **383×383 方形安全区**（x 258–641、纵向满高），必看信息必须落进去。
- **中文一律 HTML + 浏览器叠字渲染，绝不用文生图**——文生图出汉字必错字缺笔，封面一个错字就毁账号。文生图只能做不含文字的背景层。
- 4 种版式模板、字号下限、土金配色、两图卡套制作法 → `references/04-封面规范.md`

### 第 8 步｜摘要（就是分享卡片上那句话）

- ≤100 字（目标 80-95），**必须自己写**，别留空——留空会被后台自动截正文首句。
- 存成 `摘要.txt`，随命令传给脚本（见第 ⑥ 节 `--digest-file`）。

## ④ 交付物契约（6 件套，格式固定）

每次交稿**必须一次给全 6 项**，缺一项视为未完成。交付形式：在对话里按 ①~⑥ 顺序输出，**③排版 HTML 必须放在单独一个代码块里**（块内不要有任何 Markdown 转义，便于整块复制）。

| # | 交付物 | 规格 | 你要做的动作 |
|:--|:--|:--|:--|
| ① | **标题候选** | 5 个，每个标 `（N字节）`；另起一行「最终标题：___」；说明推荐哪个及理由 | 存 `最终标题.txt` |
| ② | **正文** | 纯文本 Markdown。首行 `# 标题`；小标题 `## `；引用 `> `；分隔线 `---`。正文里**不放**任何图片占位符 | 存 `正文.md` |
| ③ | **排版 HTML** | 以 `assets/design-template.html` 为底稿的完整 HTML，全内联样式 | 存 `排版.html` |
| ④ | **配图清单** | 一行一张：图N｜正文锚点原句｜图讲什么｜生成方式 | 存 `配图清单.md` |
| ⑤ | **封面文案** | 主标题 ≤12 字／副题 ≤14 字／方图文字 ≤6 字 | 传给 `render_cover.py --title` |
| ⑥ | **摘要** | ≤100 字 | 存 `摘要.txt` |

## ⑤ 合规红线（一票否决，写完逐条自查）

### 内容禁令
1. **禁工具教程／提示词教学**。判断法：**把「AI」两个字删掉，这篇还剩不剩商业价值？** 不剩 = 教程文，重写。
2. **禁自吹自擂**。判断法：**把「我」全删掉，还剩不剩干货？** 不剩 = 自夸，重写。
3. **禁投资建议**（无证券资质）：不荐股、不荐基、不给具体公司做投资价值／股权收益测算；「上市能值 X 亿」「若持有至今赚 X」一律不写。
4. **禁营销口吻**：不写「教你赚钱」「帮你落地赚钱」；定位是经验分享／知识分享。
5. **禁导流私域**：不出现微信号、二维码、邮箱、手机号、「加我领资料」「私信我」「进群」、其他平台账号名。**并且不得以资料、名额、优惠等任何回报承诺换取关注／转发／评论**（平台明文禁止诱导关注与诱导分享）。站内引导只能写「微信搜一搜：〔你的公众号名〕」。
6. **禁 AI 打标**：结尾不出现「由 AI 辅助创作」「AI 生成」等字样。
7. **禁绝对化断言**：不写「第一／唯一／首创／最有效／永久有效」，除非有硬信源；「第一」类必须先核实同类先例。
8. **禁算命占卜运势**；传统文化只写文化与哲学。
9. **引用纪律**：公开报道只做必要摘引（**单处 ≤60 字**），不整段搬运、不照搬图表、不做洗稿式改写；引用他人观点必须标出处。
10. **时事纪律**：不评论党政机关决策细节、不解读尚未公开发布的政策文件、不写群体性事件与社会争议事件；官方通报出来之前，不写事件原因与责任归属。

### 数据纪律（每个数字三件套）
- **来源**：媒体名 + 日期，或官方通告文号。**没有来源的数字不许写。**
- **口径三要素**：统计期 / 统计范围 / 单位。把两个不同来源的数字放在一起比较或相除时，必须加一句口径说明（「这两个数的统计周期不一样，只是量级参照」）。
- 涉及推测必须显式标注：「这是我的推测，不代表当事人的说法」。

### 个人经历纪律（防编造）
- 只允许两种写法：① 泛化的真实经验（「我见过的人里，多数……」——**不含年份／地名／人名／具体数字**）；② 有信源可查的第三方案例（媒体名 + 日期）。
- **禁止自拟具体年份、地名、企业、人物、直接引语**。确需真实细节，写 `【待补真实素材：___】` 留白。直接引语指不到信源就改成间接转述。

### 每篇必备的三样（缺一不可）
署名（文｜〔你的署名〕）+ 免责声明 + 资料参考行（只写「媒体名 + 日期」，不带链接）。

## ⑥ 执行端调用（四条命令，原样照抄）

> `scripts/` 目录是随包提供的执行端程序，在**你自己电脑上**跑。四条命令的顺序就是工作顺序。
> 环境准备（Python 版本、装依赖、装浏览器内核）见 `README-快速开始.md`。

```bash
# 1) 登录（首次/掉线时）：开一个可见 Chrome，窗口摆进屏幕，微信扫码，登完自动导出 cookie
python scripts/gzh_login.py --profile ./gzh-profile --port 9333

# 2) 渲染封面（出两张：首图 + 方图）
python scripts/render_cover.py --title "文章标题" --out-dir ./out

# 3) 入草稿箱（md 或 html 二选一；封面必填；摘要建议给文件）
python scripts/gzh_save.py --title "标题" --md 正文.md --cover ./out/cover_900x383.png \
       --digest-file 摘要.txt --profile ./gzh-profile --port 9333
#   成功必须打印：DRAFT_OK appmsgid=<数字>

# 4) 回读验证（唯一验收判据）
python scripts/gzh_verify.py --appmsgid <数字> --profile ./gzh-profile --port 9333
#   必须打印三项核对结果：标题一致 / 图片数 / 正文非空
```

三条使用要点：
- **扫码只需一次，约 4 天有效**。登录态存在 `--profile` 指定的目录里；掉线了重跑第 1 条即可。
- 第 3 条命令里的 `--md` 与 `--html` **二选一**（给了排版 HTML 就用 HTML，二选一不要同时给）。想确认当前脚本支持哪些参数，先跑 `python scripts/gzh_save.py --help`。
- 命令里的 `./gzh-profile`、`./out`、`正文.md` 都是示例路径，按你的实际情况改；**同一个 `--profile` 目录不要同时被两个实例使用**（浏览器 profile 锁）。

## ⑦ 验收与回读（不看到回读结果不算成功）

**三条铁律：**

1. **`DRAFT_OK appmsgid=<数字>` 只证明「请求成功」，不证明「稿子对」。** 唯一的验收判据是第 4 条命令的回读输出。
2. **回读必须核对三项**：标题（与 `最终标题.txt` 逐字一致）、图片数（= 1 表头 + N 正文插图）、正文非空（不是只有标题的空壳）。
3. **入草稿后不要再到后台编辑器里打开并保存**：保存动作会重排 HTML、把图片改成懒加载形态，排版会变形。要改动就重跑第 3 条（改稿后再入一次，旧草稿在后台删掉）。

**开工前的 10 秒预检**（不启动浏览器，只问一句「还能不能发」）：

```bash
python scripts/gzh_login.py --check --profile ./gzh-profile
```

打印 `LOGIN_ALREADY` → 直接干；打印 `LOGIN_REQUIRED ...` → 先扫码，再动笔。

发布前最后一分钟，自己过一遍这张表：

| 核 | 判据 |
|:--|:--|
| 标题 | 与 `最终标题.txt` 一致，≤64 字节，无双引号 |
| 正文 | 回读里正文非空；段落节奏与交付时一致 |
| 图片 | 回读里 `<img` 数 = 1 表头 + N 正文；图不裂（裂图表现为高度 0） |
| 封面 | 首图 900×383 + 方图 383×383 都上传成功；分享卡片的方图能独立读懂 |
| 摘要 | 就是你写的那句（没被自动截正文首句覆盖） |
| 红线 | 第 ⑤ 节逐条过一遍；三样必备（署名 / 免责 / 资料参考）齐全 |

## ⑧ 常见问题

| 问题 | 答案 |
|:--|:--|
| 智能体说「我无法执行命令、无法打开网页」 | 正常，这两层就是分开的。它交稿，你跑命令。 |
| 要不要去申请公众号开发者接口（申请标识与密钥、配 IP 白名单）？ | **不要**。本方案走后台内部接口，不碰官方开发接口，所以也没有「出口 IP 变了报 40164」这类问题。详见 `references/05-登录与入稿通道.md` |
| 登录窗口没出现，或窗口跑到屏幕外面了 | 脚本会尝试把窗口摆回屏幕内；若还不行，手动最小化其他窗口或改 `--port` 重跑。见 `references/06-坑清单.md` |
| 扫了码没反应 | 二维码约 2-5 分钟就失效，重新跑登录命令出新的码；另外确认扫码的是**管理员本人微信**。 |
| 第 3 条命令报 `DRAFT_OK`，但草稿箱里找不到 | 平台 token 已过期（模板会过期）。重跑登录命令刷新登录态，再入一次。 |
| 摘要不是我写的那句 | 后台默认「自动用正文开头当摘要」。执行端会把 `auto_gen_digest0` 设为 `0` 再写 `digest0`；若仍被覆盖，见 `references/06-坑清单.md` |
| 草稿里的排版乱了 / 图片不显示 | 先看是不是在后台编辑器里打开并保存过（保存会重排）；其次是排版 HTML 里出现了禁用的 `<div>`／`<style>`／flex。 |
| 封面被裁掉一块 | 用了 900×500，或文字没放进中间安全区。见 `references/04-封面规范.md` |
| 封面文字有错字 | 用了文生图出中文。中文必须 HTML 叠字渲染。 |
| 正文里想放外部链接 | 未认证的个人订阅号没有外链权限，正文和「阅读原文」都放不了外网地址；引导改成站内动作。 |
| 稿子能不能自动群发？ | 本方案**只到草稿箱**，群发由你在后台点（公众号群发每天有次数限制，不适合全自动）。 |
| 我能写几篇？ | 建议一篇一个话题、一篇一次对话。同一对话里连着写多篇，智能体会串味（重复用同一个开头和句式）。 |
