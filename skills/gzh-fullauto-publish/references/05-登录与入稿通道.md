# 05 · 登录与入稿通道

> 这一份解释**「为什么不申请开发者接口」**和**「稿子是怎么进草稿箱的」**。
> 你要用到的只有 `scripts/` 里的四条命令（见 `SKILL.md` 第 ⑥ 节）；本文是给你排查问题时看原理的。

---

## 一、为什么走「后台内部接口」，不走官方开发接口

| | 官方开发接口（`draft/add`） | 后台内部接口（本方案默认） |
|:--|:--|:--|
| 需要什么 | 在你后台申请的开发者接口标识 + 密钥 → 换 `access_token` | **只要一个浏览器里已登录的后台会话** |
| 关键门槛 | **`access_token` 要求出口 IP 在白名单里** | **无 IP 白名单要求** |
| 家用宽带的现实 | 运营商 DHCP 会轮换出口 IP，白名单迟早失效 → 报 `errcode 40164 invalid ip <你的IP>` | **不受影响** |
| 配置位置 | 后台「设置与开发」相关入口（近年已迁到微信开发者平台，还要另外扫码登录一次） | 无 |
| 未认证个人订阅号的可用性 | 部分能力直接 `48001 api unauthorized` | 可用 |

**结论**：家用电脑上跑，官方接口的 IP 白名单是长期麻烦（每次换 IP 都要去后台改），而且认证门槛高。所以本方案直接用**你自己浏览器里那个已经登录的后台会话**去做存稿动作——跟你在后台手动点「保存为草稿」是同一个请求。

> 如果你的账号是企业认证号、又有固定出口 IP，你当然也可以用官方接口；`scripts/gzh_save.py` 的具体实现以你下载到的版本为准（`--help` 可看参数）。但**默认路径是内部接口**。

## 二、入稿原理：三步，缺一不可

### 第 1 步｜抓一次「真实载荷模板」

公众号后台的存稿接口是：

```
POST /cgi-bin/operate_appmsg?t=ajax-response&sub=create&type=77&token=<你的会话token>
```

它要 **100 多个字段**（`title0` / `content0` / `author0` / `digest0` / `cdn_url0` / `fingerprint` / `random` …）。

**手工拼这些字段必然报 `200002`（参数错误）**——少一个就不行。所以正确做法是：**让浏览器自己去发一次真实的保存请求，把这个请求的完整表单抓下来当模板**，之后每次只替换里头的值。

抓法（两种，都是让浏览器自己发一次真实保存请求，再把这个请求的完整表单截下来当模板）：

- **手工版**：打开新建文章编辑器 → F12 → Network → **用真实鼠标坐标点击「保存为草稿」按钮** → 在 Network 面板找到 `operate_appmsg?sub=create` 那条请求 → 看它的 Form Data（约 **126 个字段**）→ 存成模板文件。
- **自动版**（本包 `scripts/gzh_save.py` 采用）：在页面里给 `XMLHttpRequest` 与 `fetch` 挂一层钩子（「页内网络探针」），记录请求体，然后照常点一次保存，把截到的表单存成模板。

> ⚠️ **别用 Playwright 的 `page.on("request")` 抓这个请求**——实测该请求对 page 级、context 级、CDP `Network` 域三种监听**全部不可见**（会漏抓，同时草稿却已经存进去了，很容易误判成「没发出去」）。必须在页面内部挂钩子才抓得到。
> **为什么要用「真实鼠标坐标点击」**：那个保存按钮用 JS 的 `.click()` 或 `locator.click(force=True)` **都不会触发保存请求**（见 `06-坑清单.md` 第 1 条）。

### 第 2 步｜改字段

运行时替换这几个（其余字段保留模板原值）：

| 字段 | 填什么 |
|:--|:--|
| `title0` | 标题（**≤64 字节**，字段内**不能有双引号**） |
| `content0` | 正文 HTML（全内联、带 `data-pm-slice` 与 `span leaf`） |
| `digest0` | 摘要（**同时**要把 `auto_gen_digest0` 设为 `"0"`，否则被忽略，见第 6 节） |
| `author0` | 署名 |
| `AppMsgId` | **清空**（`""`）——它表示「新建」而不是「覆盖某篇」 |
| `isnew` | `"0"` |
| `token` | **每次运行重新从当前页面 URL 里取**（模板里的会过期） |
| `fingerprint` | **每次运行重新从 cookie 里取**（同上） |
| `cdn_url0` / `cdn_235_1_url0` | 首图 900×383 的图片地址 |
| `cdn_1_1_url0` | 方图 383×383 的图片地址 |

### 第 3 步｜在页面上下文里提交

```javascript
fetch(url, { credentials: 'include', body: new URLSearchParams(fields) })
```

成功返回 `{"appMsgId": 100000XXX, "ret": "0"}`。

- `appMsgId`（也叫 **appmsgid**）= 公众号给这篇草稿分配的**唯一编号**。它就是你后面**回读验证**和（需要时）**删除草稿**用的钥匙。
- `ret` = `"0"` 表示请求成功，**但它不等于稿子对**（见第 五 节）。

> 保存响应里如果出现 `filter_content_html` 有内容，**是正常的**——那是平台的内容检查回显。判断成功看 `base_resp.ret == 0`。

## 三、登录态：扫码一次，约 4 天有效

### 3.1 寿命

登录成功后导出的 cookie 里，关键凭证**带明确过期时间**（不是「关浏览器就丢」）：

| cookie | 有效期 |
|:--|:--|
| `slave_sid` / `slave_user` / `bizuin` / `data_bizuin` | 登录后 **+4 天** |
| `wxuin` | +1 年 |

**结论**：**扫码一次可用约 4 天**。到点了重跑一次登录命令即可，不要等出错了才扫。

### 3.2 登录态存在哪

存在你 `--profile` 指定的目录里（默认示例 `./gzh-profile`）——那是**一个独立浏览器 profile**：

- **别把它放进网盘、Git 仓库、共享目录**：里面等价于你的登录凭证。
- **别把它的内容发给任何人**（包括你的 AI 智能体——它根本不需要）。
- 它**可以删**：删了只是要重新扫一次码。

### 3.3 两条铁律

1. **扫码与导出 cookie 必须在同一个浏览器会话（同一个进程）里完成。**
   「先跑一个脚本扫码，再跑另一个脚本导 cookie」= **登录态一定丢**（第二个进程里没有第一个进程的会话）。一条命令一次做完。
2. **窗口必须可见、并且落在屏幕内**。
   扫码是你的动作，headless 没有码可扫。脚本会用一个**独立 profile + 远程调试端口**开窗口，并且**主动把窗口摆回屏幕内**（历史踩坑：窗口曾被系统放到 `x = -1410`，屏幕上完全看不见，让人白等）。

### 3.4 登录态过期怎么判断

**唯一可靠的判据**：打开 `https://mp.weixin.qq.com/` 首页，看页面正文里有没有「**扫一扫 / 使用账号登录**」字样——**有 = 已过期**。

**别信编辑器页还能打开**——那可能是缓存造成的误判。

### 3.5 注入 cookie 能免扫码吗

**服务端会话还活着的时候可以**：把上次导出的 cookie 注回浏览器上下文（`add_cookies`）再打开首页，就直接进后台。

**但会话已过期时无效**——失效发生在服务端，本地 cookie 在不在都一样。这时只能重新扫。

## 四、图片是怎么进去的（顺序不能错）

### 4.1 主路径（后台内部接口）

| 用途 | 怎么做 | 拿到什么 |
|:--|:--|:--|
| **正文插图** | `POST /cgi-bin/filetransfer?action=upload_material&type=image&token=...`，multipart 带上 `file`、`file_size`、`subtype=image`、`material_id=0`，请求头带 `Referer` = 编辑器页、`Origin` = `https://mp.weixin.qq.com` | 返回 `{"cdn_url": "https://mmbiz.qpic.cn/..."}` |
| **首图（900×383）** | 把上面那种 CDN 地址填进表单字段 `cdn_url0` / `cdn_235_1_url0` | — |
| **方图（383×383）** | 填进 `cdn_1_1_url0` | — |

**正文 HTML 里的 `<img src>` 必须用返回的 CDN 地址，不要用本地路径或 base64。**

**顺序**：先上传图片拿到 CDN 地址 → 再把排版 HTML 里的 `[图片N]` 占位符替换成真实地址 → 最后提交。顺序反了图就是裂的。

### 4.2 备选路径（官方接口，需要 IP 白名单）

- 正文图：`POST /cgi-bin/media/uploadimg` → 返回 `url`。**它只能内嵌正文，不能当封面。**
- 封面：`POST /cgi-bin/material/add_material?type=image` → 返回 `media_id`。草稿的 `thumb_media_id` 是**必填**，缺了存不了稿。
- **封面图必须 <2MB**（接口硬限制）→ 超了先转 JPG（`quality≈88`）再传，**按 1.9MB 判，别卡 2MB 边界**。

## 五、验证判据（这一节决定你会不会「以为成功了」）

> **`{"ret":"0"}` / `DRAFT_OK appmsgid=...` 只证明「请求成功」，不证明「稿子对」。**

必须**回读**，核对三项：

| 核对项 | 判据 |
|:--|:--|
| 标题 | 与你的 `最终标题.txt` **逐字一致** |
| 图片数 | `<img` 数量 = **1（表头）+ N（正文插图）** |
| 正文 | **非空**（不是只有标题的空壳） |

回读的正确姿势：
- 列表接口（`appmsg?begin=0&count=20&type=77&action=list_card`）**不返回正文**，只能看标题 / 作者 / 摘要——拿它验正文是错的；
- 要看正文，得打开编辑器页（`appmsg_edit_v2&action=edit&appmsgid=<id>`）读正文区域的文本，或用专门的回读脚本；
- 列表接口**会限流**，偶发返回空数组 → **sleep 重试 2-3 次**再判定失败。

## 六、失败现象对号入座表

| 你看到的现象 | 真实原因 | 怎么办 |
|:--|:--|:--|
| `errcode 40164 invalid ip <IP>` | 走了**官方接口**，出口 IP 不在白名单（家用宽带轮换 IP，正常现象） | 改用本方案的后台内部接口；或把报错里的 IP 加进后台白名单 |
| 首页正文出现「扫一扫 / 使用账号登录」 | 登录态过期 | 重跑登录命令扫码 |
| `TargetClosedError` / 提示 profile 被占用 | 同一个 `--user-data-dir` 被两个浏览器实例同时使用（**profile 锁**） | 别同时开两个；已有实例时**附着**上去（远程调试连接），不要新开 |
| 返回 `200002` 参数错误 | 手工拼的表单字段缺项 | 必须用「抓来的真实模板」改字段，不要手工构造 |
| `DRAFT_OK` 但草稿箱里找不到 | 模板里的 `token` / `fingerprint` 已过期 | 重新登录刷新会话，再入一次 |
| 摘要不是我写的那句 | `auto_gen_digest0` 仍为 `1`（后台自动截正文开头当摘要） | 必须**同时**设 `auto_gen_digest0="0"` + `digest0=<摘要全文>`（见第 七 节） |
| 图片显示成一条缝 / 高度 0 | CDN 上传没成功，或 `src` 不是 `mmbiz` 地址；也可能是 HTML 里带了空值的 `data-ratio` | 重传图片；检查 `src`；删掉空的 `data-ratio` / `data-type` |
| 正文排版全丢、只剩纯文本 | HTML 里出现了 `<style>` / `class` / `<div>`，或段落缺 `data-pm-slice` + `span leaf` | 按 `03-排版与配图.md` 改；重跑排版自检 |
| 草稿里的样式乱了、图变成淡出懒加载 | **在后台编辑器里打开过并保存了** | 别在后台编辑保存；要改就重新入一次，旧草稿删掉 |
| 编辑器里点草稿标题没反应 | 草稿卡片不是靠点标题进入的 | 先 hover 唤出按钮，再点铅笔图标 |
| 网络请求正常但列表返回空数组 | 列表接口限流 | sleep 几秒重试 2-3 次 |
| `48001 api unauthorized` | 未认证号没有该接口权限 | 正常，本方案的内部接口路径不受影响 |
| 正文里写的外链点不开 | 未认证个人订阅号**没有外链权限**（正文和「阅读原文」都不行） | 改成站内动作（「微信搜一搜：〔你的公众号名〕」） |

## 七、摘要为什么会被自动覆盖（单独讲一次）

后台存稿表单里有个开关字段 **`auto_gen_digest0`**：

- `auto_gen_digest0 = "1"`（默认）→ 后台**自动截正文开头**当摘要，你传的 `digest0` **被忽略**；
- 想要自己写的摘要 → 必须**同时**做两件事：`auto_gen_digest0 = "0"` **且** `digest0 = <摘要全文>`。

摘要就是分享卡片上那行字，直接影响打开率，所以**必须自己写**（≤100 字）。

---

## 八、两条纪律

1. **凭据不外流**：登录凭证只在你的浏览器 profile 目录里。**不要给 AI 智能体任何账号密码、验证码**——它用不上，给了只会多一个泄露面。
2. **群发是人的事**：本方案只把稿子送进**草稿箱**。公众号群发每天有次数限制，且发布前你应该自己再看一眼（标题、封面、摘要、红线），所以**最后那一下由你点**。
