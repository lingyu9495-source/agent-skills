# 06 · 坑清单（实测踩过，逐条照躲）

> 每一条都是**真实踩过的坑**：现象 → 为什么 → 正解。
> 任何一步报错，先来这里对号入座；找不到再看 `05-登录与入稿通道.md` 的「失败现象对号入座表」。

---

## A. 登录阶段

### A1｜窗口不在屏幕里，人对着空气扫码
- **现象**：脚本说二维码已经生成，但屏幕上什么都看不见，或者窗口只露一条边。历史上出现过窗口被放到 `x = -1410`（屏幕左侧之外）的情况。
- **原因**：用远程调试端口启动浏览器时，窗口位置由系统恢复上次的记忆，可能落在已拔掉的显示器区域。
- **正解**：启动后**主动用系统 API 把窗口摆回屏幕内并置前**（Windows 上用 `SetWindowPos`，尺寸固定成目标分辨率内可达的大小）；脚本里不要把 `headless` 打开——**扫码是人的动作，必须可见**。

### A2｜出码脚本被前台跑，二维码随进程一起死
- **现象**：人正在扫，扫完没反应；回头发现脚本早就退出/超时了。
- **原因**：出码脚本在前台跑，命令超时被连带杀掉，页面一关二维码立即失效。
- **正解**：出码/登录脚本**必须在后台跑**，一直活到登录成功为止（成功后再等几秒让 cookie 落盘，然后正常退出）。

### A3｜二维码自动刷新，正好把扫码打断
- **现象**：扫到一半突然失败、或者反复报未登录。
- **原因**：有的脚本会定时刷新页面来「保持二维码新鲜」——刷新瞬间正好扫码，登录流程作废。
- **正解**：**出码脚本一律不自动刷新**。二维码约 **2-5 分钟**失效，过期就**重新出一次**，不要靠自动刷新续命。

### A4｜profile 锁：同一目录开两个实例
- **现象**：`TargetClosedError`，或新实例启动后立刻崩。
- **原因**：同一个 `--user-data-dir`（浏览器 profile 目录）**不能被两个实例同时使用**，第二个人会被锁挡住。
- **正解**：已经在跑就用**附着**（连接远程调试端口 `http://127.0.0.1:<port>` 后新建页），不要新开目录；**附着时只关你自己开的那个页**，不要关整个浏览器（那个实例不是本任务起的）。

### A5｜cdp 连不上本地浏览器
- **现象**：连接本地调试端口报错。
- **原因**：新版本 Chromium 对远程调试来源有限制。
- **正解**：启动参数里带 **`--remote-allow-origins=*`**，再加 `--no-first-run --no-default-browser-check`，配独立 `--user-data-dir` 和 `--remote-debugging-port`。

### A6｜扫码和导 cookie 分成两个进程 → 登录态白拿
- **现象**：明明扫码成功了，下一个脚本打开还是登录页。
- **原因**：登录态在**会话内存**里，进程一结束就没了；cookie 没在同一会话里导出。
- **正解**：**扫码与导出 cookie 必须在同一个浏览器上下文里一次做完**，然后 `ctx.cookies()` 写进文件。
- **附带说明**：注入已导出的 cookie 可以免扫码，**但只对服务端会话还有效时管用**；已过期的会话注入什么都救不回来，别在注入这条路上耗时间。

### A7｜用「编辑器页能打开」判断登录态
- **现象**：以为还登录着，结果入稿失败。
- **原因**：缓存页面看起来能打开，其实会话早过期了。
- **正解**：唯一判据是**打开后台首页看正文里有没有「扫一扫 / 使用账号登录」**——有就是过期了。

## B. 抓模板与提交阶段

### B1｜JS 点击不触发保存（最关键的一条）
- **现象**：脚本调 `.click()`，什么请求都没发出去，network 面板一片安静。
- **原因**：保存按钮的事件绑定方式特殊，程序化的点击（`element.click()`、`locator.click(force=True)`）**都不触发**。
- **正解**：**用真实鼠标坐标点击**（拿到元素框的坐标后 `page.mouse.click(x, y)`），请求才会发出去；再把这次请求的完整字段截下来当模板。
  ⚠️ 截字段**不能在 `page.on("request")` 里抓**——实测这个请求对 page 级、context 级、CDP `Network` 域三种监听**全部不可见**（草稿却已经存进去了，很容易误判成「没发出去」）。要在**页面内部给 `XMLHttpRequest`／`fetch` 挂钩子**（页内网络探针）才抓得到，见 `05-登录与入稿通道.md`。

### B2｜手工拼表单 → `200002` 参数错误
- **现象**：提交返回参数错误。
- **原因**：这个接口要 100 多个字段（约 **126** 个），少一个就报错。
- **正解**：**抓一次真实保存请求当模板**，之后只替换值（标题/正文/摘要/署名/图片地址/token/fingerprint）。

### B3｜模板会过期
- **现象**：昨天还能用，今天 `ret` 不对或草稿没生成。
- **原因**：模板里的 `token` 属于会话级、`fingerprint` 也会变。
- **正解**：**每次运行都重新取**：`token` 从当前页面 URL 里取，`fingerprint` 从 cookie 里取。`AppMsgId` 清空、`isnew="0"` 表示新建。

### B4｜ProseMirror 粘贴只吃第一次
- **现象**：想把长正文（十几 KB）用合成粘贴事件塞进编辑器，第一段进去了，后面的**全部静默丢失**（连报错都没有）。
- **原因**：公众号编辑器基于 ProseMirror，**合成 `ClipboardEvent('paste')` 只接受第一次**，之后的事件被忽略；分块（2000 字符一块）也一样。
- **正解**：**不要走浏览器交互录入正文**。直接走「抓模板 + 改字段 + 页面上下文 fetch 提交」的通道（本方案就是这么做的）。

### B5｜`execCommand('insertHTML')` 会剥掉全部样式
- **现象**：内容进去了，但内联样式全没了，只剩纯文本。
- **原因**：编辑器会做规范化，把你写的内联样式全部剥掉。
- **正解**：同上——不走交互录入。

### B6｜真实剪贴板 + Ctrl+V 同样只吃一次
- **现象**：想着「模拟人手粘贴总行吧」，结果还是只进第一段。
- **原因**：与 B4 同一个编辑器限制。
- **正解**：同上。

### B7｜`fill()` 填标题框必然超时
- **现象**：脚本卡 30 秒然后报超时。
- **原因**：标题输入框是 `visibility:hidden` 的**镜像框**，Playwright 的 `fill()` 要求元素可见可交互，所以必然超时。
- **正解**：用 JS 直接赋值 + 派发 `input` / `change` / `blur` 事件。更稳的做法是**根本不碰编辑器界面**（走 B2 的模板通道）。

## C. 图片与渲染阶段

### C1｜图片先用本地路径 / base64 → 显示不出来
- **现象**：草稿里图是裂的，或者干脆没有。
- **原因**：微信只认自家图床（`mmbiz.qpic.cn`）的地址。
- **正解**：**先上传拿 CDN 地址 → 再把占位符替换成该地址 → 最后提交**，顺序不能反。

### C2｜图片被算成高度 0，显示成一条缝
- **现象**：编辑器里那张图只有几像素高。
- **原因**：`<img>` 上带了**空值的 `data-ratio` / `data-type`**——平台按这两个值算显示高度，空值就是 0。
- **正解**：不要新增空的 `data-ratio` / `data-type`；也不要删 `style`；不要用 `data-src`（那是懒加载态，会导致高度判断异常）。

### C3｜超高页面 + `device_scale_factor=2` → 截图整段重复
- **现象**：预览图里同一段文字出现好几次，看起来像排版错乱，其实是**截图坏了**。
- **原因**：超高的页面配上 2 倍缩放，超过渲染纹理上限，画面会整段重复；而且像素已被放大过，再按 2 倍尺寸去算裁切坐标必然错位。
- **正解**：**长稿一律 `device_scale_factor=1`**，视口高度取页面实际的 CSS 高度。要更高分辨率就放大视口本身，不要靠 dsf。

### C4｜逐段 clip 截图报错
- **现象**：`Clipped area is either empty or outside the resulting image`。
- **原因**：超高页面下，逐段裁切（`page.screenshot(clip=...)`）的坐标容易落到图外。
- **正解**：**先用 `full_page=True` 出一整张图，再用 PIL 切片**（每段约 1800px），然后逐段检查。

### C5｜预览时看到的是一片裂图 / 空位
- **现象**：检查排版时图片位置全是空的，以为排版错了。
- **原因**：直接打开本地 HTML 文件时，本地图片常常不落地（相对路径失效）。
- **正解**：预览前**把图片内联成 base64** 再截图，这样验的才是真排版（正式入稿时当然仍走 CDN 地址）。

### C6｜封面用了 900×500
- **现象**：上传后上下各被切掉 58px，底行文字只剩上半截。
- **原因**：900×500 是**旧版**订阅号的后台提示尺寸，不是 2.35:1。
- **正解**：一律 **900×383**（2.35:1）+ **383×383**（1:1）。见 `04-封面规范.md`。

### C7｜封面中文交给文生图 → 错字
- **现象**：封面标题出现错字、缺笔、伪汉字。
- **原因**：文生图模型对汉字的结构化渲染正确率不达标，6 字以上几乎必错。
- **正解**：**中文一律 HTML + 浏览器叠字渲染**；文生图只能做不含任何文字的底图 / 氛围层。

### C8｜封面被裁成「每行只剩一个字」
- **现象**：中心 1:1 裁切后，「我只算了一笔账」只剩「账」。
- **原因**：把封面当成「一张图」来排，文字铺在左侧或顶边，而 1:1 只取 `x 258-641`。
- **正解**：必看信息全部锁在 `x 258-641`；先按 2.35:1 排一次，再**单独**为 1:1 排一次，两张从母版一起裁出来。

## D. 排版 HTML 阶段

### D1｜`<div>` 被转成 `<p>`，样式全丢
- **现象**：卡片底、圆角、内边距都没了。
- **原因**：编辑器会把 `<div>` 规范化成 `<p>`，写在它上面的样式一起丢。
- **正解**：布局容器**一律用 `<section>`**；文字行用 `<p>` + `<span leaf="">`。**全文零 `<div>`。**

### D2｜段落缺 `data-pm-slice` / `span leaf` → 排版不生效
- **现象**：提交成功，但进后台一看样式被降级成普通段落。
- **原因**：服务端靠这两个标记识别「这是一段完整的、带样式的段落」。
- **正解**：每个文字段落与小标题都写成：
  `<p style="..." data-pm-slice="0 0 []"><span leaf="">文字</span></p>`

### D3｜`<style>` 块 / `class` 依赖 / flex / absolute / grid
- **现象**：手机端错位、重叠、样式丢失。
- **正解**：全部内联；布局只用块级元素 + `margin` / `padding` / `border` / 背景渐变。见 `03-排版与配图.md`。

### D4｜占位符写成裸文字
- **现象**：图的位置出现一行裸露的文字，图不显示。
- **原因**：`[图片1]` 没有包在 `<img src="...">` 里，替换时它只是个字符串。
- **正解**：一律写成 `<img src="[图片1]" style="..." alt="图1：...">`。

### D5｜`〔〕` 占位符残留 / HTML 注释 / `&nbsp;` / 自闭合标签 / 属性值里的双引号
- **现象**：正文里出现莫名其妙的符号；或入稿失败、样式异常。
- **正解**：交付前跑 `03-排版与配图.md` 第 6 节的四条自检命令，全部为 0 / 相等才算干净：
  - 无 `〔〕` 残留、无 `<!-- -->`、无 `&nbsp;`、无自闭合 `<img ... />`；
  - 属性（`style` / `alt`）一律双引号包裹，**属性值内不得出现双引号**（要引用用 `「」`）；
  - 标签之间只允许一个换行，**不缩进、不留空行**。

### D6｜手工压平 HTML，误删了行内空格
- **现象**：英文单词粘在一起、数字和单位连成一片。
- **原因**：手工做 `re.sub(r'>\s+<','><',html)` 很容易连行内的空格一起吃掉。
- **正解**：**不要在写作环节手工压平**，交给执行端脚本统一做。

### D7｜色值自创 / 混入蓝青紫红
- **现象**：返工。
- **正解**：只用 `03-排版与配图.md` 第 3 节的土金板白名单；交付前跑那条配色自检命令，越界色相必须为空。

### D8｜两份真源漂移（排版 HTML 与正文 md 不一致）
- **现象**：说不清入稿用的到底是哪一份；改了一处忘了另一处。
- **正解**：**排版 HTML 是唯一真源**。改稿先改 HTML，再同步 md，最后跑一致性自检（`03-排版与配图.md` 第 6 节 ③）。

## E. 验证与后台操作阶段

### E1｜看到 `ret=0` 就以为成功了
- **现象**：以为发好了，其实草稿里是空的 / 图没上去 / 摘要是自动截的。
- **原因**：`ret=0` / `DRAFT_OK` 只说明**请求被接受**。
- **正解**：**必须回读**三项：标题一致 / 图片数 = 1 + N / 正文非空。

### E2｜拿列表接口验正文
- **现象**：回读里正文字段是空的，以为稿子坏了。
- **原因**：列表接口（`list_card`）**不返回正文**，只给标题 / 作者 / 摘要。
- **正解**：验正文要打开编辑器页读正文区域，或用专门的回读脚本。

### E3｜列表接口返回空数组
- **现象**：刚存的稿子在列表里查不到。
- **原因**：该接口**有频率限制**，连续调用会返回空数组。
- **正解**：**sleep 几秒重试 2-3 次**；别一次失败就判定「草稿没生成」。

### E4｜点草稿标题没反应
- **现象**：想打开草稿看正文，点标题不跳转。
- **原因**：草稿卡片的进入方式不是点标题。
- **正解**：**先 hover 唤出操作按钮，再点铅笔图标**（程序化 `element.click()` 无效）。

### E5｜在后台编辑器里打开并保存了草稿
- **现象**：原本正常的排版乱了，图片变成淡出的懒加载形态。
- **原因**：后台保存动作会**重排 HTML** 并把图片改成懒加载形态。
- **正解**：**入草稿后不要在后台编辑器里打开并保存**。要改就重新入一次，然后把旧草稿删掉。验证走回读接口。

### E6｜草稿箱堆了一堆测试稿
- **现象**：真稿和调试稿混在一起，分不清。
- **正解**：给测试稿起明显前缀（例 `TEST_`），并定期清理；删除是不可逆动作，**先列出待删清单确认，再执行删除**，删完复核数量。

### E7｜摘要被自动覆盖（重灾区）
- **现象**：精心写的摘要没生效，卡片上是正文第一句。
- **原因**：表单字段 `auto_gen_digest0` 默认是 `1`（后台自动截正文开头），此时 `digest0` **被忽略**。
- **正解**：**同时**设 `auto_gen_digest0="0"` 和 `digest0=<摘要全文>`。

### E8｜以为未认证号也能外链
- **现象**：正文里的链接点不开；「阅读原文」也放不了外网地址。
- **原因**：未认证的个人订阅号**没有外链权限**。
- **正解**：引导改成站内动作（「微信搜一搜：〔你的公众号名〕」）；别写「详见阅读原文」。
- **顺带**：发布后正文**不能再改结构**（只能有限次改错别字），所以 **CTA、链接、摘要必须在发布前定稿**。

## F. 通用纪律（跨阶段）

### F1｜稿子写完了才发现登不进去
- **正解**：**开工先探发布链**（跑一次登录命令看是否已登录），再去做选题和写作。发布链断了，选题再准也是空头承诺。

### F2｜连续在同一个对话里写多篇，稿子串味
- **现象**：第二篇的开头、句式、案例和第一篇几乎一样。
- **正解**：一篇一个对话。同一个话题连着写，第二篇必然重复第一篇的语感。

### F3｜凭据被发得到处都是
- **正解**：登录凭据只在浏览器 profile 目录里。**不要给 AI 智能体任何账号密码或验证码**，它不需要；也不要放进网盘 / Git / 共享目录。

### F4｜入稿前没有把材料备齐，还要人干等
- **正解**：扫码前就把标题、正文、排版 HTML、图片、摘要、封面全部准备到位；**登录窗口一开，几分钟内一次做完**。让人对着窗口干等，是最容易失败的环节。
