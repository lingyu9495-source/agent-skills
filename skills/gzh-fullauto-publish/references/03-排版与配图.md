## 一、为什么微信排版这么多限制（先懂原因，才不会踩）

公众号的文章正文不是普通网页，它在编辑器里是被一套结构化编辑器（**ProseMirror**）管理的富文本。你提交的 HTML 会被它**解析成结构化文档再重建**，所以：

| 你写的 | 会发生什么 |
|:--|:--|
| `<style>` 块、`class` 选择器 | **被整块剥掉**（编辑器不认外部样式表） |
| `<div>` | 可能**被转成 `<p>`**，丢掉你写在它上面的样式 |
| `display:flex` / `position:absolute` / `grid` | 渲染会**错位重叠**（手机端布局引擎不支持） |
| 图片用本地路径或 base64 | 显示不出来——必须先把图片上传到微信的图床（`mmbiz.qpic.cn` 域名），再把 URL 填进 `src` |
| 空值的 `data-ratio` / `data-type` | 图片高度被算成 0 → 显示成一条缝 |

**结论**：只用**块级元素**（`section` / `p`）+ `span` + `img`，布局只用 `margin` / `padding` / `border` / `border-radius` / 背景色渐变。

## 二、全内联硬规范

### 2.1 元素白名单

| 允许 | 用途 |
|:--|:--|
| `<section style="...">` | **唯一的布局容器**（可嵌套）。间隔、背景、圆角、内边距都放这里 |
| `<p style="..." data-pm-slice="0 0 []"><span leaf="">文字</span></p>` | 唯一承载文字的形态（段落、小标题、卡片里的每一行） |
| `<span style="...">` | 段内局部强调（变色、加粗） |
| `<img src="[图片N]" style="..." alt="图N：...">` | 图片（**不写自闭合 `/>`**） |

**禁止**：`<div>`、`<style>`、`class`、`flex`、`position:absolute`、`grid`、`background-clip:text`、`<table>`、HTML 注释 `<!-- -->`、自闭合标签、`<br>` 堆空行（用 margin 代替）。

### 2.2 两个必须带上的属性（不带就会丢样式）

```html
<p style="font-size:15px;color:#3D3D3A;line-height:1.95;margin:14px 0;"
   data-pm-slice="0 0 []"><span leaf="">段落文字</span></p>
```

- **`data-pm-slice="0 0 []"`**：告诉编辑器「这一段是完整的普通段落，没有被多段混在一起」——它用三个值表示切片的起止位置和嵌套属性，`0 0 []` 就是「从 0 到 0、无嵌套属性」的常规整段。**缺了它，服务端可能不认你的排版。**
- **`<span leaf="">`**：`leaf` 表示这是**叶子节点**（里面只有文字，不再嵌结构）。文字直接裸写在 `<p>` 里、不包 `span`，样式也容易被丢。

**只给文字段落和小标题带这两个属性**；表头图、卡片外壳的 `<section>` 不需要。

### 2.3 精确参数（照抄，别自己调）

| 项 | 值 |
|:--|:--|
| 正文字号 | **15px**，行距 **1.95**，字间距 **0.5px** |
| 段间距 | `margin: 14px 0` |
| 页边距 | 模板 `section` 自身 `padding: 20px`（平台容器自带留白不计入，**不再另加**）；验收口径：**375px 宽的屏上每行 16-20 个中文字**——若少于 15 字，**减 padding，不许减字号** |
| 小标题 | 胶囊样式，**16px 加粗**，居中 |
| 对齐 | **左对齐**（禁两端对齐 `text-align:justify`） |
| 加粗 | 全篇重点标注**只 3-5 处**，必须真重点 |
| 次要信息 | 字号 **≥13px**，颜色统一 `#73726C`（图注 / 日期 / 署名 / 资料参考） |
| 段内 | 段落文字内部**无半角空格、无 `&nbsp;`、无全角空格、无制表符**；行内标签与文字之间无空格 |

## 三、配色白名单（土金板 v1.0，只允许以下色值）

| 用途 | 允许色值 |
|:--|:--|
| 打底（大面积） | `#FAF9F5` 米白 / `#F4F3EE` 暖白 |
| 卡片底 | `#F4F3EE` 暖白 / `#E8DDD3` 沙米 / `#F5E6D3` 浅驼 |
| 点睛（装饰线、序号、圆点、色块底、描边） | `#D4A853` 琥珀金（主）/ `#C9A961` 古铜金 / `#B8925A` 沙金 |
| 标题 / 强调文字 | `#141413` 暖黑 |
| 正文文字 | `#3D3D3A` 深咖 |
| 次要信息 | `#73726C` 暖灰 |
| 深色卡底 | `#1F1E1D` → `#3D3D3A` 渐变 |
| 深色卡上的文字 | `#F5E6D3` 浅驼 / `#D4A853` 琥珀金（≥24px） |
| 压在金色块 / 渐变上的文字 | **`#141413` 暖黑**（**禁白色**） |

**金色渐变公式**（统一用它，别自创）：`linear-gradient(135deg,#D4A853,#C9A961)`
**允许的半透明写法**：只允许用上面的色值做 `rgba(...)`（例如 `rgba(212,168,83,0)` 做渐隐装饰线），不得引入新色相。

### 对比度硬条（手机可读性，不许违反）

- 浅底（米白 / 暖白 / 沙米 / 浅驼）上的文字对比度 ≥ **4.5:1** → 正文用 `#3D3D3A`，要强调就用 `#141413` **加粗**。
- **金色不要在浅底上当小字颜色**：琥珀金压在米白上只有约 **2.1:1**，手机上看不清。金色只用于**≥24px 的装饰性元素、色块底、描边、装饰线**。
- **压在金 / 驼渐变上的文字一律 `#141413`，不得用白色**（白压金约 2.2:1，手机上看成一坨）。
- 深色卡（`#1F1E1D`→`#3D3D3A`）上的琥珀金对比度约 **7.7:1**，可以正常用（建议 ≥24px）。

**禁止任何蓝、青、紫、红、橙系色值**（橙色系包括一切橘红、橘黄偏红；**饱和度高的暖橙也在禁列**），**禁止用纯白铺大底**（用米白 `#FAF9F5`）。

## 五、配图规范

### 5.1 原则

**图是文章某一段的可视化延伸，不是装饰。** 每张图都要能回答：「这段在讲什么，图帮读者一眼看懂什么？」

- **张数**：每 500-600 字一张，常规 2-4 张。
- **图的三种类型**：① 信息图 / 对比图 / 结构图（用 HTML+CSS 画，块级布局）② 数据图（把算的账变成图表）③ 封面（见 `04-封面规范.md`）。
- **AI 文生图的使用边界**：**只能**做不含任何文字的底图 / 氛围层（色相限定在金 / 棕区间、饱和度 ≤60%），或版式 C 的人物插图。**任何中文字都不能交给文生图**（必出错字）。

### 5.2 占位符写法（写错图就不显示）

必须写成：

```html
<img src="[图片1]" style="width:100%;display:block;border-radius:8px;margin:18px 0;" alt="图1：〔写这张图讲什么〕">
```

**绝对不能在 HTML 里写裸的 `[图片1]`**——替换后会变成正文里一行裸露的文字。

执行端替换后的硬规格（你交稿时要保证 `src` 处于「可替换」状态）：

```html
<img src="http://mmbiz.qpic.cn/..." style="width:100%;display:block;border-radius:8px;margin:18px 0;" alt="图1：...">
```

- `src` 必须是 `mmbiz` 地址；
- **不得出现 `data-src`**、不得用 base64、不得删 `style`、不得新增空值的 `data-ratio` / `data-type`（空值会让图片高度算成 0）。

### 5.3 编号三处必须一一对应

| 位置 | 写法 |
|:--|:--|
| 正文占位符 | `[图片1]` 连续到 `[图片N]`，不跳号、不重号 |
| 配图清单 | 「图 1」…「图 N」 |
| 图注 / `alt` | 同一句文案，带「图 N」前缀 |

**配图清单格式**（锚点列是执行端定位插入的唯一依据）：

```
| 图N | 正文锚点原句（从排版 HTML 里逐字复制） | 这张图讲什么 | 生成方式 + prompt |
```

**图上下各留空、不贴边**；`alt` 与图注两处文案必须一致。

### 5.4 信息图的导出规格（你做 HTML，执行端渲染）

| 项 | 值 |
|:--|:--|
| 宽度 | **1080 px** |
| 底色 | **米白 `#FAF9F5`，不透明**（不要透明底、不要纯白大底） |
| 图上正文字号 | **≥48 px** |
| 单张高度 | **≤2400 px**（超出就拆成 2-3 张） |
| 单张体积 | **≤2 MB** |

**字号是怎么定出来的**：手机端正文展示宽度约 335px，1080 宽的图缩到 335 宽时缩放比约 0.31；图上字号 × 0.31 要 ≥15px → 图上字号 ≥48px。

### 5.5 锚点自检（图有没有插错位置）

把每张图的锚点原句单独存成一个文件 `锚点.txt`（每行一句），然后跑：

```bash
python -c "
h=open('排版.html',encoding='utf-8').read()
for a in open('锚点.txt',encoding='utf-8').read().splitlines():
    a=a.strip()
    if a: print('OK      ' if a in h else 'MISSING ', a[:24])
"
```

期望：全部 `OK`。出现 `MISSING` 说明锚点句在排版 HTML 里找不到（多半是智能体改过词），执行端插不进图。

## 七、装配原料：标签间的空白怎么处理

- **不要手工压平 HTML**——压平（`re.sub(r'>\s+<','><',html)`）由执行端脚本统一做。
- 你要保证的是：标签之间**只允许一个换行、不得缩进、不得留空行**；段落文字内部无空格（见 2.3 表格最后一行）。
- HTML 属性（`style` / `alt`）**一律用双引号包裹**，**属性值内禁止出现双引号**——需要引用一律用 `「」` 或 `《》`。

手工压平极易误删行内的空格（中文排版里不该有空格，但英文与数字之间可能有），所以交给脚本做。

## 八、装配顺序（照这个顺序工作，别乱）

```
1. 定稿正文段落       → 正文.md
2. 定配图锚点（逐字抄原句）+ 编号 1..N
3. 抄 assets/design-template.html 的模块，把文字填进去
4. 图片位置放 <img src="[图片N]"> 占位符（表头 1 + 正文 N）
5. 跑第六节①②③④四条自检命令，全绿才算排版完成
6. 交稿
```

**一个提醒**：排版 HTML 是唯一真源。改稿时**先改 HTML，再同步 md**，最后重跑第 ③ 条一致性自检——不要两边同时手改。
