# 04 · 封面规范

> 封面是**唯一一个「尺寸错了就白做」的东西**：文章写得再好，封面被裁掉半行字，读者第一眼看到的就是残缺。
> 这份规范里的尺寸、安全区、字号下限都是**可验证的硬数字**，照做即可。
> 渲染由 `scripts/render_cover.py` 完成；本文解释参数与版式，也给你手改的依据。

---

## 0. 先看这三条结论

1. **尺寸**：首图 **900×383 px（2.35:1）**；方图 **383×383 px（1:1）**。同一张母版可以同时出这两张。
2. **核心安全区（唯一不会被裁掉的区域）**：

   > 画布横向正中那条 **383 px 宽、纵向满高**的方带 —— 即 `x ∈ [258, 641]`、`y ∈ [0, 383]` 的 383×383 方形区域，**任何展示位置都不会被裁到**。凡「必须被看见」的信息必须落进这条带子里。

   推导：1:1 裁切取的是**画布中心正方形**，而画布高正好 383，所以这个正方形纵向吃掉全部高度，横向只取中间 383 px：`(900 − 383) / 2 = 258.5`。

3. **打法**：不要试图用一张图同时取悦 2.35:1 和 1:1。走「**两图卡套**」——母版 1283×383，左 900 是首图、右 383 是方图，各自独立设计。赶稿时才用「保底单图安全式」（版式 D）。

## 1. 硬参数表

| 项目 | 参数 |
|:--|:--|
| **首图 / 主封面** | **900×383 px，比例 2.35:1** |
| **方图 / 次图（转发卡片封面）** | **383×383 px，1:1** |
| ❌ **禁用 900×500** | 那是**旧版**订阅号的后台提示尺寸；按 2.35:1 裁后就是 900×383，也就是说用 900×500 上传等于**每次上下各被切掉 58px** |
| 格式 | JPG / PNG 静态图 |
| 体积 | 建议 **≤1MB**（加载快）；后台硬限 10MB；**上传接口硬限 2MB** → 超了会被执行端自动转 JPG（`quality≈88`）压缩 |
| 要不要两张 | 后台只上传 1 张也能用（它自己中心裁 1:1），但那样**转发卡片就是你首图的正中央一截**——商业号必须主动上传方图 |

**诚实说明**：微信官方帮助中心**没有公开**像素级的封面尺寸清单。2.35:1 与 1:1 这两个**比例**是后台上传裁剪框的实际界面事实；900×383 / 383×383 这两个**像素值**是运营圈的通行换算（多家编辑器一致）。**比例是硬约束，像素取整不必纠结 1-2px。**

## 2. 封面在各位置怎么被渲染

| 展示位 | 显示形状 | 是否裁切 | 裁哪一块 |
|:--|:--|:--|:--|
| 订阅号消息列表（星标 / 常读用户） | 2.35:1 横图 | 不裁 | 完整显示 900×383 |
| 订阅号消息列表（未星标 / 非常读） | **1:1 方图** | **裁** | 取画布中心正方形（约 383×383），左右各丢 258px |
| 公众号主页 / 历史消息列表 | 1:1 方图 | 裁 | 同上，中心 383×383 |
| 朋友圈 / 群聊分享卡片 | 1:1 方图 | 裁 | 同上 |
| 内容推荐流 | 2.35:1 横图 | 一般不裁 | 与首图一致 |
| 站内搜索结果 | 1:1 缩略图（保守判断） | 裁 | 按中心 1:1 处理 |

> 「星标 / 常读 → 大图，否则 → 小图」这一条是运营圈实测口径，非官方文档。**但这不重要**——你无法控制读者是不是星标，所以**设计必须以「会被裁成中心 1:1」为前提**。

### 三层退化设计法（按这个排信息）

| 层 | 区域 | 保证 |
|:--|:--|:--|
| **L1 核心层** | `x 258-641`，`y 0-383` | 任何位置都看得见。放主标题、核心数字、品牌字 |
| **L2 边缘层** | `x 60-258` 与 `x 641-840` | 只在 2.35:1 大图位可见。放副标题、氛围装饰 |
| **L3 出血层** | `x 0-60` 与 `x 840-900`，以及全画布最上 / 最下 20px | 随时可能被裁或被标题浮层压住。**不放任何信息** |

**标题浮层再保险**：部分列表形态下文章标题会压在封面图上，追求绝对保险就让核心层再上下各退 30px（`y 30-353`）。

## 3. 八条设计规律

1. **文字量：一个断言，不超过 12 个字（2 行 × 6 字）。** 读者在信息流里停留约 0.3 秒，封面只负责制造一个好奇心缺口，不负责解释。
2. **字号下限**：首图主标题 **≥56px**；想让副行也被读到必须 **≥48px**（**36px 的副行在 200px 缩略图下已经糊掉**）；方图文字 **≥34px**。≤28px 的眉标在缩略图里就是噪点，**不要往里放信息**。（量化依据见第 7 节）
3. **对比度**：主标题与背景的**明度差 ≥60%**——深底浅字或浅底深字。**金色系最容易犯「金底金字」**：金字压深色底（`#1F1E1D`）可以，压浅驼底（`#F5E6D3`）**绝对不行**。
4. **数字 > 形容词**。「54 万」「9 个月」「38%」的点击力远高于「成本高企」。财经类封面的主流句式是「**具体数字 + 反常识判断**」。
5. **主体位置二选一，不要中间态**：要稳重就左对齐到 `x = 52`；要冲击就居中。文字两端一律留 **≥5% 边距，不得顶边**。
6. **留白 ≥30%，文字块只占画面 35%-50%。** 塞满＝廉价，这是商业号最容易失守的一条。
7. **颜色 ≤3 种**：1 个底色 + 1 个主色 + 1 个强调色。
8. **情绪走「冷静权威」，不走「热闹促销」**：硬朗无衬线、方角、细金线、低饱和；不用卡通、不用爆炸贴、不用大红大绿。人物只用半身 / 背影 / 手部特写。

## 4. 四个可复用版式（土金板 v1.0）

### 账号色板（硬约束，违者退回）

| 用途 | 色值 |
|:--|:--|
| 打底 | `#FAF9F5` 米白 / `#F4F3EE` 暖白 |
| 点睛主色 | `#D4A853` 琥珀金 |
| 点睛辅色 | `#C9A961` 古铜金 / `#B8925A` 沙金 |
| 深浅底过渡 | `#E8DDD3` 沙米 / `#F5E6D3` 浅驼（**浅底用这个，不要纯白**） |
| 深色底 | `#1F1E1D` → `#3D3D3A` 渐变 |
| 文字（浅底） | `#141413` 暖黑 / `#3D3D3A` 深咖；次要 `#73726C` 暖灰 |
| 压在金 / 驼渐变上的文字 | `#141413` 暖黑（**禁白色**） |

**绝对禁止**：一切橙（含偏红的橘橙）、蓝、青、紫、红系、纯白铺大底、荧光霓虹。
**金色渐变公式**：`linear-gradient(135deg,#D4A853,#C9A961)`。
**字体**：中文一律 **`Microsoft YaHei`（微软雅黑）**，macOS 回退 `PingFang SC`，再回退 `sans-serif`。用系统字渲染，中文**零错字**。

---

### 版式 A｜大字断言式（深底）—— 最常用

**适用**：成本账、反常识判断、行业冷暖。**情绪**：沉稳、权威、克制。

- **分区**：左 0-58%（`x 0-520`）文字区；右 58-100%（`x 520-900`）金色氛围区（径向光晕 + 金色描边方框 + 一个金色大字符号做视觉锚）
- **眉标**：1 行 ≤4 字，20-22px，琥珀金描边小框（装饰层，缩略图下会糊，正常）
- **主标题**：**2 行、每行 6-8 字、56-60px、`font-weight:bold`、行距 1.25**；第 1 行 `#F5E6D3`（浅驼），第 2 行琥珀金 `#D4A853`
- **分隔线**：132×3px，金渐变，圆角 2px
- **副行**：≤14 字，34-36px，`#C9A961`（只在 2.35:1 位可见）
- **底**：`#1F1E1D` + 琥珀金径向光晕 + 135° 叠加 `#3D3D3A → #1F1E1D`

### 版式 B｜数字冲突式（浅底）—— 数据类首选

**适用**：财报、现金流、同比对比、行业数据。**情绪**：清醒、算账。

- **分区**：左 0-72%（`x 0-650`）数字区；右 72-100% 金线装饰
- **眉标**：≤5 字，22px，琥珀金底 + `#141413` 字，圆角 4px
- **两个对立数字**：**96-110px bold**；数字 ① 用 `#D4A853`，数字 ② 用 `#141413`；中间插 **2px 金竖线**（高约 120px，上下渐隐）做分隔
- **结论行**：1 行 ≤14 字，**36px**，`#3D3D3A`
- **底**：`linear-gradient(135deg,#FAF9F5 0%,#F4F3EE 45%,#E8DDD3 100%)` + `#B8925A` 低透明描边

### 版式 C｜人物留白式（深底 + 右侧 38% 预留）

**适用**：人物稿、走访见闻、案例访谈。**情绪**：现场感。

- **分区**：左 0-62%（`x 0-560`）文字区；**右 62-100%（`x 560-900`，宽 340px）为「插图 / 人物贴入区」**
- **主标题**：2 行，每行 **7 字**，56px bold
- **副行**：≤12 字，34px
- **预留区只贴**：AI 生成的低饱和金调场景图 / 半身人物（或实拍照片）；**区内严禁出现任何文字**
- **底**：深底；预留区当前用琥珀金径向光晕占位

### 版式 D｜保底单图安全式（深底）—— 只出一张图时用

**适用**：临时赶稿、不做卡套、或不确定后台裁剪操作时。**这是最保险的版式。**

- **所有元素锁死在 `x 258-641` 内**；中轴 = 450 = 安全区中心
- **主标题**：2 行 × **5 字**，字号 **66px**，居中（`5 × 66 = 330 < 383`，数学上保证整行落在安全带内）
- **结构**：中央 340×290 琥珀金描边圆角卡（radius 14）+ 顶部眉标 20px + `x=258` / `x=641` 两条 1px 金色竖细线（正片里当视觉框，1:1 裁切时自动消失）
- **品牌字**：底部居中〔你的公众号名〕，28px，`#73726C`
- **实测结论**：中心裁成 383×383 后，**画面依然是一张完整的方图，无一处残缺**

## 5. 生产方法：HTML + 浏览器渲染，**不用 AI 文生图出中文**

### 为什么中文封面必须走 HTML 叠字

1. **文生图的中文正确率不达标**：主流文生图模型对汉字的结构化渲染正确率很低，6 字以上的句子几乎必出错字、缺笔、伪汉字。**封面出现一个错字，账号专业性直接崩**，这是不可接受的下限风险。
2. **不可精确定位**：字号、行数、每行几个字、坐标都无法指定，改一版等于重抽一次盲盒。而封面的价值恰恰在这些数字上。
3. **代码即版式**：HTML 里字号 / 坐标 / 行数都是数字，可 diff、可复用、可批量。
4. **中文字体 100% 正确**：用系统字（微软雅黑）渲染，笔画零错误。
5. 封面 **80% 的价值在文字，20% 在氛围**。文字必须走 HTML；氛围可以用 AI。

### AI 文生图的能力边界（写死，别越界）

| | 可以做 | 绝对不可以做 |
|:--|:--|:--|
| 内容 | 底图 / 氛围背景（抽象金调渐变、金属拉丝质感、光影体积）、版式 C 的人物与场景插图 | **任何中文字**（标题、口号）、logo、任何形式的文字水印；把 AI 生成的人脸当作「真人本人」 |

**三条铁律**（AI 图作为背景层时必须同时满足）：
1. **不含任何文字 / 水印**（生成后必须目视检查）；
2. **色相限定在金 / 驼 / 棕区间，饱和度 ≤60%**，不得出现蓝青紫红；
3. **与文字区叠加时必须压 ≥45% 的深色遮罩**，保证主标题与背景**明度差 ≥60%**。

### 渲染参数

`scripts/render_cover.py --title "文章标题" --out-dir ./out` 会：出母版 1283×383 → 裁出首图 900×383 与方图 383×383。

你自己写渲染器时要遵守的参数：

```
浏览器内核       ：随包安装的 Chromium（Playwright 自带的，别依赖系统浏览器）
device_scale_factor = 1     ← 必须 1，见 06-坑清单
viewport         = 目标像素尺寸（直接设成 1283×383），整帧截图即为精确像素产物，不需要再缩图
字体             ：Microsoft YaHei → PingFang SC → sans-serif
```

## 6. 两图卡套的制作规程

**原理**：后台上传封面的裁剪弹窗里同时提供 **2.35:1** 与 **1:1** 两个比例框。把两张图**左右拼成一张**上传，然后在两个框里各拖一次 —— **一次上传，两张封面**。

```
母版 1283 × 383 = 左 900×383（2.35:1 首图） + 右 383×383（1:1 方图）
分界线在 x = 900
首图 = 母版.crop((0,   0, 900, 383))    ← 裁切，100% 无损
方图 = 母版.crop((900, 0, 1283,383))    ← 裁切，100% 无损
```

**必须是「裁切」不是「缩放」**——两张图都从母版原像素直接裁下来，才能保证 1:1 像素级精确、文字不糊。

### 关键纪律（保证方图不裁掉重点）

1. **方图的文字必须独立完整可读，绝不能依赖首图的文字位置。** 方图是给「转发卡片 + 未星标信息流」看的，那些位置看不到首图的左半边。
2. **方图字号下限 34px**（383 缩到 200px 宽还剩约 18px，清晰）。方图只放 **4-6 个字的核心结论 + 品牌字**。
3. **首图内容不得跨过 `x=900` 分界线；方图内容不得跨进 `x<900`。**
4. **分界线两侧各留 12px 空白缓冲**，防止后台上拖框时手抖切到邻区内容。
5. **方图不要再用「中心裁切」逻辑思考**——它就是独立设计的一张方图。

> 如果你的账号走的是脚本入稿（本包的默认路径），执行端会直接把两张图分别写进封面字段：首图 → `cdn_url0` / `cdn_235_1_url0`，方图 → `cdn_1_1_url0`，**不需要手工在后台拖框**。

- [ ] 画面**无 AI 生成的汉字**、无水印
- [ ] 后台预览里**大图位和小图位都看过**，不只确认大图

## 9. 最常见的封面事故（照这躲）

| 事故 | 症状 | 正确做法 |
|:--|:--|:--|
| **用了 900×500** | 上下各被切掉 58px，底行文字只剩上半截 | 一律 900×383 |
| **把封面当「一张图」排** | 中心 1:1 裁切后每行字被逐字切断（「我只算了一笔账」→ 只剩「账」） | 先按 2.35:1 排一次，再**单独**为 1:1 排一次，两张一起从母版出来 |
| **装饰物占了黄金位** | 一根装饰柱正好压在 `x 258-641`，1:1 视图只剩它、零信息 | 核心层只放信息，装饰放 L2/L3 |
| **底行小字过小** | 30px 的小字缩到缩略图后约 6.7px，等于没有 | 小字只服务手机列表，**不要往里放信息** |
| **没有独立方图** | 靠系统从首图中心自动裁 → 必然出现被切断的字 | 出两张，分别上传 |
| **文字顶边 / 压最下沿** | 任何上下裁切都会伤到 | 上下各留 ≥20px；文字两端 ≥5% 边距 |
| **中文交给文生图** | 错字、缺笔、伪汉字 | 中文一律 HTML 叠字渲染 |

**共同病根（一句话）**：把封面当成「一张图」，而公众号封面是「**两套裁切框**」。
