# 记忆修剪与归档

## When to Use

- 记忆用量 >80%（`MEMORY.md` / 长期记忆快满）
- AI 出现"记不住东西 / 越跑越乱 / 遗忘早期约束"
- 定期检查（建议每 2-4 周一次）
- 用户要求"记忆修剪 / 把多余的存到文档里"

## 一句话核心

**记忆存"判断与偏好"，文档存"细节与档案"。长满就剪，剪完归档，不丢东西。**

## 修剪三分类

| 类别 | 例子 | 处理 |
|---|---|---|
| **该留** | 稳定偏好、铁律、环境事实、高频指针 | 保留，可精简措辞 |
| **该归档** | 一次性项目细节、已沉淀进技能的内容、易过时的数值、过程记录 | 搬进归档文件，记忆里改成一两行指针 |
| **该删** | 完全过时、被替代、错误信息 | 直接删，归档也不留 |

## 判断"该留"的三条标准

1. **稳定**：半年后还成立吗？（会过时 → 归档）
2. **高频**：每次都用到吗？（偶尔一次 → 归档）
3. **决策级**：影响怎么对用户/客户做判断吗？（纯路径、版本号 → 技能里已有，归档）

三条全满足才留。

## 五步流程

**Step 1 · 分段落**
读 `MEMORY.md` 与用户画像，按分隔符拆段，每段标"留/归档/删"。

**Step 2 · 先归档（防丢）**
建归档文件 `archive/记忆归档-YYYY-MM-DD.md`，分类存：
- 已沉淀进技能的指针
- 环境配置事实
- 模型/API 矩阵
- 一次性项目案例

全文不丢——这是保险，不是删除。

**Step 3 · 批量精简**
按 `old_text` 精确匹配删除已归档段。保留核心段 + 补回关键指针。

**Step 4 · 补回长期偏好**
修剪后重点检查：**用户的稳定偏好、战略决策**有没有被误删。
那些虽然新加，但属长期偏好，要补回。

**Step 5 · 验证**
- 用量降到 <50%
- 重读一遍，确认"条目不多但都是关键"
- 随便问三个旧问题，看还能不能答上（答不上说明剪过头）

## 坑

- **只删不归档**：剪完就丢，三个月后要用找不回来
- **把过程当记忆**：调试日志、命令输出、"今天试了 X"——这些归归档，不进记忆
- **热层当仓库**：越写越长，最后挤占上下文，模型变迟钝
- **剪完不复读**：剪完必须读一遍，确认没有把铁律剪掉
- **没有定期**：等满了才剪，往往已经出了事故
