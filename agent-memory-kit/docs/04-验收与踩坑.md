# 04 · 验收与踩坑

## 一、验收四步（缺一步不算装好）

1. **写入**：`ai_mem add "暗号：蓝鲸" --tags 测试`
2. **同会话召回**：`ai_mem recall 蓝鲸` 命中
3. **跨会话召回**：**重启进程 / 新开会话**，让它自己想起来 —— 这一步才是真验证，90% 的"假成功"死在这
4. **隔离**：换另一个成员目录/账号搜同一个词，必须搜不到

**判成功的硬证据**：不是"它答得像"，而是**会话文件里能 grep 到注入的原文标记**（如 `【长期记忆·自动召回】…`）。
模型不调工具也能编出"我记得"，但编不出你写的那段文字。

```bash
# 查它到底有没有被注入（以 Hermes 会话库为例）
grep -c "长期记忆·自动召回" ~/.hermes/sessions/<session>.json
```

只报"装好了 / 配置生效了 / 服务 active"都不算完成。

## 二、18 个坑（按踩到的顺序）

### 检索类

1. **中文整句搜不到**
   `unicode61` 分词把连续中文当一个词；换 `trigram` 后短词能搜，但**一整句问话仍搜不到**——
   因为"客户那单收了多少定金"从来不会原样出现在记录里。
   → **召回必须走 `recall`**（切成 2-3 字片段 OR 匹配打分），`search` 只给明确关键词（人名、编号、条款号）。
   → 口诀：**自动注入用 recall，人手查词用 search**。

2. **向量不是万能的**
   C 档默认 embedding 常是英文小模型，对中文几乎全 `[UNK]`；
   能答对靠的是关键词 + 多路融合 + 重排，不是"语义理解"。
   → 验收要造三类题：同义改写、时间关联、跨条聚合。

### 架构类

3. **只装不注入**：底座跑通、文件落盘，只证明"存"通了。不接进系统提示 = 白装。
4. **只写不读**：写入正常但召回从不触发。查法：看注入钩子有没有被调用（日志/计数），不是看数据库条数。
5. **热层无限膨胀**：`MEMORY.md` 超 8KB 开始挤占上下文，模型变迟钝。按月归档。
6. **多人共用一套**：必须一成员一账号/一目录，否则记忆互相污染。
7. **两个主库并行**：记忆分裂，日后没人知道哪条是真的。主库只能一个。
8. **换模型后记忆断层**：换 provider 不换存储目录；换了 embedding 模型必须重建索引。

### 合规类

9. **AGPL-3.0**（OpenViking / Basic Memory）：自用可控，**对外提供服务或改源码交付**就要法务过。拿不准选 MIT/Apache-2.0。
10. **embedding 走谁的 key**：客户数据不出内网时，embedding 必须本地化或走客户自己账号。写进合同。

### 运维类

11. **每日自动镜像必须白名单**
    定时任务把整个目录"全量推"进底座 = 把 AI 每天自产的草稿、学习卡也当记忆，几个月就把有用内容埋了。
    只推成果类目录（工作成果/客户交付/SOP），草稿类只留最近 30 天（mtime 过滤）。
12. **429 时记忆是静默丢失的**（B 档）：不报错，只是没抽出来。表现为"接了但什么都没记住"。
    → `batch_size=8`、`max_concurrent=1`、`max_retries=6`；桥端再节流。
13. **中文分词与 SQLite 版本**：老 Python 的 sqlite 可能没编 FTS5。`install.sh` 会先自检。
14. **配置文件权限**：含 key 的配置一律 600；桥接客户端的配置优先级要写死（**环境变量 > 用户级 > 系统级**），
    否则成员装完写的却是别人的库（真的会静默写错账号）。
15. **systemd 不 restart = 没生效**：改 drop-in 后 `daemon-reload` 只是让 unit 重读，进程还是旧的。必须重启并验证新进程的环境变量。

### 重型方案（C 档）专属

16. **Hindsight 不能以 root 跑**：内嵌 Postgres `initdb: cannot be run as root`，必须建非特权用户。
17. **模型初始化要从 HuggingFace 拉权重**，国内会卡到 300 秒超时：
    `HF_ENDPOINT=https://hf-mirror.com`、`HF_HUB_DISABLE_XET=1`、调大 `*_MODEL_INIT_TIMEOUT`，剩下的大文件 `curl -C -` 断点续传。
18. **体积被严重低估**：含 torch 全量约 8-10GB、装 45 分钟。报工时把这三项算进去，否则现场必翻车。

## 三、附带发现：会话压缩悖论

长会话跑久了，框架会做上下文压缩。压不动时会出现一个恶性循环：

- 摘要写出来不比原文短 → 压缩失败 → **不退避，立刻重试** → 一直空转
- 表现：一句话发出去，几分钟不回，CPU 却不高，日志里全是 compaction
- 对策：**给单会话设硬上限**（例如文件 >3MB 或 >800 轮就自动开新会话），并在切换时把要点写进底座

记忆底座和会话轮转是一对：**底座负责"不忘"，轮转负责"不背"**。只做一个都会瘸。

## 四、对客户怎么说（照抄）

> "AI 的记忆分两层：一层是**它的记性**（记住跟你打过什么交道），一层是**你们的资料库**（合同、SOP、历史文档）。
> 我们装的是第一层——它不会把你的资料传到外面，记忆存在你自己机器上的一个文件里，你随时能打开看、能删、能带走。
> 第二层用你们现有的共享盘/知识库接进来就行。"

**边界**：不承诺"永不忘记"；不承诺记忆跨客户迁移；客户数据不上我方服务器；embedding/模型费用谁出写进合同。
