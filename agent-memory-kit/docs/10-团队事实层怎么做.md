# 10 · 团队事实层怎么做（共享，但不混库）

> 先把话说明白：云端版是**一人一库**。你和同事之间，默认互相搜不到。
> 这是故意的——客户资料不能串。团队要共享的，是**口径和结论**，那走"事实层"。

---

## 一、先决定共享什么

| 该进事实层 | 不该进事实层 |
|---|---|
| 报价口径、合同条款偏好 | 某个客户的具体报价数字 |
| 交付流程与验收标准 | 客户的联系人、身份证、流水 |
| 踩过的坑与通用结论 | 单个项目的内部讨论 |
| 行业合规红线 | 任何带客户实名/金额明细的内容 |

一句话判据：**别人拿去能直接复用、且不泄露具体客户的，才进事实层。**

---

## 二、两条落地路径（选一条，别两条混着用）

### 路径 A：事实层账号（简单，全员可读可写）

做法：建一个专用账号（如 `facts`），把它的 key 发给全员。谁写都行，谁都能搜。

```bash
# 管理员侧：建账号、取 key
POST /api/v1/admin/accounts/default/users   {"user_id":"facts","role":"user"}
# 把返回的 user_key 存成 ~/.ovmem-facts.key（600 权限），发给团队成员
```

```bash
# 成员侧：查事实层（不影响自己的私有库）
OVMEM_USER=facts OVMEM_KEY=$(cat ~/.ovmem-facts.key) ovmem search "报价口径" -k 3

# 成员侧：写一条口径进事实层
OVMEM_USER=facts OVMEM_KEY=$(cat ~/.ovmem-facts.key) \
  ovmem remember "对外报价一律先给区间，再给分项明细" --tag 口径,报价 --title "报价口径"
```

- 优点：十分钟就能用，不需要额外系统
- 缺点：**谁都能写，也能写错**。靠两条兜：① 标题统一前缀（如 `[口径]`）方便筛；② 每季度由负责人过一遍，删掉过期条目
- 适用：5 人以内小团队，互相信任

### 路径 B：知识总桶（只读共享，写入口径清晰）

做法：事实层放对象存储/知识总桶，只有负责人有写权限，成员定时拉一份本地只读副本，检索走本地。

```bash
# 成员侧（每日定时）：拉最新事实层到本地只读目录
rclone sync remote:team-facts ~/.team-facts --read-only

# 检索：本地 grep 或灌进自己的记忆库
ovmem remember "$(cat ~/.team-facts/报价口径.md)" --tag 口径 --title "[口径]报价"
```

- 优点：权限清晰、可审计、能版本回溯；写错不会污染全员
- 缺点：不实时（有同步间隔），需要维护存储
- 适用：10 人以上，或对合规有要求的律所/财税团队

## 三、验收：三步，缺一步不算成

1. 成员 B 用**自己的 key** 搜 A 的私库内容 → **必须 0 命中**（隔离没破）
2. 成员 B 用 `OVMEM_USER=facts` 搜事实层内容 → **必须命中**（共享通了）
3. 事实层里搜客户实名 → **必须 0 命中**（说明规约守住了）

第 3 步最容易被跳过，也最要命。建议每季度跑一次。

---

## 四、三个坑

1. **把私库内容整段粘进事实层**：一次操作就把客户资料扩散给全员，且无法回收（有缓存/备份）。写之前先脱敏
2. **事实层账号的 key 外流**：等于全员可写，出现脏数据查不到人。缓解：key 定期轮换；写入必带 `--tag` 标明来源团队
3. **指望"建 group"实现共享**：实测无效。把人拉进同一个组，互相搜对方库仍是 0 命中。共享只能靠上面两条路径

---

## 五、给客户讲的时候怎么说

> "每个人的 AI 记忆是自己的，互相看不到——这样客户资料不会串。
> 团队要共享的是口径：报价怎么报、合同怎么审、哪些坑别再踩。这部分放在事实层，谁都能查，但写进去要先脱敏。
> 这两件事分开，既不会互相污染，也不会各干各的。"

不要说的话：
- ❌ "我们全员共用一个大记忆库"（会被懂行的追问隔离，一问就露）
- ❌ "记忆完全隔离，团队啥也共享不了"（那就没有团队价值了）
