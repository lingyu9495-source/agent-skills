# 02 · 三层架构与选型

## 一、三层结构（热 / 温 / 冷）

```
┌─ 热层 MEMORY.md ────────────── 每轮都在上下文里，≤8KB
│   身份、铁律、稳定偏好、高频指针
├─ 温层 facts/*.jsonl + FTS5 ─── 按需召回，无限增长
│   事实、决定、事件、偏好变化（带时间/标签/来源）
└─ 冷层 archive/*.md ─────────── 月度摘要，人读用
    过期细节、已完成项目、历史口径
```

原则：
- **热层只放"每次都要用"的**，超 8KB 就开始挤占上下文，必须剪
- **温层是主战场**：写进去的不是原文，是抽出来的事实
- **冷层是保险**：不指望 AI 读，指望人查、指望半年后还在

写入判据（三条都满足才进热层）：**半年后还成立（稳定）＋ 每次都用到（高频）＋ 影响判断（决策级）**。

## 二、三档选型

| 档 | 方案 | 依赖 | 常驻内存 | 适合 | 能力 |
|---|---|---|---|---|---|
| **A 轻量**（默认） | 本包 `ai_mem.py`：sqlite FTS5 + 明文 jsonl + MEMORY.md | 仅 Python3 | <30MB | 客户机、4G 内存、无人运维 | 事实/偏好/决定/时间线，关键词与片段召回 |
| **B 标准** | OpenViking 单机 + 云端 embedding | Python3.12 + 常驻进程 | ~450MB | 8G+、要语义召回、多成员隔离 | 自动抽取、语义召回、按成员隔离 |
| **C 重型** | Hindsight / Mem0 / Graphiti | Docker / Postgres / Neo4j | 2.5GB+ | 4C8G 以上、要时序追溯 | 时序事实、图谱推理 |

**决策树**
- 客户机 ≤4G / 客户不会运维 → **A**
- 有 8G+、要"自动记"、要多人隔离 → **B**
- 事实会变、要回答"三月时是什么状态" → **C**（否则别碰，运维成本劝退）

**选型三条件，按顺序看**：机器算力 → 许可证 → 谁付 embedding 的 API 钱。
GitHub 星标只用来回答"谁做得大"，不参与决策。

## 三、开源方案对照（2026-11 实查）

| 方案 | 许可 | 自托管形态 | 备注 |
|---|---|---|---|
| **Hindsight** | MIT | 单容器 + 内嵌 Postgres | 抽取/召回/反思三步，运维最省 |
| **Mem0** | Apache-2.0 | 库或 Docker | 生态最大；默认要 OpenAI key，可换国产 |
| **Cognee** | Apache-2.0 | 嵌入式 | 图 + 向量管线，组织级知识图谱 |
| **Graphiti** | Apache-2.0 | 需 Neo4j / FalkorDB | 时序知识图谱 |
| **Letta** | Apache-2.0 | 完整 Agent 运行时 | 记忆 = git 管的 Markdown；要的是"带记忆的 Agent" |
| **OpenViking** | **AGPL-3.0** | 单进程 | 分层记忆 + 虚拟文件系统；Alpha（0.5.x），迭代快 |
| **Basic Memory** | **AGPL-3.0** | Markdown + SQLite + MCP | 笔记即记忆，轻 |

## 四、许可红线（对外交付必看）

- **AGPL-3.0**：客户装在自己机器上自用、不改源码、不对外提供网络服务，通常可控；
  但只要**你交付的是一套对外服务，或改过源码给客户**，就要法务过一遍。
  拿不准时选 **MIT / Apache-2.0**（Hindsight、Mem0、Cognee、Graphiti、Letta）。
- 永远问一句：**embedding 走谁的 key、谁的账号、钱谁出**。
  客户对出网有要求时，embedding 必须本地化或走客户自己的 key。
- 本包（`ai_mem.py`）是自研 MIT，不含任何第三方代码，可自由分发。

## 五、部署归属铁律

- **客户那套装在客户自己的机器/云上**，一个客户一个实例。
  不托管客户记忆、不远程读客户数据、不把客户接进你的共享底座。
- **团队用共享实例 + 一成员一账号**，账号混用 = 记忆互相污染。
- **一个团队只允许一个主库**。两个主库并行 = 记忆分裂，日后没人知道哪条是真的。
  多端用"主库唯一 + 本地兜底 + 只读镜像"，不要"每台再建一个底座"（见 05 篇）。
