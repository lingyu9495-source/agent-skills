## 二、部署清单（9 步，少一步都跑不通）

1. **服务器准备**：确认 2C4G 以上、有 root 与 systemd（容器环境要另谈）；确认磁盘与备份空间
2. **服务部署**：独立 venv 装服务，systemd 常驻，内存限额（`MemoryHigh` / `MemoryMax`），开机自启
3. **模型配置**：embedding 模型 + 视觉模型各一个；**按客户实际配额设限流**（`batch_size=8`、`max_concurrent=1`、`max_retries=6`）——不设就等着静默丢记忆
4. **建账号**：一人一号一号 key，key 600 权限，不进日志不进代码库；**root key 交接单**（谁保管、离职/换人怎么转）
5. **接框架**：按客户实际在用的工具接（Hermes / WorkBuddy / 豆包 / Claude Code / 自研 HTTP），每个工具现场跑通一次写入+召回
6. **网络**：安全组白名单或 SSH 隧道；**反代 + HTTPS**；写清谁负责配（客户 IT 还是我们），客户 IT 不配合时的替代方案
7. **备份与恢复演练**：每日打包，保留 7 天，异地一份；**现场做一次恢复演练并记时间**（只打包不演练等于没有备份）
8. **培训**：包内自带，覆盖"怎么写一条好记忆""怎么查""哪些不能写进事实层"
9. **书面验收单**：三步验收逐项打勾 + 客户签字（模板见下）

## 五、必须写进合同的三条边界

1. **数据流向不做承诺**：记忆本体存在客户自己的服务器（明文 + 索引），但语义检索与图片理解要调第三方模型 API，请求内容会经过模型服务商。**这一条必须书面告知，让客户自行评估**（律所/财税客户建议先过内部法务）
2. **不提供合规认证**：产品提供的是本地化存储与隔离能力，"是否符合数据安全法/个保法"由客户自行判断与承担
3. **不保零风险**：已做限流与日志巡检降低丢记忆概率，但不能承诺"绝不丢"。建议客户定期抽样核对

## 六、客户最可能问的 5 个问题（照这个答）

**Q1 数据会不会经过第三方？**
存是存在你自己的服务器上；但检索要用向量模型、看图要用视觉模型，这部分请求会经过模型服务商。这一点我们写进合同，不藏着。介意的话可以只接本地模型，代价是效果打折、部署成本上升。

**Q2 符不符合数据安全法？**
我们不给合规认证，给的是能力和边界：数据存你自己机器、一人一库隔离、每条记忆可追溯到人。合规判断与责任在客户侧。

**Q3 记忆会不会丢？**
限流参数已经按保守值配了（并发 1、批量 8），日志会巡检。但不敢保零风险，建议每月抽样核对一次，合同里也写清楚。

**Q4 后面还要交钱吗？**
不用。¥49 买断，一次付清。服务器和模型 API 是你自己的开销，我们不收年费、不绑订阅。

**Q5 装不上你管不管？**
管答疑：把报错原文发我，帮你看哪一步错了。但不代装——代装是另一件事，不在 49 块里。

## 七、交付现场最常翻车的四件事

1. 客户服务器没有 systemd（容器/宝塔环境）→ 装不上，白跑一趟。**签合同前先问**
2. embedding 配额很小，批量导入直接 429 → 记忆静默丢失，客户以为"没效果"。**先核配额再导数据**
3. 客户 IT 不放行端口也不给隧道 → 全员接不上。**网络方案与责任人写进合同**
4. root key 留在离职员工手里 → 谁都能读写。**交接单 + 定期轮换**
